The Saga Pattern for Distributed Transactions

Overview

Saga breaks a distributed transaction into a sequence of local transactions; each step publishes events. If a step fails, compensating transactions are executed to rollback.

Types

  • Choreography: Each service listens to events and reacts, no central coordinator.
  • Orchestration: A central orchestrator coordinates steps and compensation (e.g., a saga manager).

Example flow (order placement)

  1. Order service creates order (PENDING) and emits order.created.
  2. Inventory service reserves items; if successful emits inventory.reserved.
  3. Payment service attempts charge; if successful emits payment.completed and order moves to CONFIRMED.
  4. If payment fails, payment service emits payment.failed, and Inventory service performs compensation inventory.release.

Implementation considerations

  • Idempotency & dedupe for events
  • Timeouts and manual reconciliation for long-running sagas
  • Observability for saga state
