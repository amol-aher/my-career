Rails and N+1 Queries — Detection & Resolution

N+1 occurs when you query an association inside a loop, causing N additional DB queries. Rails provides tools and community practices to detect and eliminate them.

How N+1 happens

posts = Post.all
posts.each do |p|
  puts p.author.name   # triggers a query per post unless eager loaded
end

Detection

  • Bullet gem: warns on N+1 and unused eager loading.
  • APM/tracing: look for endpoints with many DB queries or high DB time.
  • Review tests with query counters (e.g., ActiveSupport::Notifications or custom helpers).

Resolution

# Eager load associations
posts = Post.includes(:author).all
posts.each do |p|
  puts p.author.name
end

# For nested associations
posts = Post.includes(author: :profile).all

Advanced strategies

  • Use pluck when you only need specific columns to avoid object instantiation.
  • Use find_each for large datasets to batch process rows.
  • Denormalize or cache computed values if access patterns require it.

Example: test that asserts query count

assert_queries(2) do
  get :index
end
