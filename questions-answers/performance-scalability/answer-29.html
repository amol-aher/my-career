Rails Caching Types — Explained

Rails offers multiple caching techniques. Choosing the right one depends on page dynamics, personalization, and cache invalidation complexity.

Low-level caching

Generic key-value caching via Rails.cache. Good for any computed value.

Rails.cache.fetch("some_key") { expensive_computation }

Fragment caching

Cache parts of a view (partials) to avoid re-rendering expensive templates. Use cache helper in views.

<% cache product do %>
  <%= render 'product', product: product %>
<% end %>

Russian doll caching

Nested fragments where parent caches reference child caches. When a child changes, only that child's cache key changes and parent can remain valid if designed well using keys/versioning.

# parent view
<% cache [@category, @category.updated_at] do %>
  <%= render collection: @category.products, partial: 'product' %>
<% end %>

Page caching

Serve full HTML pages directly from the cache (often done at CDN or proxy layer). Rare in modern Rails apps because of personalization. Works best for truly public pages.

Comparison table

  • Low-level: flexible, key-value, good for API results.
  • Fragment: view-level, good for parts of pages.
  • Russian doll: efficient nested invalidation and partial updates.
  • Page: fastest for public content, complex for per-user personalization.
