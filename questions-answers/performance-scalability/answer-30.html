Invalidating Cached Content Efficiently in Rails

Cache invalidation is hard. Use patterns that make invalidation deterministic and cheap: versioned keys, touch callbacks, and background refresh.

1. Use versioned cache keys

# model cache key
def cache_key
  "#{self.class.name.downcase}/#{id}-#{updated_at.to_i}"
end

2. Use touch to propagate updates

When an associated record changes, use touch: true to update parent's timestamp so its cache key changes automatically.

class Comment < ApplicationRecord
  belongs_to :post, touch: true
end

3. Explicit expire on write

Rails.cache.delete("top_products/v1") # when product changes
# or use cache.delete_matched for pattern deletes (costly)

4. Use background refresh (stale-while-revalidate)

Serve slightly stale content while a background job recomputes the cache to avoid thundering herds.

value = Rails.cache.fetch(key, expires_in: 5.minutes) do
  computed_value
end
# Kick off background job to refresh near expiry

5. Use CDN & cache-control carefully

Short TTLs with cache invalidation APIs (CloudFront invalidation) for critical changes. Use surrogate keys on CDNs when supported for targeted purge.

6. Use cache namespaces / versioning for mass invalidation

# bump namespace version to invalidate many keys
Rails.cache.fetch("v2:top_products:...") { ... }
# bump the 'v2' quickly invalidates older keys without deletes

7. Practical checklist

  • Prefer deterministic keys with timestamps
  • Use touch and association callbacks to cascade invalidation
  • Avoid broad deletes in hot caches; use namespacing when possible
  • Monitor cache hit/miss, eviction rates, and latency
