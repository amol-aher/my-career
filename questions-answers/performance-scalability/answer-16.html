Web Servers I've Used and Why

I've used a variety of web servers and fronting proxies depending on stack and requirements. Below is an overview and trade-offs.

Reverse proxies / LB

  • Nginx: Preferred as reverse proxy, SSL termination, caching, HTTP/2, and buffering. Lightweight and battle-tested.
  • HAProxy: High-performance load balancing with advanced routing and health checks.
  • Cloud LBs: AWS ALB / NLB for managed load balancing, integration with autoscaling.

Application servers (Ruby)

  • Puma: Multi-threaded and recommended for Rails on Heroku and many cloud setups. Good for IO-bound workloads.
  • Unicorn: Process-based, simpler but less memory-efficient for many concurrent connections (no threads).
  • Passenger: Easy deployment, process management; integrates with Nginx/Apache.
  • Thin: Evented but less commonly used now.

When to pick what

  • Puma when you want threads and better memory usage and faster concurrency for I/O.
  • Unicorn when you prefer the isolation of processes and your workload is CPU-bound and you control worker counts.
  • Passenger for simplified operations with process management baked in.

Examples

# Nginx as reverse proxy in front of Puma/Unicorn
server {
  listen 80;
  server_name example.com;
  location / {
    proxy_pass http://unix:/tmp/puma.sock;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
  }
}
