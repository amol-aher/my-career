Techniques to Reduce Rails Boot Time in Large Applications

Fast boot time improves deploy speed, quick autoscaling, and developer productivity. Here are practical techniques and examples.

1. Use bootsnap

bootsnap caches expensive file-system lookups and speeds up boot significantly.

# Gemfile
gem 'bootsnap', require: false

# config/boot.rb
require 'bootsnap/setup' # Speed up boot time by caching expensive operations

2. Preload app and use copy-on-write friendly forks

With Puma's preload_app!, load the application before forking workers to take advantage of OS COW memory sharing.

# config/puma.rb
preload_app!
workers Integer(ENV['WEB_CONCURRENCY'] || 2)

3. Reduce and optimize initializers

Avoid heavy work in initializers (network calls, expensive computations). Move such work to lazy-loading or background tasks.

4. Lazy-load rarely used gems

Require costly gems only when needed. Use require_dependency or autoloading where appropriate.

5. Use Zeitwerk autoloader and avoid eager loading unnecessary constants

Rails' Zeitwerk handles autoloading efficiently. Avoid forcing eager_load for development unless necessary.

6. Optimize gemset and remove unused gems

Each gem increases boot time. Audit gems and remove or move heavy gems to optional groups.

7. Cache expensive configuration and view compilation

Precompile assets and view templates. Use config.cache_classes and config.eager_load properly in production.

8. Use quick deploy strategies

Blue-green deploys or pre-warmed instances help avoid cold start impact on live traffic.

9. Monitor boot time and regressions

Track boot time metrics in CI and production so regressions are visible early.

Summary checklist

  • Add bootsnap.
  • Preload app and use Puma workers for COW.
  • Reduce expensive initializers and lazy-load where possible.
  • Audit gems and precompile assets/templates.
