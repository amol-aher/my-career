When to choose RDS vs DynamoDB vs Aurora

Short summary

  • RDS (Postgres/MySQL): Relational, strong consistency, complex queries, ACID transactions, vertical/horizontal scaling via read replicas and sharding. Good for OLTP with relational models.
  • Aurora: Managed MySQL/Postgres-compatible with better performance, storage auto-scaling, global read replicas (Aurora Global DB). Good when you want managed relational with scalability and lower latency reads.
  • DynamoDB: Fully managed NoSQL key-value / document store. Single-digit ms reads/writes at scale, auto-scaling, global tables for multi-region, eventual or strong consistency (per-request). Good for massive scale, predictable access patterns, and flexible schema.

Decision factors

  • Data model complexity: Use relational (RDS/Aurora) for complex joins and transactions; DynamoDB for simple access patterns and denormalized documents.
  • Scale and throughput: DynamoDB scales virtually unlimited; Aurora scales reads via replicas and writes are limited to the cluster's writer.
  • Cost model: DynamoDB billed on RCUs/WCUs and storage; RDS/Aurora billed for instances and storage; consider unpredictable traffic vs provisioned capacity.
  • Global requirements: DynamoDB Global Tables are easy for multi-region active-active; Aurora Global DB supports cross-region read replicas (best for active-passive or read-heavy scenarios).
  • Operational preferences: If you need SQL, choose RDS/Aurora; if you want serverless and minimal ops, consider DynamoDB or Aurora Serverless.

Examples

  • E-commerce catalog with complex queries & reporting: RDS/Aurora + data warehouse for analytics.
  • High-scale session store or user feature flags: DynamoDB (low-latency, high throughput).
  • Financial systems requiring strong ACID across multiple entities: RDS/Aurora.

Summary checklist

  1. Define access patterns and query complexity.
  2. Estimate read/write throughput and growth.
  3. Decide on consistency vs availability trade-offs.
  4. Choose DB that minimizes operational burden and fits data model.
