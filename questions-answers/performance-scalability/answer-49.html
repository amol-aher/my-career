Handling Data Consistency Across Services

Patterns

  • Event-driven eventual consistency: Emit and consume events to keep read models in sync.
  • Change Data Capture (CDC): Use Debezium or cloud CDC to stream DB changes to other services.
  • Read models / materialized views: Build local optimized copies for queries.
  • Saga/compensation: For multi-step business transactions.

Techniques to ensure integrity

  • Use ordered messaging where order matters (Kafka partitions).
  • Design idempotent consumers.
  • Implement reconciliation jobs to detect and repair inconsistencies.

Trade-offs

Eventual consistency reduces coupling but introduces temporal window where data may appear inconsistent. Communicate and design for it in SLAs and UIs.
