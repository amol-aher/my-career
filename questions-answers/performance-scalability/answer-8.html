Immediate and Practical Solutions to Fix Performance Issues

Short-term (minutes to hours)

  • Identify and kill runaway queries/processes.
  • Enable read-only replicas and redirect reporting queries.
  • Increase DB connection pool temporarily and tune Sidekiq concurrency.
  • Enable caching (Redis) for heavy queries or endpoints.

Mid-term (hours to days)

  • Add targeted indexes based on slow query patterns.
  • Refactor hot code paths to batch operations and reduce allocations.
  • Move report generation to background workers and rate-limit jobs.

Longer-term (weeks)

  • Implement CQRS and read-optimized stores or data warehouse.
  • Introduce event streaming for decoupled processing.
  • Refactor monolith into services if deployment agility or scaling requires it.

Concrete Playbook

  1. Measure p95/p99 latency and identify top offenders.
  2. Apply quick wins: caching, throttling, read-replicas.
  3. Apply structural fixes: indexing, batching, offload reports.
  4. Monitor impact and iterate.

Example: Throttling Sidekiq Jobs

# Using sidekiq-throttled gem (example)
class HeavyWorker
  include Sidekiq::Worker
  sidekiq_throttle(concurrency: {limit: 5}, threshold: {limit: 100, period: 1.minute})
  def perform(*args)
    # heavy DB work
  end
end
