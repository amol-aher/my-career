Designing a Rails App to Expose RESTful and GraphQL APIs

Design decisions include resource modeling, versioning, authentication, rate limits, pagination, and tooling. Below are pragmatic guidelines and examples for both REST and GraphQL.

REST API design

  • Use resourceful routes (resources :users) and standard HTTP verbs (GET, POST, PUT/PATCH, DELETE).
  • Design JSON representations via serializers (fast_jsonapi, ActiveModel::Serializers, Blueprinter).
  • Use status codes properly (200,201,204,400,404,422,500).
  • Include HATEOAS links when helpful.

Example controller

class Api::V1::UsersController < ApplicationController
  def index
    users = User.order(:created_at).page(params[:page]).per(25)
    render json: UserSerializer.new(users).serializable_hash
  end

  def show
    user = User.find(params[:id])
    render json: UserSerializer.new(user).serializable_hash
  end
end

GraphQL design

  • Use graphql-ruby to define schema, types, and mutations.
  • Implement batching solutions (DataLoader) to avoid N+1 in GraphQL queries.
  • Limit query complexity and depth to protect the server.

Example GraphQL type (graphql-ruby)

Types::UserType = GraphQL::ObjectType.define do
  name "User"
  field :id, !types.ID
  field :name, types.String
end

Authentication & Authorization

Use token-based auth (JWT or OAuth2 bearer tokens) for API clients. Use Pundit or Cancancan for authorization checks in controllers/resolvers.

Performance & caching

  • Cache serialized responses for public endpoints.
  • For GraphQL, consider persisted queries and response caching for repeated queries.

Versioning

For REST, namespace routes or use headers (see question on versioning). For GraphQL, maintain backward-compatible schema changes or introduce a new endpoint/version if needed.

Observability

Log request IDs, timings, and errors. Use tracing for distributed systems and track API usage metrics for throttling and billing.

Summary

Design REST for resource-oriented APIs and GraphQL for flexible client-driven queries. Use serializers, auth, throttling, and caching to make APIs production-ready.
