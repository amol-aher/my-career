Alternatives to Full Normalization for Performance

1. Denormalization

Duplicate critical read fields to avoid joins. Keep them in sync via background jobs or triggers.

2. Materialized Views

Precompute heavy joins/aggregates and refresh periodically or incrementally.

3. Read Replicas and Read-Optimized Stores

Use replicas for reporting and heavy read analytics. Consider a separate read-optimized database (columnar).

4. Caching Layers

Cache computed results and fragments at app or CDN layer.

5. Sharding and Partitioning

Split large tables by key or time to reduce the working set per query.

6. Query Refactoring

Use pagination, projection (select only necessary columns), and indexes to make queries efficient without schema changes.

7. Event Sourcing / CQRS

Store events in append-only store and project read models tailored for queries.

8. Example: Materialized View in Postgres

CREATE MATERIALIZED VIEW daily_sales AS
SELECT date_trunc('day', created_at) AS day, product_id, sum(amount) AS total
FROM sales
GROUP BY day, product_id;

-- Refresh
REFRESH MATERIALIZED VIEW CONCURRENTLY daily_sales;
