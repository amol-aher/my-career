Implementing Caching for Frequently Used Queries

Caching reduces database load and decreases latency. Below are practical approaches and code samples for Rails apps.

1. Low-level cache (Rails.cache)

Rails.cache.fetch("top_products/v1", expires_in: 10.minutes) do
  Product.order(sales_count: :desc).limit(50).to_a
end

2. Fragment caching (views)

<% cache product do %>
  <%= render partial: 'product', locals: {product: product} %>
<% end %>

3. Russian doll caching

Nest fragments so parent caches expire when child fragments change. Use cache keys with timestamps.

# In Product model
def cache_key
  "#{super}-#{updated_at.to_i}"
end

4. HTTP-level caching & CDN

Set Cache-Control, ETag headers and use CloudFront or Fastly for edge caching.

5. Query result caching vs object caching

Cache serialized results (JSON) for APIs to avoid object instantiation overhead.

6. Cache invalidation strategies

  • TTL-based expiry for eventual consistency.
  • Explicit key invalidation on writes (touch/expire).
  • Versioned keys (incrementing version in namespace) for mass expire.

7. Example: Background refresh with stale-while-revalidate

value = Rails.cache.fetch(key, expires_in: 5.minutes) do
  # compute and return fresh value
end
# In parallel, kick off a background job to warm cache before expiry if needed
