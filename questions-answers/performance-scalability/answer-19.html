Troubleshooting Performance Bottlenecks in Rails Apps

When a Rails app is slow, I follow a structured approach: measure, isolate, fix, and validate. Below are concrete steps and examples.

1. Profiling & Observability

  • APM (NewRelic, Datadog) for traces and slow endpoints.
  • rack-mini-profiler and flamegraphs for local profiling.
  • Bullet gem to find N+1 queries.

2. Common fixes

N+1 query elimination

# bad
orders.each { |o| puts o.user.name }
# good
orders.includes(:user).each { |o| puts o.user.name }

Caching

Use fragment, action, and low-level caching for expensive renders and queries. Example:

Rails.cache.fetch("product:#{id}:summary", expires_in: 5.minutes) do
  Product.find(id).decorate.summary
end

Backgrounding heavy work

Push heavy computations to Sidekiq with appropriate concurrency limits and batching.

Database optimizations

Add or tune indexes, use read replicas, and partition large tables.

Optimize serialization

Use fast JSON serializers (Oj, fast_jsonapi) and select only required fields.

3. Web server and connection tuning

Choose Puma with threads tuned to DB pool size; set keepalive and proxy buffering in Nginx. Use pgbouncer if DB connections are scarce.

4. Load tests and validation

Run k6 or JMeter scenarios that mimic production load and validate latency improvements before deploy.

5. Example remediation workflow

  1. Identify top offenders by p99 latency in APM.
  2. Reproduce locally with sample data.
  3. Apply fix (index change, eager loading, caching).
  4. Load test and deploy with canary.
