Sticky Sessions on AWS ALB — How to Configure and Trade-offs

How to configure

  1. Create or edit your target group in the AWS Console.
  2. Enable stickiness and choose duration (seconds). ALB uses a load-balancer-generated cookie (AWSALB).
  3. Alternatively, use application cookie stickiness for finer control.

Trade-offs

  • Reduces statelessness: Ties a user to a specific instance which complicates scaling and deployments.
  • Failover issues: If target fails, sticky sessions are lost and clients may need to re-authenticate or lose session state.
  • Maintenance: Rolling deploys may evict sticky sessions leading to inconsistent user experience.

Alternatives

  • Use shared session stores (Redis) or JWT/session in cookies to remain stateless.
  • Prefer sticky sessions only for legacy apps that cannot be refactored quickly.
