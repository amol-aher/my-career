Backup & Recovery Strategies for Mission-Critical Services

Principles

  • Define RPO (data loss tolerance) and RTO (time to recovery).
  • Automate backups and verify restores regularly (DR drills).
  • Store backups offsite and across regions.
  • Protect backups (encryption, least privilege).

Concrete strategies

  • Databases: RDS automated backups + snapshots, enable PITR (Postgres WAL archiving) where supported; cross-region snapshots for DR.
  • DynamoDB: On-Demand backups + PITR, export to S3 for long-term archiving.
  • S3: Versioning + cross-region replication (CRR) and lifecycle policies.
  • ElastiCache: Redis snapshots persisted to S3 and cross-region copy if needed; ensure Multi-AZ and automatic failover.
  • Infrastructure as Code: Store Terraform/CloudFormation state in remote buckets with locking (S3 + DynamoDB lock) and backup state snapshots.

Recovery runbook checklist

  1. Declare incident and RTO/RPO targets.
  2. Identify latest good backup and its region.
  3. Restore backups to an isolated environment and validate integrity.
  4. Promote restored DB to be writable if necessary and update DNS/load balancer.
  5. Validate application behavior and monitor for errors.

Testing

Run regular restore tests, simulate outages with chaos engineering, and update runbooks based on observations.
