System Health: Instrumentation and Logging

Key Signals of Healthy Systems

  • Availability (uptime, error rate)
  • Latency (p50, p95, p99)
  • Throughput (requests/sec, jobs/sec)
  • Resource utilization (CPU, memory, I/O)
  • Business KPIs (orders processed, revenue, conversion)

Instrumentation

  • APM: NewRelic/Datadog/AppSignal for tracing requests, service maps, span breakdowns.
  • Distributed Tracing: OpenTelemetry/Jaeger/Zipkin to trace across microservices.
  • Metrics: Prometheus + Grafana for custom metrics (counters, gauges, histograms).
  • Health checks: Readiness and liveness endpoints for orchestration and LB.

Logging

  • Structured logs (JSON) shipped to a central store (ELK/CloudWatch/Datadog Logs).
  • Correlation IDs and trace IDs in logs to tie logs to traces.
  • Log retention and sampling for noise control (sample verbose logs).

Alerting and SLOs

Define SLOs (e.g., 99.9% of requests complete within 500ms). Alert on SLO breaches, not raw outages. Use multi-channel escalation (PagerDuty, Slack).

Example: Adding Metrics in Ruby

# using prometheus-client
registry = Prometheus::Client.registry
http_latency = Prometheus::Client::Histogram.new(:http_request_duration_seconds, docstring: '...')
registry.register(http_latency)
# in middleware
http_latency.observe(duration)

Playbooks and Runbooks

Maintain runbooks for common incidents (DB failover, high latency, memory leak). Include steps, dashboards to observe, and rollback plans.
