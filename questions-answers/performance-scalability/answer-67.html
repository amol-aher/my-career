Invalidating CloudFront Cache Effectively

Options

  1. Versioned assets (best practice): Use fingerprinted filenames (app.abcd1234.js). No need to invalidate — clients request new file names.
  2. Invalidate specific paths: Use CloudFront invalidation API or console for targeted paths.
  3. Short TTL + stale-while-revalidate: Use cache-control headers to keep TTL short for frequently changing content.
  4. Use Cache-Control + Query String: Vary caching by query string or headers when appropriate.

AWS CLI invalidation example

aws cloudfront create-invalidation --distribution-id EXXXXX   --paths "/assets/app.abcd1234.js" "/index.html"
  # For wildcard:
  aws cloudfront create-invalidation --distribution-id EXXXXX --paths "/*"

Considerations

  • Invalidations cost and are rate-limited (wildcard invalidations are heavier).
  • Prefer versioning to reduce operational costs.
  • Use Cache Behavior settings to control TTLs per path.
