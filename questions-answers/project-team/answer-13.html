Diagnosing missed sprint commitments — key metrics

System architect · Technical lead · Senior software engineer (Ruby on Rails, AWS, SQL, Vue.js)

Summary: To diagnose missed commitments I track velocity, sprint predictability, cycle time, WIP, blocked time, defect rate, review time, and unplanned work. These metrics together point to root causes like over-commitment, bottlenecks, QA slowdowns, or unstable requirements.

Core metrics
  • Velocity: story points completed per sprint (trend over time)
  • Sprint predictability: % of committed points completed
  • Cycle time & lead time: time from 'in progress' to 'done' and 'ready' to 'done'
  • WIP: number of active stories per developer
  • Blocked time: time tickets spend blocked
  • Review & Merge time: time from PR opened to merged
  • Escaped defects: bugs found in production related to sprint work
  • Unplanned work percentage: how much of sprint capacity consumed by incidents/urgent tasks
How to use the data
  1. Low velocity + high WIP → too many concurrent tasks; reduce WIP and focus on finishing.
  2. High merge time → code review bottleneck; rotate reviewers or enforce SLA for reviews.
  3. High blocked time → identify recurring blockers and create mitigation (sandbox envs, infra availability).
  4. High unplanned work → measure and allocate capacity for interrupts or create a stable on-call rota.
