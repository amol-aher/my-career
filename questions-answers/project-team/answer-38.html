Identifying risks early in a project

System architect · Technical lead · Senior software engineer (Ruby on Rails, AWS, SQL, Vue.js)

Summary: Risks are identified through discovery workshops, technical spikes, dependency mapping, and regular risk reviews. Maintain a risk register with owners and mitigation plans.

Practical tactics
  • Run pre-mortem to imagine failures and plan mitigations.
  • Map external dependencies and SLAs (third-parties, infra teams).
  • Perform architecture reviews and security assessments early.
  • Create lightweight spikes for unknowns.
Risk register example
Risk: Third-party API rate limit
Likelihood: High
Impact: Medium (delays onboarding)
Mitigation: Implement local caching & exponential backoff, request higher rate limits
Owner: @backend-lead
