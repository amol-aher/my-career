Hands-on in creating user stories and decomposing them

System architect · Technical lead · Senior software engineer (Ruby on Rails, AWS, SQL, Vue.js)

Summary: I am very hands-on. I co-create user stories with Product, ensure acceptance criteria are precise, and decompose stories into implementation tasks including infra and QA work.

Typical workflow
  1. Discovery: Work with product on user needs, run spikes for unknowns.
  2. Draft stories: Write stories using the standard template (As a / I want / So that) and propose acceptance criteria driven by examples.
  3. Grooming: In grooming sessions, break stories into vertical slices and list the tasks (API, UI, DB, tests, infra, deploy).
  4. Definition of Done: Code + tests + docs + deployment + monitoring + performance considerations.
Example user story and subtasks
User story:
As a paying customer, I want to save multiple shipping addresses so that I can choose them at checkout.

Acceptance criteria:
- Add new address
- List existing addresses
- Select default address for checkout
- Validation errors shown for invalid input

Subtasks:
- Backend: Add Address model and controller endpoints (2d)
- Frontend: Address management UI (3d)
- Tests: RSpec + system tests (1d)
- Infra: Add secrets & config for address validation service (0.5d)
- Docs: API docs and runbook (0.5d)
When I do less hands-on

If the team is senior and self-sufficient, I step back to unblock and review, focusing on architecture and non-blocking contributions.
