Revisiting past solutions using hashes — migration to structured schema or JSONB

System architect · Technical lead · Senior software engineer (Ruby on Rails, AWS, SQL, Vue.js)

Problem: Storing deeply nested Ruby hashes (serialized) in a single column made querying, indexing, and reporting slow and complex. It complicated joins and analytics.

Options to refactor
  1. Normalize into relational tables (preferred for frequently queried fields and joins).
  2. Use Postgres JSONB with proper indexes for semi-structured data.
  3. Create materialized views or derived columns for hot queries.
Migration approach — step by step
  1. Catalog queries & identify hot fields used in WHERE/JOIN clauses.
  2. Design normalized tables for fields that need indexing and joins.
  3. Write a safe migration plan: add new columns/tables, backfill in batches, add indexes, switch code to read new representation, then drop old column.
Example migration (JSONB approach & ActiveRecord)
-- 1) add jsonb column and index
ALTER TABLE users ADD COLUMN profile jsonb;
UPDATE users SET profile = to_jsonb(profile_hash);
CREATE INDEX idx_users_profile_city ON users ((profile->>'city'));

-- 2) ActiveRecord usage
class User < ApplicationRecord
  scope :by_city, ->(city) { where("profile->>'city' = ?", city) }
end

-- 3) For normalized table (addresses)
class CreateAddresses < ActiveRecord::Migration[6.1]
  def change
    create_table :addresses do |t|
      t.references :user, null: false, foreign_key: true
      t.string :city
      t.string :state
      t.timestamps
    end
    add_index :addresses, :city
  end
end
Querying performance tips
  • Use GIN indexes for existence and containment queries on JSONB.
  • Extract frequently queried fields into generated columns (Postgres 12+) for faster queries.
  • For analytics, maintain ETL into a warehouse (Redshift/Snowflake) for large aggregations.
When hashes are still OK

If the fields are truly ad-hoc metadata rarely queried, keep JSONB and document the schema. Use schema migration/validation tools to track changes.
