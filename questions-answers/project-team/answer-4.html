Agile practices: Sprints vs Kanban

System architect · Technical lead · Senior software engineer (Ruby on Rails, AWS, SQL, Vue.js)

Summary: I have run both Scrum (timeboxed sprints) and Kanban depending on team context. Choice depends on predictability needs, work nature, and organizational cadence.

When to use Scrum (sprints)
  • When you have cross-functional features requiring coordination.
  • When stakeholders want predictable delivery windows and demos.
  • When planning and capacity forecasting matter for release trains.
When to use Kanban
  • High rate of small, operational changes or support tickets.
  • When continuous flow and limiting WIP provide better throughput.
  • When priorities change frequently and strict sprint boundaries slow delivery.
Hybrid approaches

We often use a hybrid: run 2-week sprints for feature work, but maintain a Kanban-style board for urgent production fixes (exceptions prioritized into sprint or triaged separately).

Operational details I enforce
  • Definition of Ready and Done.
  • Timeboxed ceremonies: planning, daily standup, retro, and demo.
  • Continuous improvement via sprint retros with clear action items.
  • Use of metrics: velocity, cycle time, and defect escape rate.
