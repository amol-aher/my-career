Sizing sub-tasks

System architect · Technical lead · Senior software engineer (Ruby on Rails, AWS, SQL, Vue.js)

Summary: Sub-tasks are sized for single-developer completion and ideally less than 1–2 days. If a sub-task exceeds that, it should be split further.

Sizing heuristics
  • Micro: < 4 hours — quick fixes, small UI tweaks
  • Small: 4–16 hours — single feature + tests
  • Medium: 2–3 days — multiple components, moderate risk
  • Large: > 3 days — split into smaller tasks or create a spike
Sizing checklist
  • Has clear acceptance criteria?
  • Is it possible to test in isolation?
  • Any external dependencies or environment setup?
  • Does it include code, tests, infra changes, and docs?
Example of a sub-task description
Title: Implement POST /api/v1/addresses
Estimate: 8h
Description:
- Add controller endpoint and strong params
- Create Address model validations
- Add serializer and policy checks
- Add unit and request specs
- Update API docs
