How I debug a module solo — practical step-by-step
  1. Reproduce locally: create a reproducible environment (seed data, sample requests). Use Docker or the project's dev environment scripts.
  2. Read the contracts: inspect API contracts, DB schema, existing tests, ADRs, and the README to understand intended behavior.
  3. Instrument: add logs, request/response dumps, and lightweight metrics to surface where the failure occurs.
  4. Binary search: use git bisect or comment-out technique to narrow the change that introduced the issue.
  5. Use debuggers: pry/byebug for Ruby. Example:
# Gemfile (dev)
group :development do
  gem 'pry'
  gem 'pry-byebug'
end

# usage
require 'pry'; binding.pry
  1. Write failing tests: Add a focused unit/integration test that demonstrates the bug (test-first ensures fix coverage).
  2. Patch & refactor: implement the minimal fix, refactor to improve clarity, and run full test suite.
  3. CI & deploy: push a branch with CI, add feature flag if risky, deploy to staging, and run smoke tests.
  4. Post-deploy: observe metrics, verify logs, and schedule a postmortem if it impacted users.
Example: Debugging a slow ActiveRecord query
# Identify in production logs
User.includes(:orders).where('orders.created_at > ?', 1.month.ago).to_sql

# Use EXPLAIN in psql
EXPLAIN ANALYZE SELECT ...;

# Fix approach: add an index or change the query
add_index :orders, :created_at

# Or batch to avoid N+1
User.find_each(batch_size: 100) do |u|
  u.orders.recent.limit(50) # avoid loading everything
end
