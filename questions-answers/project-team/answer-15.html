Detecting if work is stuck in QA or in-progress too long

System architect · Technical lead · Senior software engineer (Ruby on Rails, AWS, SQL, Vue.js)

Summary: Monitor status dwell times (time spent per workflow state), PR age, and lead time. Set SLAs for stages like 'In Review' and 'In QA' and alert when exceeded.

Concrete signals
  • Median time in QA rising over several sprints.
  • Backlog of PRs waiting for review for >24–48 hours.
  • Stories cycling between QA and In Progress more than N times.
Automated alerts

Use CI/Jira automation to flag PRs older than X hours and stories in QA beyond a threshold. Slack alerts to the team or a dedicated triage channel help visibility.

Root causes and remedies
  • Flaky tests: stabilize tests, quarantine flaky tests, and ensure deterministic test data.
  • Environment instability: invest in reliable staging environments and parallel test runners.
  • Review bottleneck: implement review SLAs and rotate on-call reviewers.
  • Incomplete test coverage: expand test matrix and add smoke tests for critical flows.
