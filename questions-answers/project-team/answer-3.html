Missing deadlines or production incidents — handling and learnings

System architect · Technical lead · Senior software engineer (Ruby on Rails, AWS, SQL, Vue.js)

Summary: Missed deadlines and incidents are inevitable; the measure is response quality. My process emphasizes containment, root cause, remediation, and prevention.

Immediate incident response (first 60–120 minutes)
  1. Assess impact: Who is affected? What functionality is down? Severity level.
  2. Mitigate: Apply hotfix, rollback, or circuit-breaker/feature-flag toggle.
  3. Communicate: Notify stakeholders and on-call with current state and estimated next update.
  4. Stabilize: Stop further changes and focus on containment.
Post-incident (within 24–72 hours)
  1. Postmortem: A blameless report with timeline, root cause, contributing factors, impact, and remediation plan.
  2. Action items: Assign owners for fixes: tests, infra changes, runbook updates, monitoring.
  3. Follow-through: Track and verify completion of action items.
Missed deadline — practical handling
  1. Be transparent: Inform stakeholders with reason, impact, and revised plan.
  2. Prioritize: Re-scope to deliver core value first (MVP approach).
  3. Adjust process: Modify estimation practice, add buffer for unknowns, or increase QA capacity.
Example scenario and learnings

We once missed a launch because integration tests with a third-party payment provider were flaky and skipped in CI. Actions taken:

  • Added contract tests & mocked provider for CI.
  • Created staging environment with test provider credentials.
  • Introduced a pre-release checklist that includes end-to-end smoke tests.
  • Result: subsequent releases had fewer surprises and quicker time-to-release.
Checklist to prevent recurrence
  • End-to-end smoke tests in pipeline
  • Feature flags for partial rollouts
  • Runbooks for on-call
  • Pre-release canary deployments
