Prioritizing tasks when everything seems urgent

System architect · Technical lead · Senior software engineer (Ruby on Rails, AWS, SQL, Vue.js)

Summary: Use frameworks (Impact/Effort, RICE), align with business goals, and use triage rules. Communicate trade-offs and maintain a clear escalation path for truly urgent items.

Practical approach
  1. Classify: Is this emergency (production incident), business-critical (regulatory), or important but not urgent?
  2. Quantify impact: revenue, user experience, legal/compliance risk, or technical risk.
  3. Estimate effort: quick estimate to decide if fast mitigation is possible.
  4. Use RICE: Reach * Impact * Confidence / Effort for prioritization.
  5. Apply WIP limits: avoid starting too many items simultaneously.
Triage playbook
Priority matrix:
- P0: production outage -> immediate
- P1: major feature blocking revenue -> next slot with senior devs
- P2: nice-to-have -> backlog

Communicate: update stakeholders with chosen path and expected ETA within 1 hour for emergencies.
