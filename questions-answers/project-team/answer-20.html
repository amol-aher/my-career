Difficult team project — example and approach to delivery

System architect · Technical lead · Senior software engineer (Ruby on Rails, AWS, SQL, Vue.js)

Summary: Example project: migrating a monolith payments system to microservices while maintaining 99.95% uptime. The project required cross-team coordination, careful sequencing, and robust testing.

Challenges
  • Strong coupling between modules and shared DB tables.
  • Zero-downtime requirement for millions of transactions.
  • Multiple teams and stakeholders (product, compliance, ops).
Approach
  1. Discovery & spike: identify boundaries and run a proof-of-concept splitting read vs write responsibilities.
  2. Design: define API contracts, data migration strategy (dual-write then backfill), and idempotency guarantees.
  3. Phased delivery: break into vertical slices by feature and user cohort.
  4. Testing: contract tests, consumer-driven contract testing, canary deploys, and high-fidelity staging.
  5. Coordination: regular cross-team syncs, clear runbooks, and rollback criteria.
Outcome

Successful migration with a series of canary releases, minimal user impact, and improved scalability. Lessons learned included the importance of feature flags, thorough contract testing, and early stakeholder alignment.
