System architect · Technical lead · Senior software engineer (Ruby on Rails, AWS, SQL, Vue.js)

Difficult issue (incident): A cascading failure due to a bad schema migration that caused background jobs to crash and created a backlog of failed work.

Why it was difficult
  • Multiple services relied on the schema.
  • Backlog of jobs could cause duplicated downstream effects on users.
  • Hard to rollback without data loss.
How I handled it
  1. Immediate triage: paused job processors, assessed error surface, and collected metrics.
  2. Rollback strategy: applied a safe migration to restore compatibility while preserving data.
  3. Backfill plan: wrote an idempotent backfill job that processed failed items in controlled batches with checkpoints.
  4. Postmortem & prevention: added migration checklists, pre-production dry runs, and stronger migration tests.
Example backfill pattern (Ruby)
class BackfillOrdersState
  BATCH_SIZE = 1000

  def perform
    loop do
      batch = Order.where(state: nil).limit(BATCH_SIZE).pluck(:id)
      break if batch.empty?

      Order.where(id: batch).find_each do |order|
        # idempotent compute
        order.update_columns(state: compute_state(order))
      end
      sleep 0.5 # reduce DB pressure
    end
  end
end
Unsolicited improvement I implemented

I introduced a migration safety harness: test runner that runs migrations in a clone of production DB (sanitized) and runs a suite of smoke checks before allowing deployment.
