Rack: The Core of Ruby Web Applications

What is Rack?

Rack is a minimal, modular interface for developing web applications in Ruby. It provides a standard way for web servers to communicate with Ruby applications, acting as the foundation for frameworks like Sinatra, Rails, and many others.

# Minimal Rack application (config.ru)
require 'rack'

app = Proc.new do |env|
  [200, {'Content-Type' => 'text/html'}, ['Hello World']]
end

run app

Rack's Core Components

1. The Environment Hash (env)

A hash containing all information about the HTTP request:

{
  "REQUEST_METHOD" => "GET",
  "PATH_INFO" => "/users",
  "QUERY_STRING" => "",
  "SERVER_NAME" => "localhost",
  "CONTENT_TYPE" => "application/json",
  "rack.input" => #<Rack::Lint::InputWrapper ...>
}

2. The Response Array

A three-element array representing the HTTP response:

[
  200,                  # Status code
  {"Content-Type" => "text/plain"}, # Headers
  ["Hello, world!"]     # Body
]

3. Middleware

Components that wrap around applications to modify requests/responses:

# Example middleware (adds timestamp to response)
class TimestampMiddleware
  def initialize(app)
    @app = app
  end

  def call(env)
    status, headers, body = @app.call(env)
    body << "\nGenerated at: #{Time.now}"
    [status, headers, body]
  end
end

How Rack Works

Your Application
Rack Middleware (Logging, Session, etc.)
Rack Handler (Webrick, Puma, Unicorn)
Web Server (Nginx, Apache)

When a request comes in:

  1. Web server passes environment hash to Rack handler
  2. Rack handler wraps application in configured middleware
  3. Middleware processes request and calls next component
  4. Application generates response
  5. Middleware modifies response if needed
  6. Rack handler returns final response to web server

Rack in Rails

Rails uses Rack extensively:

  • Rack Middleware Stack: Defined in config/application.rb
  • Action Controller: Implements Rack interface
  • Railties: Uses Rack to serve assets and handle routes
# config/application.rb
module MyApp
  class Application < Rails::Application
    config.middleware.use Rack::SSL
    config.middleware.insert_before ActionDispatch::Static, Rack::Cache
  end
end

Key Functionalities

  • Standard Interface: Unified way to build web apps
  • Middleware Architecture: Chainable components for cross-cutting concerns
  • Streaming Support: Efficient body handling for large responses
  • Multi-server Compatibility: Works with Webrick, Puma, Unicorn, Passenger
  • Framework Agnostic: Used beyond Rails (Sinatra, Hanami, etc.)

Practical Applications

  • Custom Middleware: Add authentication, rate limiting, CORS handling
  • Microframeworks: Build lightweight APIs with minimal dependencies
  • Performance Monitoring: Instrument request/response times
  • Request Validation: Sanitize input parameters
  • Session Management: Custom session stores (Redis, Memcached)
