Creating Real-time PDFs in Rails

Prepared by: Senior Software Engineer & System Architect — Rails / AWS / SQL / Vue.js

Date: 2025-09-10 (UTC)

Overview

Options for generating PDFs in real-time: libraries (WickedPDF/wkhtmltopdf, Prawn, Grover), streaming, background processing for heavy PDF generation, and UX considerations.

Common PDF libraries and tradeoffs

  • WickedPDF / wkhtmltopdf: Renders HTML/CSS via headless WebKit. Good for converting complex HTML templates with CSS; heavyweight because it shells out to wkhtmltopdf.
  • Grover (Puppeteer/Chrome): Uses headless Chrome for high-fidelity rendering; supports modern CSS, JS, and complex layouts.
  • Prawn: Ruby-native PDF generation for programmatic PDFs (invoices, tickets); great for precision but more code for layouts.
  • PrinceXML / DocRaptor: Commercial tools with excellent CSS support and performance guarantees.

Real-time strategies

  • Lightweight PDFs: If generation is quick (<200–500ms), generate synchronously in request and stream the response with appropriate headers.
  • Heavy PDFs: Offload to background jobs and notify the user via email or WebSocket/ActionCable when ready. Provide a progress indicator or a 'Generating...' page.
  • Streaming: Use Rails streaming (ActionController::Live) or chunked responses to start sending parts early, but be mindful of server thread usage.

Example: synchronous generation with WickedPDF

# Gemfile
gem 'wicked_pdf'
gem 'wkhtmltopdf-binary' # or install wkhtmltopdf separately

# Controller
class ReportsController < ApplicationController
  def show
    @report = Report.find(params[:id])
    html = render_to_string('reports/show.pdf.erb', layout: 'pdf', locals: { report: @report })
    pdf = WickedPdf.new.pdf_from_string(html)
    send_data pdf, filename: "report-\#{@report.id}.pdf", type: 'application/pdf', disposition: 'inline'
  end
end

Example: background generation pattern

  • User requests PDF → create a job (Sidekiq) that generates the PDF and uploads to S3.
  • Notify user via ActionCable or email with a pre-signed S3 URL when ready.
class GenerateReportJob
  include Sidekiq::Worker

  def perform(report_id, user_id)
    report = Report.find(report_id)
    html = ApplicationController.renderer.render(template: 'reports/show.pdf', assigns: { report: report })
    pdf = WickedPdf.new.pdf_from_string(html)
    s3_key = "reports/\#{report_id}/\#{SecureRandom.hex(8)}.pdf"
    s3.put_object(bucket: 'my-bucket', key: s3_key, body: pdf, content_type: 'application/pdf')
    # notify user with presigned URL
  end
end

Performance & resource considerations

  • Rendering via headless Chrome or wkhtmltopdf can be CPU and memory intensive — isolate in worker pool with resource limits or use separate service with autoscaling.
  • Cache generated PDFs for repeat requests and use conditional GET or ETag headers.
  • Use pre-render templates and avoid heavy JS execution where possible to reduce runtime.

Subquestions you should expect

  1. When to choose Prawn vs HTML-based rendering?
    Prawn for programmatic, precise control (invoices with tables), HTML-based (WickedPDF/Grover) for WYSIWYG templates that designers can handle.
  2. How to preview PDFs in app?
    Stream inline PDFs in browser (disposition: 'inline') or provide presigned S3 URL for direct viewing via CDN.
