Fetching Batches of Records in Rails

Why Batch Processing?

When dealing with large datasets in Rails, loading all records into memory at once can cause significant performance issues, including memory bloat and slow response times. Batch processing allows us to process records in smaller chunks, reducing memory consumption and improving overall application performance.

Available Methods

Rails provides three primary methods for batch processing: find_each, find_in_batches, and in_batches.

1. find_each

The simplest way to iterate through records in batches. It yields individual records to a block.

Basic Usage:

User.find_each do |user| puts user.email end

Key Features:

  • Processes records one-by-one
  • Default batch size: 1000 records
  • Automatically orders by primary key
  • Handles large datasets efficiently

Customization Options:

# Change batch size User.find_each(batch_size: 500) do |user| # ... end # Start from a specific point User.find_each(start: 5000) do |user| # ... end

2. find_in_batches

Similar to find_each, but yields entire batches (arrays of records) rather than individual records.

Basic Usage:

User.find_in_batches do |users| users.each { |user| puts user.email } end

Key Features:

  • Yields batches as arrays
  • More efficient for certain operations
  • Allows batch-level processing

Customization Options:

# Specify columns to select User.find_in_batches(select: :email) do |users| # Only email field loaded end

3. in_batches

The most flexible option, providing direct access to batch objects for more advanced scenarios.

Basic Usage:

User.in_batches do |relation| relation.update_all(active: true) end

Key Features:

  • Provides batch objects with additional methods
  • Supports chaining with other query methods
  • Allows batch-level operations

Advanced Usage:

# Access batch information User.in_batches(of: 100).each_with_index do |relation, batch_index| puts "Processing batch #{batch_index}" # Perform batch operation relation.update_all(processed_at: Time.current) end

Comparison Table

Method Yields Individual Records Yields Batches Batch Object Access Best For
find_each Yes No No Simple iteration over records
find_in_batches No Yes (as arrays) No Batch-level processing
in_batches No Yes (as relations) Yes Advanced batch operations

Important Considerations

  • Ordering: All batch methods rely on primary key ordering. If your records aren't ordered by ID, results may be inconsistent.
  • Concurrency: Batch processing isn't thread-safe by default. Use appropriate locking mechanisms if modifying records.
  • Database Load: While batch processing reduces memory usage, it increases database load due to multiple queries.
  • Association Loading: Be cautious with eager loading associations, as it can significantly increase memory usage.

Best Practices

  • Always specify a reasonable batch_size based on your memory constraints
  • Use select to limit loaded columns when possible
  • Avoid complex calculations inside batch blocks
  • Consider background jobs for long-running batch processes
  • Monitor database performance during batch operations

Alternatives

  • Raw SQL Cursors: For extremely large datasets, consider database-specific cursor implementations
  • Background Jobs: Use Active Job with queue adapters for asynchronous batch processing
  • Streaming Responses: For web requests, consider streaming responses with ActionController::Live

Conclusion

Choosing the right batch processing method depends on your specific use case. For simple iteration, find_each is usually sufficient. For batch-level operations, find_in_batches or in_batches provide more flexibility. Always consider memory constraints and database performance when working with large datasets.
