Counter Cache in Ruby on Rails

Understanding Counter Cache

What is Counter Cache?

A feature that maintains a cached count of associated records on a parent model, avoiding expensive COUNT queries.

Implementation Requirements

  • Parent model must have a `counter_cache` column
  • Child model must declare `belongs_to` with `counter_cache: true`
  • Database triggers or callbacks to keep counts synchronized

Basic Setup

# app/models/post.rb class Post < ApplicationRecord belongs_to :category, counter_cache: true end # app/models/category.rb class Category < ApplicationRecord has_many :posts end

Database Column

# db/migrate/xxxxxx_add_counter_cache_to_categories.rb add_column :categories, :posts_count, :integer, default: 0

Keeping Counts Updated

Use ActiveRecord callbacks to increment/decrement counters:

# app/models/post.rb after_save :increment_posts_count after_destroy :decrement_posts_count private def increment_posts_count category.increment!(:posts_count) end def decrement_posts_count category.decrement!(:posts_count) end

Performance Benefits

Scenario Without Counter Cache With Counter Cache
Displaying post count SELECT COUNT(*) FROM posts WHERE category_id = X SELECT posts_count FROM categories WHERE id = X
Update frequency Every read operation Only when posts are added/removed
Performance impact High for large datasets Constant time lookup

Advanced Usage Patterns

  • Conditional counter caching with scopes
  • Multi-level nested counter caches
  • Custom named counters for different relationships

Limitations

  • Requires careful synchronization
  • Not suitable for highly dynamic counts
  • May require eventual consistency checks
