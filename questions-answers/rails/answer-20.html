Test-Driven Development in Ruby on Rails

Core Principles

Red-Green-Refactor Cycle

  1. Red: Write failing tests for new functionality
  2. Green: Implement minimal code to pass tests
  3. Refactor: Improve code while keeping tests passing

Testing Pyramid

Test Type Purpose Examples
Unit Tests Isolate small pieces of functionality Model validations, helper methods
Integration Tests Test interactions between components Controller actions, service objects
System Tests Full-stack browser simulation End-to-end user workflows

Setting Up Tests in Rails

# Gemfile group :development, :test do gem 'rspec-rails' gem 'factory_bot_rails' gem 'shoulda-matchers' end # spec/rails_helper.rb RSpec.configure do |config| config.include Shoulda::Matchers::ActiveModel config.include FactoryBot::Syntax::Methods end

Writing Unit Tests

# Model validation test describe User do it "is valid with proper attributes" do user = build(:user, name: "John", email: "john@example.com") expect(user).to be_valid end it "requires an email address" do user = build(:user, name: "Jane") expect(user).not_to be_valid expect(user.errors[:email]).to include("can't be blank") end end

Writing Integration Tests

# Controller test describe UsersController do describe "GET /users" do it "returns all users" do create_list(:user, 3) get :index expect(response).to have_http_status(:ok) expect(assigns(:users).size).to eq(3) end end end

Writing System Tests

# System test with Capybara require "rails_helper" feature "User registration" do scenario "successful registration" do visit new_user_path fill_in "Name", with: "Alice Smith" fill_in "Email", with: "alice@example.com" click_button "Sign Up" expect(page).to have_content("Welcome, Alice!") expect(User.count).to eq(1) end end

Test Coverage Guidelines

  • Aim for 80-90% coverage for critical business logic
  • Prioritize tests for high-risk areas (payment processing, auth)
  • Include negative tests for edge cases
  • Mock external services to avoid flakiness
