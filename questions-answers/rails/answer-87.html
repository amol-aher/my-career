Overview

How to configure CORS for Rails and how reverse proxies (Nginx, ALB) affect headers and routing. Includes debugging tips.

Basics of CORS

CORS is a browser-enforced mechanism. Servers must respond with the proper Access-Control-* headers for cross-origin requests.

Configuring rack-cors in Rails

# config/initializers/cors.rb
Rails.application.config.middleware.insert_before 0, Rack::Cors do
  allow do
    origins ENV.fetch('CORS_ALLOWED_ORIGINS', 'https://app.example.com')
    resource '/api/*', headers: :any, methods: [:get, :post, :put, :patch, :delete, :options, :head], credentials: true, max_age: 600
  end
end

Remember not to use origins '*' with credentials: true.

Reverse proxy implications

  • Reverse proxies can strip or add headers. Ensure they forward Origin to backend if you're using dynamic origin validation.
  • For TLS termination at ALB/Nginx, forward X-Forwarded-Proto and X-Forwarded-For so Rails can detect the original scheme and IP.
  • Set config.action_dispatch.trusted_proxies and config.force_ssl = true appropriately.

Common pitfalls & debugging

  • OPTIONS preflight returning 404 — make sure middleware responds to OPTIONS.
  • Credentials issues — ensure Access-Control-Allow-Credentials is present and the client sends withCredentials.
  • Header rewriting — ensure proxies don't remove access-control headers set by backend.

Use browser devtools network tab and curl (curl doesn't enforce CORS but shows headers) to debug.

Subquestions you should expect

  1. How to handle dynamic origins?
    Whitelist origins server-side and echo back the incoming origin only if allowed. Don't return '*' for credentialed requests.
  2. How to configure Nginx to pass Origin?
    Nginx forwards headers by default — ensure no proxy_hide_header or other directives strip them. Use proxy_set_header to forward Origin and other headers.
