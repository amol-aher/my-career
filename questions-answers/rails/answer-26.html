Design Patterns in Ruby on Rails

Essential Design Patterns

1. Service Objects

Encapsulate business logic in plain Ruby classes:

# app/services/order_processor.rb class OrderProcessor def initialize(order) @order = order end def process_payment # Business logic here end end

2. Repository Pattern

Separate data access logic from domain models:

# app/repositories/user_repository.rb class UserRepository def find_active User.where(active: true) end end

3. Command Pattern

Encapsulate requests as objects:

# app/commands/create_user_command.rb class CreateUserCommand def initialize(attributes) @attributes = attributes end def execute User.create(@attributes) end end

4. Observer Pattern

Define hooks for model events:

# app/models/user.rb class User < ApplicationRecord after_create :send_welcome_email private def send_welcome_email # Email sending logic end end

5. Strategy Pattern

Select algorithms at runtime:

# app/strategies/payment_strategy.rb class PaymentStrategy def pay(amount) raise NotImplementedError end end class CreditCardStrategy < PaymentStrategy def pay(amount) # Credit card processing logic end end class PayPalStrategy < PaymentStrategy def pay(amount) # PayPal processing logic end end

Why These Patterns Matter

  • Maintainability: Decouple concerns and responsibilities
  • Testability: Isolate units for easier testing
  • Scalability: Design systems that grow with application needs
  • Collaboration: Standardized patterns help team communication
