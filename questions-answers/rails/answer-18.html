Monkey Patching in Ruby

Definition and Purpose

Monkey patching (or dynamic patching) is the process of modifying or extending existing classes or modules at runtime without changing their original source code.

Why Use Monkey Patching?

  • Fix bugs in third-party libraries
  • Add functionality to core classes
  • Create mock objects for testing
  • Implement cross-cutting concerns (logging, security)

Basic Implementation

# Adding a method to String class class String def shout self.upcase + "!!!" end end # Using the patched method puts "hello".shout # => "HELLO!!!"

Scope Considerations

Scope Effect
Global Scope Affects all instances
Module Scope Limited to specific context
Class-Specific Modifies only one class

Best Practices

  • Use sparingly and document thoroughly
  • Consider alternatives like composition first
  • Test patches thoroughly
  • Be cautious of method name collisions

Advanced Techniques

# Using alias_method to preserve original behavior class String alias_method :original_upcase, :upcase def upcase original_upcase + " (MODIFIED)" end end # Using prepend to add methods before existing ones String.prepend(Module.new { def upcase super + " (PREPEND)" end })

Potential Risks

  • Unexpected side effects
  • Compatibility issues with library updates
  • Difficulty in debugging
  • Namespace pollution
