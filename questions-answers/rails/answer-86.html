Secure Authentication for Rails APIs Serving Web and Mobile Clients

Prepared by: Senior Software Engineer & System Architect — Rails / AWS / SQL / Vue.js

Date: 2025-09-10 (UTC)

Overview

Designing an authentication system that supports both browser-based web apps (cookie-based) and mobile/native clients (token-based) securely.

Goals & Threat Model

  • Protect user credentials and sessions from theft.
  • Prevent CSRF for browser flows, prevent token reuse, and allow revocation and rotation.
  • Support offline mobile clients and refresh tokens.

Recommended approach (hybrid)

Use cookie-based sessions for web UI (same-site cookies + CSRF) and short-lived access tokens (JWT) with refresh tokens for mobile/third-party clients. Centralize auth in an Auth service or use Devise + Doorkeeper.

Web flow (cookie-based)

  • Authenticate via username/password over TLS and set a session cookie with HttpOnly, Secure, and SameSite=Lax/Strict.
  • Protect state-changing endpoints with CSRF tokens (Rails includes this by default).
  • Use rotating session IDs and short session expiry + remember-me via secure refresh tokens.

Mobile/API flow (token-based)

  • Issue a short-lived access token (JWT, 5–15 minutes) and a long-lived refresh token (secure, stored in secure storage on device).
  • Use refresh tokens to obtain new access tokens; store refresh token identifiers server-side to allow revocation and detect theft.
  • Implement token rotation: when refresh token is used, issue a new refresh token and revoke the old one to limit replay.
  • Provide OAuth2/OpenID Connect flows using Doorkeeper or an external provider for third-party access.

Server-side best practices

  • Keep JWTs short lived and validate signatures and claims. Prefer reference tokens for more control (store token metadata server-side).
  • Use TLS everywhere, HSTS, and CORS configured properly for API endpoints.
  • Store refresh token metadata (device_id, user_agent, ip) to detect anomalies.
  • Allow per-device revocation and show active sessions in user settings.

Additional security measures

  • Rate limit auth endpoints and instrument for brute-force detection.
  • Enforce strong password policies and offer MFA (TOTP, WebAuthn).
  • Use device trust and risk-based authentication for unusual logins.

Subquestions you should expect

  1. Should I store JWTs in localStorage?
    Avoid localStorage for web apps; prefer HttpOnly cookies to mitigate XSS. If using SPA with tokens, use Authorization header and implement appropriate XSS protections.
  2. How to revoke tokens?
    Store refresh token IDs or token version per user; increment token version on password reset or logout to invalidate older tokens.
  3. OAuth2 vs custom tokens?
    For third-party integrations prefer OAuth2/OpenID Connect; for first-party mobile apps, JWTs with server-side rotation are acceptable.
