Rails Middleware Explained

Rails middleware are modular components that sit between the web server and your Rails application. They process HTTP requests and responses, enabling cross-cutting concerns like authentication, logging, and parameter parsing.

Core Concepts:

  1. Request Flow: Middlewares form a stack where each processes the request before passing it to the next
  2. Response Flow: Responses travel back through the stack in reverse order
  3. Rack Compliance: Rails middlewares adhere to Rack specifications

Common Built-in Middlewares:

  • ActionDispatch::RequestId: Adds unique request ID for traceability
  • Rack::Runtime: Measures request processing time
  • ActionDispatch::Flash: Manages flash messages between requests
  • Rack::MethodOverride: Supports HTTP method overrides
  • ActionDispatch::Cookies: Handles cookie management

Sub-question: How to create custom middleware?

There are two primary ways to create middleware in Rails:

1. Class-based Middleware

# app/middleware/request_logger.rb
class RequestLogger
  def initialize(app)
    @app = app
  end

  def call(env)
    start_time = Time.now
    status, headers, response = @app.call(env)
    duration = Time.now - start_time
    
    Rails.logger.info("Request #{env['REQUEST_METHOD']} #{env['PATH_INFO']} completed in #{duration.round(2)}s")
    
    [status, headers, response]
  end
end

2. Block-based Middleware

# config/application.rb
config.middleware.use lambda { |env|
  # Custom logic here
  @app.call(env)
}

To add your middleware to the stack:

# config/application.rb
config.middleware.insert_before ActionDispatch::Static, RequestLogger

Sub-question: When should you use middleware vs controllers?

Aspect Middleware Controller
Scope Global application-wide Per-controller basis
Timing Before/after request processing During request handling
Access Limited access to request/response Full access to params, session, etc.
Use Cases Authentication, logging, compression Business logic, data manipulation

Sub-question: How to test middleware?

Testing involves simulating requests through the middleware stack:

# spec/middleware/request_logger_spec.rb
require 'rails_helper'

RSpec.describe RequestLogger do
  let(:app) { ->(env) { [200, {'Content-Type' => 'text/plain'}, ['OK']] } }
  let(:middleware) { RequestLogger.new(app) }

  it 'logs request information' do
    expect(Rails.logger).to receive(:info).with(/Request GET .* completed in/)
    middleware.call({'REQUEST_METHOD' => 'GET', 'PATH_INFO' => '/test'})
  end
end
