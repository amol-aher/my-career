Duck Typing in Ruby

Concept and Principles

What is Duck Typing?

"If it walks like a duck and quacks like a duck, then it probably is a duck."

An object-oriented programming principle where the suitability of an object for a particular purpose is determined by the presence of certain properties and methods, rather than the actual type of the object.

Core Principle

# Instead of checking class if obj.respond_to?(:quack) obj.quack end

vs Static Typing

Feature Duck Typing Static Typing
Type Checking Runtime Compile-time
Flexibility High Low
Polymorphism Natural Explicit interfaces

Practical Examples

# Ruby Example module Quackable def quack puts "Quack!" end end class Duck include Quackable end class ToyDuck include Quackable end duck = Duck.new toy_duck = ToyDuck.new [duck, toy_duck].each(&:quack)

Benefits in Ruby

  • Flexible design patterns
  • Easier polymorphism implementation
  • Natural fit for Ruby's dynamic nature
  • Reduced coupling between components

Potential Pitfalls

  • Runtime errors if expected methods aren't present
  • Less explicit contracts can lead to confusion
  • Testing requires more thorough scenario coverage
