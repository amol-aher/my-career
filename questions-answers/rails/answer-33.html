HTTP Status Codes in the 300 Series

The 300 series HTTP status codes indicate redirection. They inform clients that the requested resource has moved or needs additional information to fulfill the request.

Status Code Name Description Usage Example
300 Multiple Choices Indicates multiple options for the resource that the client may choose from Content negotiation where multiple formats exist
301 Moved Permanently Resource has been permanently moved to a new URL Domain migration or URL restructuring
302 Found / Moved Temporarily Resource is temporarily located at another URL Session-based redirects or temporary maintenance pages
303 See Other Response to POST request directing to a GET resource Form submission redirecting to confirmation page
304 Not Modified Resource hasn't changed since last request (cache hit) Conditional GET requests with ETag/Last-Modified
305 Use Proxy Client must access resource through specified proxy Legacy proxy configuration (rarely used today)
307 Temporary Redirect Similar to 302 but preserves original HTTP method POST request redirected to maintain method integrity
308 Permanent Redirect Similar to 301 but preserves original HTTP method Permanent redirects maintaining POST semantics

Implementation in Rails

Rails provides convenient helpers for redirects:

# Permanent redirect (301)
redirect_to users_path, status: :moved_permanently

# Temporary redirect (302)
redirect_to login_path, status: :found

# See other (303)
redirect_to confirmation_url, status: :see_other

# Not modified (304)
if stale?(last_modified: @article.updated_at)
  head :not_modified
end

Common Subquestions:

Q: When should you use 301 vs 302 redirects?

Use 301 for permanent moves (SEO benefits), 302 for temporary situations. Search engines treat 301 as permanent and update indexes accordingly.

Q: How do browsers cache 304 responses?

Browsers cache 304 responses based on Cache-Control headers. Proper ETag/Last-Modified headers enable efficient conditional requests reducing bandwidth.

Q: What's the difference between 307 and 308?

Both preserve the original HTTP method, but 307 is temporary while 308 is permanent. This distinction affects caching behavior and search engine indexing.
