Adding a New Feature to an Existing Rails App — End-to-end Approach

Prepared by: Senior Software Engineer & System Architect — Rails / AWS / SQL / Vue.js

Date: 2025-09-10 (UTC)

Overview

Step-by-step approach from database changes to API and UI delivery, emphasizing safety, iteration, testing, and observability.

1) Discovery & Requirements

Understand the feature: functional requirements, non-functional requirements (performance, security), owners, SLA, and success metrics.

  • Talk to product and stakeholders to capture acceptance criteria.
  • Create example user journeys and API contracts (request/response examples).
  • Identify data model changes and surface areas impacted (background jobs, caches, indexes).

2) Design & API Contract

Design the database schema changes, API endpoints (REST or GraphQL), UI wireframes, and migration strategy. Prefer backward-compatible APIs when possible.

  • Define request/response shapes and error codes.
  • Define feature flags and rollout strategy.
  • Design migrations as expand → backfill → switch → contract.

3) Plan the work & break into small tasks

Split the work into small, testable PRs: schema changes, migrations, models, service objects, API endpoints, background jobs, UI. Each PR should be deployable independently if possible.

4) Implement database changes safely

Follow expand-contract pattern:

  1. Add new nullable columns or new tables.
  2. Deploy code that writes to both old and new fields (dual-write) or publishes events for backfill.
  3. Backfill data using background jobs with throttling and monitoring.
  4. Switch reads to new columns once backfill is complete.
  5. Remove old columns after verification.
# example migration
class AddRatingToProducts < ActiveRecord::Migration[7.0]
  def change
    add_column :products, :rating, :decimal, precision: 3, scale: 2, default: nil
    add_index :products, :rating
  end
end

5) Implement business logic & layering

Keep controllers thin — implement business logic in model methods, service objects, or domain classes. Add validations and use form objects for complex params.

6) API layer & authentication

Expose endpoints with clear versioning and authorization checks. Use serializers (fast_jsonapi / ActiveModelSerializers) for stable outputs and document via OpenAPI.

7) UI implementation & progressive enhancement

Implement UI components (Vue.js) with feature flags, client-side validations, and progressive enhancement. Keep API responses minimal to avoid overfetching.

8) Testing strategy

  • Unit tests for models and services.
  • Request/integration tests for APIs (RSpec + request specs).
  • System tests for UI flows (Capybara or Cypress).
  • Contract tests if integrating with other services.

9) Deploy, monitor & iterate

Deploy to staging, run smoke tests, monitor logs/metrics, and perform canary/gradual rollout behind feature flags. Observe SLOs and error budgets, then promote to production and monitor.

Subquestions you should expect

  1. How do you perform rolling back?
    Use immutable artifacts and deploy the previous image; ensure database migrations are backward compatible or have compensating migrations for rollback windows.
  2. How to avoid long downtime for migrations?
    Use online schema changes, avoid blocking statements, and perform backfills asynchronously.
  3. How to keep API backwards compatible?
    Add new optional fields, version endpoints, and deprecate old fields with clear timelines.
