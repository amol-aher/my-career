CORS in Rails

What is CORS?

Cross-Origin Resource Sharing (CORS) is a mechanism that allows restricted resources on a web page to be requested from another domain outside the domain from which the resource originated.

Why Use CORS?

  • Enable secure cross-domain data transfers
  • Support modern web applications with API integrations
  • Facilitate mashups and widget embedding

Configuring CORS in Rails

1. Using rack-cors Gem

# Gemfile gem 'rack-cors'

2. Basic Configuration

# config.ru use Rack::Cors do allow do origins 'https://trusted-client.com' resource '*', headers: ['X-Requested-With'] end end

3. Fine-grained Control

# Advanced configuration use Rack::Cors do allow do origins '*' resource '*', headers: ['Content-Type', 'Expires', 'Cache-Control', 'Content-Encoding'] methods ['GET', 'POST', 'PUT', 'DELETE', 'PATCH'] end end

Security Considerations

1. Restrict Origins

Never use `'*'` wildcard for production applications. Specify trusted domains only.

2. Protect Sensitive Endpoints

Exclude sensitive routes from CORS policy:

# Excluding specific routes use Rack::Cors do allow do origins 'https://public-api.com' resource '/', headers: ['Content-Type'], methods: ['GET'] end end

3. Handle Preflight Requests

Respond appropriately to OPTIONS requests:

# Handling preflight requests map = Rack::Cors::Map.new map.preflight(true) map.run(Rack::Lint.new(Rack::Lint::DEFAULT_OPTIONS))

Testing CORS Configuration

  • Use tools like curl or Postman to test CORS headers
    • $ curl -I https://your-app.com -H Origin:http://localhost:3000
  • Write integration tests for cross-origin requests

Common Pitfalls

  • Over-permissive CORS policies exposing sensitive data
  • Ignoring preflight requests leading to errors
  • Not accounting for browser-specific quirks
