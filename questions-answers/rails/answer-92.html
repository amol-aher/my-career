Using CDNs — What they are and how to use them

Prepared by: Senior Software Engineer & System Architect — Rails / AWS / SQL / Vue.js

Date: 2025-09-10 (UTC)

Overview

Definition, benefits, configuration and examples of using CDNs with Rails (CloudFront, Fastly, Cloudflare, Akamai), signed URLs, cache-control strategies, and invalidation.

What is a CDN and why use one?

CDN = Content Delivery Network. A globally distributed network of edge servers that cache and deliver content (static assets, images, videos, APIs) closer to end users to reduce latency, save origin bandwidth, and improve availability.

  • Benefits: lower latency, reduced origin load, DDoS mitigation at edge, geographic caching, and TLS termination at edge.

Common CDN providers I've worked with

  • AWS CloudFront: deeply integrated with S3, signed URLs, Lambda@Edge.
  • Fastly: programmable edge (VCL), real-time purging — good for dynamic caching strategies.
  • Cloudflare: easy global coverage, WAF, edge workers, and DNS integration.
  • Akamai: enterprise CDN with extensive features for high-volume media delivery.

How to use CDN with Rails assets and uploads

  • Assets pipeline: Configure Rails to serve assets from CDN host (asset_host). Precompile and upload assets to S3 or directly to CDN origin.
  • ActiveStorage: Use S3 for storage and serve via CloudFront with signed URLs for private objects.
  • Cache headers: Set appropriate Cache-Control and Expires headers. Use long-term caching for fingerprinted assets and short TTLs for dynamic content.
# config/environments/production.rb
config.action_controller.asset_host = "https://d123.cloudfront.net"
config.active_storage.service = :amazon

Cache invalidation & purging

Approaches:

  • Versioned assets: Fingerprint files (e.g., app-abcdef.js) so you rarely need purging.
  • Explicit purge: Use CDN APIs to purge specific URLs or cache tags (Fastly supports surrogate keys).
  • Short TTLs for dynamic endpoints: Use Cache-Control: max-age=0, s-maxage=60 for edge caching with origin revalidation.

Edge compute and tradeoffs

Edge compute (Lambda@Edge, Workers) allows running small logic at the edge (A/B tests, redirects, header rewrites). Use sparingly; consider complexity and debugging overhead.

Security & CDN

  • Use TLS at edge and enforce HTTPS.
  • Use WAF and rate-limiting at CDN level to block obvious attacks before they reach origin.
  • Use signed URLs or cookies for access-controlled content (ActiveStorage + CloudFront signed URLs).

Subquestions you should expect

  1. How to serve private files via CDN?
    Use signed URLs or signed cookies; CloudFront signed URLs integrate well with S3 private buckets.
  2. How to handle API caching?
    Cache only idempotent, read-heavy endpoints. Use Vary, Cache-Control, and consider Edge Side Includes or surrogate keys for partial caching.
