Difference Between includes and eager_load in Rails

Prepared by: Senior Software Engineer & System Architect — Rails / AWS / SQL / Vue.js

Date: 2025-09-10 (UTC)

Overview

Detailed differences between ActiveRecord's includes, preload, and eager_load, and when to use each.

Overview

ActiveRecord offers three main ways to avoid N+1:

  • preload — always issues separate queries for associations.
  • eager_load — forces a LEFT OUTER JOIN and loads everything in a single (bigger) query.
  • includes — intelligent: chooses between preload or eager_load depending on subsequent query constraints.

Behavioral differences

MethodSQLWhen to use
preloadMultiple SELECTsWhen joins are unnecessary and you want separate queries to keep joins out of critical paths.
eager_loadLEFT OUTER JOINWhen you need to filter/order by associated table columns (useful for complex filtering).
includesEither preload or eager_load based on queryDefault convenience — use when unsure and ActiveRecord can decide automatically.

Performance tradeoffs

  • JOIN size: eager_load produces joined rows (cartesian growth) which can blow up result sets if associations are 1:N.
  • Separate queries: preload keeps row counts smaller but executes multiple queries.
  • Indexes: Ensure associated tables have proper indexes for JOIN/filter operations.

Examples

# includes (Auto chooses)
User.includes(:posts).where(posts: { published: true }) 
# ActiveRecord will use LEFT OUTER JOIN under the hood (eager_load behavior)

# preload (always separate queries)
User.preload(:posts).to_a

# eager_load (force join)
User.eager_load(:posts).where("posts.created_at > ?", 1.week.ago)

Subquestions you should expect

  1. When does includes choose preload vs eager_load?
    When you reference the associated table in WHERE/ORDER/GROUP clauses, includes will use eager_load (JOIN). Otherwise it will use preload.
  2. When to use joins?
    Use joins when you want filtering based on associated tables and don't need the association objects loaded.
