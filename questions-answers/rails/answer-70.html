Single Sign-On (SSO) in Rails Applications

Introduction to SSO

Single Sign-On (SSO) is an authentication scheme that allows users to log in once and gain access to multiple applications without re-entering credentials. This improves user experience and security by reducing password fatigue and minimizing credential exposure.

In Rails applications, SSO is typically implemented using industry-standard protocols like OAuth 2.0, OpenID Connect (OIDC), or SAML.

Key Components of SSO

Component Description
Identity Provider (IdP) Service that authenticates users (e.g., Google, Okta, Azure AD, Auth0)
Service Provider (SP) Your Rails application that relies on the IdP for authentication
Protocol Communication method (OAuth 2.0, OIDC, SAML)
Assertion/Token Credentials exchanged between IdP and SP

Implementation Approaches in Rails

There are several ways to implement SSO in Rails:

  • OmniAuth: Popular gem for social login (supports multiple providers)
  • Devise with OmniAuth: Combines Devise authentication with OmniAuth
  • Doorkeeper: OAuth 2.0 provider for building your own IdP
  • Custom Solution: Direct integration with IdP APIs

Step-by-Step Implementation with OmniAuth

1. Add Dependencies

# Gemfile gem 'omniauth' gem 'omniauth-google-oauth2' # Example for Google gem 'devise' # Optional, if using Devise

2. Configure OmniAuth

# config/initializers/omniauth.rb Rails.application.config.middleware.use OmniAuth::Builder do provider :google_oauth2, ENV['GOOGLE_CLIENT_ID'], ENV['GOOGLE_CLIENT_SECRET'] # Add other providers as needed end

3. Set Environment Variables

# .env file GOOGLE_CLIENT_ID=your-client-id GOOGLE_CLIENT_SECRET=your-client-secret

4. Create Callback Controller

# app/controllers/auth_callbacks_controller.rb class AuthCallbacksController < ApplicationController def google user = User.from_omniauth(request.env["omniauth.auth"]) sign_in_and_redirect user end end

5. Add Routes

# config/routes.rb devise_for :users, controllers: { omniauth_callbacks: "auth_callbacks" }

The SSO Authentication Flow

Step 1: User Accesses Protected Resource

The user tries to access a protected page in your Rails app but isn't authenticated.

Step 2: Redirect to Identity Provider

Your app redirects the user to the chosen IdP (e.g., Google) with an authentication request containing:

  • Client ID and Secret
  • Callback URL (where the IdP will redirect after authentication)
  • Requested permissions/scopes

Step 3: User Authenticates with IdP

The user logs in to the IdP and grants permission for your app to access their profile information.

Step 4: IdP Returns Authentication Response

The IdP redirects back to your app's callback URL with an authentication token/assertion containing user information.

Step 5: Verify Token and Create Session

Your Rails app:

  • Verifies the token signature and validity
  • Extracts user information (email, name, etc.)
  • Creates or updates a local user record
  • Establishes a session for the user

Step 6: Grant Access

The user is now authenticated and can access protected resources in your app.

Security Considerations

  • Token Verification: Always verify tokens with the IdP's public key
  • Secure Storage: Store tokens securely (use Rails encrypted secrets)
  • HTTPS: Mandatory for all communications
  • Token Expiry: Respect token expiration times
  • Revocation Checks: Periodically check if tokens have been revoked

Subquestion: How to handle token revocation?

To handle token revocation:

# Add a background job to periodically check token validity class TokenRevocationChecker def perform(user_id) user = User.find(user_id) # Call IdP endpoint to check token status response = Faraday.get("#{ENV['IDP_BASE_URL']}/tokeninfo", headers: { 'Authorization': "Bearer #{user.access_token}" }) if response.status != 200 # Revoke token and force re-authentication user.update(access_token: nil) sign_out(user) end end end

Conclusion

Implementing SSO in Rails applications significantly improves security and user experience. The key steps involve choosing an IdP, integrating with OmniAuth or a similar library, properly configuring authentication flows, and ensuring secure token handling. By following RESTful principles and implementing proper security measures, you can create a seamless authentication experience for your users while maintaining the highest security standards.
