API Best Practices in Ruby on Rails

Key Principles

1. Versioning

# config/routes.rb namespace :api, defaults: { format: :json } do resources :products end

2. Error Handling

# app/controllers/api/v1/products_controller.rb class ProductsController < ApplicationController rescue_from ActiveRecord::RecordNotFound, with: :json def show product = Product.find(params[:id]) render json: product end end

3. Serialization

# app/serializers/product_serializer.rb class ProductSerializer include JSONAPI::SerializerResource attributes :id, :name, :price has_one :category end

4. Rate Limiting

# app/middleware/rate_limiter.rb class RateLimiter def initialize(app) @app = app end def call(env) status, headers, response = @app.call(env) if rate_exceeded?(env) return [429, {'Content-Type' => 'application/json'}, '{"error": "Rate limit exceeded"}] end [status, headers, response] end private def rate_exceeded?(env) current_time = Time.now.to_i key = "rate_limit:#{env['REMOTE_ADDR']}" Redis.current.get(key) > MAX_REQUESTS_PER_MINUTE end end

5. Security Headers

# config/initializers/security_headers.rb Rails.application.configure do |config| config.middleware.insert_before Rack::Sendfile, Rack::Deflater config.middleware.use Rack::SSL, :exclude => proc { |env| env["HTTPS"] != "on" } end

Best Practices Summary

  • Use versioned APIs (e.g., `/api/v1/resource`)
  • Implement proper authentication (JWT/OAuth)
  • Include pagination parameters (`page`, `per_page`)
  • Add etag support for caching
  • Implement rate limiting and throttling
  • Use HSTS and secure cookies
