Handling Dynamic Content in PDFs

Prepared by: Senior Software Engineer & System Architect — Rails / AWS / SQL / Vue.js

Date: 2025-09-10 (UTC)

Overview

Strategies for embedding dynamic content (tables, images, localized text, variable-length sections) into PDFs generated by Rails apps.

Dynamic content challenges

  • Variable-length content affects pagination and layout (tables, multi-page sections).
  • Dynamic images (user-uploaded) need proper sizing and embedding.
  • Localization and fonts (embedding fonts to support non-Latin scripts).

Techniques for dynamic PDFs

  • Template-driven HTML PDFs: Use ERB/HAML templates and CSS for layout with Grover or WickedPDF for complex layouts.
  • Programmatic layout: Use Prawn for precise control, build pages and paginate content programmatically.
  • Chunking large tables: Break tables into page-sized chunks and repeat headers on each page.
  • Image handling: Use optimized image sizes, prefetch from S3, and convert to formats friendly to PDF engines.
  • Fonts & localization: Embed fonts (TTF) in PDFs and ensure CSS @font-face is available to the HTML renderer.

Example: Prawn table pagination

Prawn::Document.generate('report.pdf') do |pdf|
  pdf.font_families.update('DejaVu' => { normal: '/path/DejaVuSans.ttf' })
  pdf.font 'DejaVu'
  data = [['Header1', 'Header2']] + rows # rows from database
  table data, header: true do |t|
    t.row(0).font_style = :bold
    t.column(1).width = 200
  end
end

Example: HTML + CSS approach tips

  • Design CSS with page-break-inside: avoid; use page-break-before and page-break-after rules.
  • Use @media print CSS to tailor styling for PDF renderers.
  • Test with your renderer (wkhtmltopdf vs Chrome) as CSS support differs.

Subquestions you should expect

  1. How to handle table headers across pages?
    Use table markup supported by renderer and repeat headers via renderer-specific options (Prawn handles it programmatically; CSS-based solutions are renderer-dependent).
  2. How to make PDFs accessible?
    Use proper tagging and ARIA-like semantics where supported; programmatic engines like Prawn can include metadata. Accessibility support for PDFs can be limited, so plan if required.
