GitHub Actions — sample CI/CD workflow (.github/workflows/ci.yml)

This example demonstrates PR checks, build, test, image build, scan, and push to ECR, then trigger a deploy job.

name: CI

on:
  push:
    branches: [ main ]
  pull_request:
    branches: [ main ]

env:
  RUBY_VERSION: 3.2.2
  RAILS_ENV: test
  AWS_REGION: us-east-1
  ECR_REGISTRY: 123456789012.dkr.ecr.us-east-1.amazonaws.com
  IMAGE_NAME: myapp

jobs:
  test:
    runs-on: ubuntu-latest
    services:
      postgres:
        image: postgres:14
        env:
          POSTGRES_USER: postgres
          POSTGRES_PASSWORD: postgres
        ports:
          - 5432:5432
        options: >-
          --health-cmd pg_isready --health-interval 10s --health-timeout 5s --health-retries 5

    steps:
      - uses: actions/checkout@v4
      - uses: ruby/setup-ruby@v1
        with:
          ruby-version: ${{ env.RUBY_VERSION }}
      - name: Cache gems
        uses: actions/cache@v4
        with:
          path: vendor/bundle
          key: ${{ runner.os }}-gems-${{ hashFiles('**/Gemfile.lock') }}
      - name: Install dependencies
        run: |
          bundle config set --local path 'vendor/bundle'
          bundle install --jobs 4 --retry 3
      - name: Set up DB
        run: |
          cp config/database.ci.yml config/database.yml
          bundle exec rails db:create db:schema:load
      - name: Run tests
        run: bundle exec rspec
  build-and-push:
    needs: test
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Login to ECR
        uses: aws-actions/amazon-ecr-login@v1
      - name: Build and push
        uses: docker/build-push-action@v4
        with:
          context: .
          push: true
          tags: ${{ env.ECR_REGISTRY }}/${{ env.IMAGE_NAME }}:${{ github.sha }}
  deploy:
    needs: build-and-push
    runs-on: ubuntu-latest
    steps:
      - name: Trigger deploy (example: call your deployment endpoint or invoke ArgoCD)
        run: |
          curl -X POST https://deploy-api.example.com/deploy -d '{"image":"'"${{ env.ECR_REGISTRY }}/${{ env.IMAGE_NAME }}:${{ github.sha }}"}'

Notes:

  • Store AWS credentials and other secrets in GitHub Secrets and use least-privilege IAM credentials.
  • Use environments and required reviewers for production deployments.

Jenkins — Declarative Pipeline (Jenkinsfile) example

Example Jenkinsfile using declarative pipeline with stages and credentials binding.

pipeline {
  agent { label 'docker' }
  environment {
    ECR_REGISTRY = '123456789012.dkr.ecr.us-east-1.amazonaws.com'
    IMAGE_NAME = 'myapp'
  }
  stages {
    stage('Checkout') {
      steps {
        checkout scm
      }
    }
    stage('Build & Test') {
      agent { docker { image 'ruby:3.2.2' } }
      steps {
        sh 'bundle config set --local path vendor/bundle'
        sh 'bundle install --jobs 4 --retry 3'
        sh 'bundle exec rspec'
      }
    }
    stage('Build Image') {
      steps {
        withCredentials([[$class: 'AmazonWebServicesCredentialsBinding', credentialsId: 'aws-deployer']]) {
          sh '''
            $(aws ecr get-login --no-include-email --region $AWS_REGION)
            docker build -t $ECR_REGISTRY/$IMAGE_NAME:$GIT_COMMIT .
            docker push $ECR_REGISTRY/$IMAGE_NAME:$GIT_COMMIT
          '''
        }
      }
    }
    stage('Deploy') {
      steps {
        input message: 'Approve production deploy?', ok: 'Deploy'
        sh "curl -X POST https://deploy-api.example.com/deploy -d '{"image":"$ECR_REGISTRY/$IMAGE_NAME:$GIT_COMMIT"}'"
      }
    }
  }
  post {
    always {
      archiveArtifacts artifacts: 'log/test-results/**', allowEmptyArchive: true
    }
  }
}

Notes:

  • Jenkins allows flexible agent orchestration and integration with Kubernetes plugin to spin up ephemeral agents.
  • Use credentials binding and secret text for tokens and AWS keys.

CI Best Practices & Tips

  • Cache dependencies: Use caching for bundler, node_modules, and build artifacts to speed up pipelines.
  • Parallelize tests: Use test splitting (knapsack, parallel_tests) to reduce latency.
  • Fail fast: Quickly run lint and fast unit tests first to avoid wasted work.
  • Immutable artifacts: Build once and promote the artifact between environments rather than rebuilding for each env.
  • Artifact signing: Sign releases or images and verify during deploy.
  • Branch protection & gates: Require CI green and PR reviews before merging to protected branches.

Subquestions you should expect

  1. How to handle secrets?
    Use the platform's secret store (GitHub Secrets, Jenkins Credentials) and integrate with external stores (AWS Secrets Manager or Vault) for dynamic secrets.
  2. How to create preview environments?
    Create ephemeral namespaces and deploy PR images automatically; tear them down when PR closes. Use the branch name or PR number in image tags and K8s namespace names.
  3. How to speed up pipelines?
    Cache, parallelize, run only affected tests via changed file detection, and use job matrices sparingly.
