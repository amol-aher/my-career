Null Object pattern — cleaning up conditionals in Rails

Problem: Many controller/view conditionals like if user or if current_account.present? spread logic and lead to clutter.

Null Object idea

Create an object that responds to the same methods as the real object but implements no-op or sensible default behavior, eliminating many nil checks.

Example: NullUser

class NullUser
  def name; 'Guest'; end
  def admin?; false; end
  def email; nil; end
  def present?; false; end
end

# controller helper
def current_user
  @current_user ||= (super || NullUser.new)
end

# view
= current_user.name # always safe

Variants

  • Use SimpleDelegator to delegate unknown methods to a default object.
  • Use gems like null_object if you prefer structured implementations.

When to use

  • When the absence of an object is common and handling it with branch logic pollutes the codebase.
  • In views and presenters to simplify template logic.

Caveats

  • Make sure the Null object implements only safe defaults — unknown or unexpected behavior may hide bugs.
  • Do not use Null objects to mask real errors in business logic; they should represent true absence semantics.

Interview tip
