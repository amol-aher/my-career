Difference between Template Method and Strategy patterns in Ruby

Template Method

Defines the skeleton of an algorithm in a base class, allowing subclasses to implement specific steps. Uses inheritance; base class orchestrates the flow.

class Report
  def generate
    fetch_data
    process
    export
  end

  def fetch_data
    raise NotImplementedError
  end

  def process
    raise NotImplementedError
  end

  def export
    raise NotImplementedError
  end
end

class SalesReport < Report
  def fetch_data; end
  def process; end
  def export; end
end

Strategy

Encapsulates interchangeable algorithms in separate classes and composes them into a context. Uses composition and allows runtime swapping.

class ExportCsv
  def export(report); end
end

class ExportJson
  def export(report); end
end

class ReportService
  def initialize(exporter)
    @exporter = exporter
  end

  def generate(report)
    @exporter.export(report)
  end
end

Key differences

  • Inheritance vs Composition: Template Method relies on subclassing; Strategy uses composition.
  • Runtime flexibility: Strategy allows swapping behaviors at runtime; Template Method fixes the skeleton at compile/design time.
  • When to use: Template Method when algorithm steps are fixed but implementations vary; Strategy when you need interchangeable behaviors (e.g., different export formats, payment processors).

Interview tip

Explain both with short code and justify the choice depending on need for runtime flexibility and complexity. Mention that in Ruby, duck typing blurs the lines—both are easy to implement idiomatically.
