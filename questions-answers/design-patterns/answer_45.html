ActiveSupport::Concern & the Mixin / Module pattern

Summary: ActiveSupport::Concern is a Rails helper for writing modules (mixins) that cleanly separate behavior for reuse across models/controllers. It provides structured hooks for included and class methods and encourages small, composable behavior units.

Example

module Archivable
  extend ActiveSupport::Concern

  included do
    scope :archived, -> { where.not(archived_at: nil) }
    scope :active, -> { where(archived_at: nil) }
  end

  def archive!
    update!(archived_at: Time.current)
  end

  class_methods do
    def archive_all
      update_all(archived_at: Time.current)
    end
  end
end

class Post < ApplicationRecord
  include Archivable
end

How it maps to Mixin pattern

  • Mixins allow composition of behavior without inheritance.
  • ActiveSupport::Concern adds syntactic niceties (automatic import of class methods and included hooks).
  • Concerns are best for small, focused behaviors (taggable, searchable, archivable).

Best practices

  • Keep concerns small and single-purpose (SRP).
  • Document expectations and required methods (use ActiveSupport::Concern to define required hooks).
  • Avoid overusing concerns as a catch-all — they can become a God module.

Interview tip

Discuss a refactor where you extracted shared behavior into concerns, and how it improved code reuse and testability while noting how you avoided large, unmaintainable concern modules.
