Factory Method pattern — implementation in Ruby

Intent: define an interface for creating an object, but let subclasses decide which class to instantiate. Useful when a class can’t anticipate which concrete class it must create.

Simple example — notifications

class Notification
  def deliver; raise NotImplementedError; end
end

class EmailNotification < Notification
  def deliver; puts 'send email'; end
end

class SmsNotification < Notification
  def deliver; puts 'send sms'; end
end

class Notifier
  def initialize(factory)
    @factory = factory
  end

  def notify(type, payload)
    notification = @factory.create(type, payload)
    notification.deliver
  end
end

class NotificationFactory
  def create(type, payload)
    case type
    when :email then EmailNotification.new(payload)
    when :sms   then SmsNotification.new(payload)
    else raise 'unknown type'
    end
  end
end

# usage
factory = NotificationFactory.new
notifier = Notifier.new(factory)
notifier.notify(:email, {to: 'a@x.com'})

Variations

  • Use dependency injection to pass different factories for testing or runtime configuration.
  • Use registries or a hash map to avoid big case statements: registry[type].new.

Registry-based factory (extensible)

class NotificationFactory
  def initialize
    @registry = {}
  end

  def register(type, klass)
    @registry[type] = klass
  end

  def create(type, payload)
    klass = @registry[type] or raise 'unknown type'
    klass.new(payload)
  end
end

# register providers
factory = NotificationFactory.new
factory.register(:email, EmailNotification)
factory.register(:sms, SmsNotification)
