Example: replacing conditionals with polymorphism in Rails

Conditionals that switch behavior by type (payment method, user role, product type) are a common maintenance headache. Replace them with polymorphism (Strategy / subclasses / delegates) to follow the open/closed principle.

Problem — conditional-heavy code

def charge_payment(order)
  case order.payment_method
  when 'stripe'
    StripeGateway.charge(order)
  when 'paypal'
    PaypalGateway.charge(order)
  else
    raise 'unsupported'
  end
end

Polymorphic solution — Strategy pattern

module Payment
  class Base
    def charge(order); raise NotImplementedError; end
  end

  class Stripe < Base
    def charge(order)
      # stripe logic
    end
  end

  class Paypal < Base
    def charge(order)
      # paypal logic
    end
  end
end

# factory
class PaymentFactory
  def self.build(method)
    case method
    when 'stripe' then Payment::Stripe.new
    when 'paypal' then Payment::Paypal.new
    else raise 'unsupported'
    end
  end
end

# usage
gateway = PaymentFactory.build(order.payment_method)
gateway.charge(order)

Alternative: polymorphic association or subclassing

# single-table inheritance (STI) example
class Payment < ApplicationRecord; end
class StripePayment < Payment
  def charge; # stripe; end
end
class PaypalPayment < Payment
  def charge; # paypal; end
end

# usage
payment = order.payment
payment.charge

Benefits

  • No spread of type-checking logic—each implementation encapsulates its behavior.
  • Easy to add new implementations without touching existing code.
  • Improves testability — test each strategy in isolation.

Interview tip

Bring a concrete example from your work where you replaced a long conditional with a polymorphic design and explain how it simplified adding new cases and reduced bugs.
