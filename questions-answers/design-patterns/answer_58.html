Applying Domain-Driven Design (DDD) patterns in Rails

Rails is an opinionated framework optimized for CRUD, but you can apply DDD principles by organizing code around domain concepts: entities, value objects, aggregates, repositories, domain services and bounded contexts.

Key practices

  • Bounded contexts: group related code under namespaces (or engines) per domain.
  • Entities & Value Objects: implement as plain Ruby classes under app/domain.
  • Aggregates: choose aggregate roots (e.g., Order) and enforce invariants through domain services.
  • Repositories: encapsulate persistence behind interfaces and adapters.
  • Domain events: use events to communicate between bounded contexts asynchronously.

Project structure example

app/domain/orders/
  entities/
    order.rb
    line_item.rb
  services/
    place_order.rb
  repositories/
    order_repository.rb
  events/
    order_placed.rb

Example entity and domain service

module Orders
  class OrderEntity
    attr_reader :line_items, :customer_id

    def initialize(attrs)
      @customer_id = attrs[:customer_id]
      @line_items = attrs[:line_items] || []
    end

    def total_cents
      line_items.sum { |li| li.unit_price_cents * li.qty }
    end

    def valid?
      # domain invariants
    end
  end
end

class PlaceOrder
  def initialize(repo: Orders::Repository.new, payments: Payments::Gateway.new)
    @repo = repo; @payments = payments
  end

  def call(order_attrs)
    order = Orders::OrderEntity.new(order_attrs)
    raise unless order.valid?
    ActiveRecord::Base.transaction do
      persisted = @repo.save(order)
      @payments.charge(persisted)
      EventBus.publish('order.placed', order_id: persisted.id)
    end
  end
end

Governance & team structure

  • Organize teams around bounded contexts for faster autonomy.
  • Define contracts (events, APIs) between teams and version them.

Tools & gems

  • rails_event_store — event store and dispatcher.
  • dry-rb family (dry-struct, dry-validation) — for value objects and validations.

Interview tip

Explain how you gradually introduced DDD into an existing Rails app: start with one bounded context, extract domain objects and repositories, and add events to decouple downstream concerns.
