Using the Composite pattern in Rails (nested comments, menus)

Intent: treat individual objects and compositions (nodes with children) uniformly. Useful for tree-like structures: nested comments, menus, categories.

Modeling nested comments

class Comment < ApplicationRecord
  belongs_to :post
  belongs_to :parent, class_name: 'Comment', optional: true
  has_many :children, class_name: 'Comment', foreign_key: 'parent_id', dependent: :destroy

  # simple recursive render
  def render_tree(depth = 0)
    [('#' * depth) + body] + children.flat_map { |c| c.render_tree(depth + 1) }
  end
end

Optimizations

  • Use closure table or nested set (awesome_nested_set gem) for efficient subtree queries.
  • Use materialized path (store path strings) for simpler indexing and retrieval.
  • Cache rendered trees for read-heavy pages.

Menus & UI components

Menu items with children can be represented similarly and rendered recursively by presenters or helpers.

When to use composite

  • Tree-like data with uniform behavior (render, aggregate counts, permission checks).
  • When clients need to treat single items and groups interchangeably.

Interview tip

Be ready to discuss trade-offs between simple parent/child vs specialized tree models (nested sets, closure tables) and how you’d migrate when scale increases.
