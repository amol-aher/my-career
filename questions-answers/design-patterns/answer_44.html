Mediator pattern with an example in Rails

Intent: encapsulate interactions between multiple objects (colleagues) within a mediator to reduce coupling between them. In Rails, a mediator often manifests as a coordinator or orchestration service that knows how to talk to multiple subsystems.

Example scenario

When an order is completed, several subsystems must act: payment capture, inventory update, shipment creation, and notifications. A mediator coordinates these steps.

class OrderCompletionMediator
  def initialize(order, services: {})
    @order = order
    @payment_service = services[:payment] || PaymentGateway.new
    @inventory_service = services[:inventory] || InventoryAdapter.new
    @shipping_service = services[:shipping] || ShippingProvider.new
    @notifier = services[:notifier] || Notifier.new
  end

  def call
    ActiveRecord::Base.transaction do
      capture_payment
      reserve_inventory
      create_shipment
      @order.update!(status: 'completed')
    end
    notify_parties
  rescue => e
    handle_failure(e)
  end

  private

  def capture_payment
    @payment_service.capture(@order)
  end

  def reserve_inventory
    @inventory_service.reserve(@order.line_items)
  end

  def create_shipment
    @shipping_service.create_shipment(@order)
  end

  def notify_parties
    @notifier.order_completed(@order)
  end

  def handle_failure(e)
    # compensation logic, logging, alerts
    raise
  end
end

# usage
OrderCompletionMediator.new(order).call

Benefits

  • Reduces direct coupling between services.
  • Makes orchestration logic explicit and testable.
  • Mediator can implement retries, backoff, and compensation strategies.

When not to use

  • If interactions are trivial and can be expressed as simple service calls — mediator might add unnecessary indirection.
  • For extremely complex long-running flows, prefer a workflow engine (Temporal, Step Functions) rather than a monolithic mediator.

Interview tips

Describe how the mediator improved maintainability and how you refactored direct service-to-service calls into a mediator to centralize error handling and compensation logic.
