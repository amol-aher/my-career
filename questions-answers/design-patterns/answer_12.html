Tools and infrastructure components every robust system design should consider

This is a checklist of components you’ll commonly include in production systems (web apps, APIs, services). For each, I explain purpose and design considerations.

Networking & edge

  • DNS — domain resolution, failover (Route53), and global traffic policies.
  • CDN — CloudFront / Fastly for static assets, caching API responses where applicable, and TLS offload.
  • Load Balancers — L4/L7 (ELB/ALB/NGINX/Envoy) for distributing traffic and health checks.
  • WAF & DDoS protection — AWS WAF, Cloudflare, or vendor solutions to block malicious traffic.

Application layer

  • Web servers / App servers — Puma/Unicorn for Rails, Node for frontend microservices; autoscaled behind LBs.
  • API Gateway — centralize auth, routing, rate limiting, and metrics for public APIs.
  • Service mesh / sidecars — Envoy/Linkerd for internal service-to-service observability and security in microservices architectures.

Data & storage

  • Primary database — PostgreSQL / MySQL for transactional relational data; design for HA and backups.
  • NoSQL / wide-column stores — Cassandra / DynamoDB for high-write scaled workloads and denormalized query patterns.
  • Cache — Redis / Memcached for low-latency lookups, sessions, and counters.
  • Search / analytics — Elasticsearch / OpenSearch for text search and aggregations.
  • Object storage — S3 for media and large binary artifacts; lifecycle policies and signed URLs.
  • Message broker / streaming — Kafka, RabbitMQ, or SQS for decoupling, async tasks, and event-driven systems.

Background processing & orchestration

  • Worker queues — Sidekiq, Resque, Celery or serverless functions for heavy/async jobs.
  • Workflow / orchestrator — Temporal, Cadence, or Step Functions for long-running and stateful workflows.
  • Scheduler — Cron jobs, Kubernetes CronJob, or EventBridge for scheduled tasks.

Security & identity

  • Identity provider — OAuth2/OpenID Connect (Auth0, Cognito) for auth and SSO.
  • Secrets management — HashiCorp Vault, AWS Secrets Manager for DB credentials and API keys.
  • Encryption — TLS in transit and KMS-managed encryption at rest.

Observability & operations

  • Monitoring — Prometheus, CloudWatch metrics and dashboards (Grafana).
  • Logging — Central logs (ELK/Fluentd/CloudWatch Logs) and structured formats.
  • Tracing — OpenTelemetry, Jaeger for distributed traces and latency analysis.
  • Alerts & Incident management — PagerDuty, Opsgenie for on-call and escalation.

Developer tooling & delivery

  • CI/CD — GitHub Actions, GitLab CI, or Jenkins for builds, tests, deployments.
  • Infrastructure as Code — Terraform, CloudFormation for reproducible infra.
  • Feature flags and experimentation — LaunchDarkly or open-source tools for controlled rollouts.

Cross-cutting design patterns

  • Health checks / readiness & liveness endpoints for orchestrators.
  • Circuit breakers and bulkheads to avoid cascading failures.
  • Rate limiting and backpressure at the API gateway to protect downstream services.
  • Immutable infrastructure and blue/green or canary deployments.

Interview subquestions & short answers

  • Q: Where do you put caching? Cache at multiple layers: CDN for static assets, edge for public API responses, Redis for per-user or computed views, and application-level fragment caching in Rails.
  • Q: How to scale databases? Read replicas, partitioning/sharding, or migrating read-heavy data to specialized data stores; use connection pooling and optimize queries.
  • Q: How to secure APIs? Use API gateway + mTLS for internal services, OAuth2/JWT for clients, WAF, rate limiting, and input validation.
