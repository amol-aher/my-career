Query Object pattern — encapsulating complex queries

Purpose: move complex database query logic out of models and controllers into a focused object that returns an ActiveRecord::Relation or result set. Improves testability and readability.

Benefits

  • Single place for query tuning, indexing decisions and ARel complexity.
  • Reusable across controllers and services.
  • Encourages composition (chain queries).

Example — Posts::SearchQuery

module Posts
  class SearchQuery
    def initialize(relation = Post.all)
      @relation = relation
      @filters = {}
    end

    def by_user(user_id)
      @filters[:user_id] = user_id
      self
    end

    def with_terms(terms)
      @filters[:terms] = terms
      self
    end

    def call
      rel = @relation
      rel = rel.where(user_id: @filters[:user_id]) if @filters[:user_id]
      if @filters[:terms]
        rel = rel.where("to_tsvector('english', content) @@ plainto_tsquery(?)", @filters[:terms])
      end
      rel.order(created_at: :desc)
    end
  end
end

# usage
posts = Posts::SearchQuery.new.call.by_user(1).with_terms('rails').call

Testing & organization

  • Unit-test the query object with seeded records and assert SQL structure or results.
  • Place query objects under app/queries or app/queries/posts.

Interview tip

Explain how query objects help you move complex SQL out of models and reduce duplication, and mention using database explain plans to optimize the queries encapsulated by the object.
