Load balancing techniques — types and when to use them

Summary: Load balancing distributes network or application traffic across multiple servers to improve reliability and performance. Techniques vary by layer (L4 vs L7), algorithm, and capability (stateful vs stateless). Choose based on session needs, routing complexity, and observability requirements.

Layer types

  • L4 (Transport layer) — route based on IP/port (fast, low overhead), e.g., AWS ELB Classic, Nginx stream, IPVS.
  • L7 (Application layer) — route based on HTTP attributes (headers, paths, cookies), supports advanced features like A/B testing, JWT-based routing, and request rewriting (e.g., Nginx, Envoy, Kong).

Common algorithms

  • Round Robin — cycle through servers evenly. Good for equal capacity servers and stateless workloads.
  • Least Connections — send to the server with the fewest active connections. Helps with uneven request durations.
  • IP Hash / Source Hash — sticky routing by client IP. Useful for session affinity without cookies, but affected by proxying and NAT.
  • Weighted Round Robin / Weighted Least Connections — account for server capacity differences.
  • Random — low overhead; sometimes combined with weights.
  • Consistent Hashing — used for caching layers to reduce key remapping when nodes change (e.g., memcached ring).

Advanced techniques

  • Health checks — active/passive checks to remove unhealthy nodes.
  • Connection draining — allow in-flight requests to complete during node removal.
  • Global load balancing — DNS-based or geo-routing (Route53 latency-based, geo proximity). Combine with Anycast for global edge services.
  • Canary / traffic shifting — gradually route fraction of traffic to new deployments (weighted routing).
  • Proxy-based client-side load balancing — service mesh sidecars (Envoy) or client SDKs (Ribbon) where client decides endpoint based on discovery.

Stateful vs stateless balancing

For stateful applications (sticky sessions), use cookie-based affinity or session stores. For stateless apps, prefer round robin or least connections. Externalize session state to Redis if possible to maintain statelessness.

When to use which

  • Simple web apps: L4 or L7 round robin.
  • Long-lived connections (websockets): least-connections or sticky sessions with connection draining.
  • Caching clusters: consistent hashing to minimize redistribution on node changes.
  • Microservices: use service discovery + client-side or L7 proxy with health checks for fine-grained control.

Interview follow-ups

  • How to handle sudden traffic spikes? Autoscale, use rate limiting, queue work, and employ CDN for static content.
  • How to debug routing problems? Trace requests across LB, enable access logs, and correlate with health checks and metrics.
  • How to ensure consistency for sticky sessions? Prefer external session store in Redis instead of affinity where possible.
