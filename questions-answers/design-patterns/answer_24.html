Implementing the Decorator pattern in Ruby (plain Ruby)

Intent: add responsibilities to objects dynamically without changing their class. Good for presentation concerns, logging, or adding cross-cutting behavior.

Example: Decorating a simple Product presenter

class Product
  attr_reader :name, :price
  def initialize(name, price)
    @name = name; @price = price
  end
end

# base presenter
class ProductPresenter
  def initialize(product)
    @product = product
  end

  def title
    @product.name
  end

  def price
    "$#{'%.2f' % (@product.price / 100.0)}"
  end
end

# decorator that adds discount label
class DiscountDecorator
  def initialize(presenter, discount_percent)
    @presenter = presenter
    @discount_percent = discount_percent
  end

  def title
    @presenter.title
  end

  def price
    original = @presenter.price
    # return both original and discounted price
    discounted = (@presenter.instance_variable_get(:@product).price * (100 - @discount_percent) / 100.0).floor
    "$#{'%.2f' % (discounted / 100.0)} (#{@discount_percent}% off)"
  end
end

# usage
product = Product.new('Widget', 1999)
base = ProductPresenter.new(product)
deco = DiscountDecorator.new(base, 20)
puts deco.title
puts deco.price

Notes

  • Decorators delegate to the wrapped object; keep the interface consistent.
  • Use Forwardable or SimpleDelegator from stdlib for convenience:
require 'delegate'
class LoggingDecorator < SimpleDelegator
  def perform(*args)
    puts "calling perform"
    __getobj__.perform(*args)
  end
end

When to prefer Decorators

  • Presentation layer concerns (formatting) that shouldn't live in the domain model.
  • When you need to compose behaviors at runtime (e.g., add caching or logging around objects).

Trade-offs

  • Many wrapping layers can make debugging harder — keep decorators small and focused.
  • Consider using composition over inheritance; avoid modifying original class behavior in surprising ways.

Interview tip

Show the SimpleDelegator example as a concise idiomatic Ruby solution and explain when to prefer decorators over presenters or helpers.
