When and how to use the Command pattern in Ruby

Intent: encapsulate a request as an object, thereby letting you parameterize clients with different requests, queue or log requests, and support undoable operations.

Use cases

  • Background job systems where you want to enqueue rich commands.
  • Undo/redo stacks in UIs.
  • Transaction scripts where you want to compose operations and run them later.
  • Implementing CLI command handlers in a uniform way.

Example — command objects for order processing

class CreateInvoiceCommand
  def initialize(order_id)
    @order_id = order_id
  end

  def call
    order = Order.find(@order_id)
    Invoice.create_from(order)
  end
end

class SendInvoiceEmailCommand
  def initialize(invoice_id)
    @invoice_id = invoice_id
  end

  def call
    invoice = Invoice.find(@invoice_id)
    InvoiceMailer.send(invoice).deliver_now
  end
end

# Enqueueing commands
class CommandWorker
  include Sidekiq::Worker
  def perform(class_name, *args)
    klass = Object.const_get(class_name)
    klass.new(*args).call
  end
end

# usage
CommandWorker.perform_async('CreateInvoiceCommand', order.id)

Benefits

  • Commands encapsulate both data and behavior — easy to serialize if arguments are simple.
  • Commands make replay, logging, and testing straightforward.
  • Composing commands (execute one after another) supports complex orchestrations.

Considerations

  • Avoid very large command objects — keep them focused (SRP).
  • For complex workflows, consider a workflow engine rather than ad-hoc chaining.
  • When serializing commands for queues, prefer arguments that are IDs or primitives, not entire AR objects.

Interview tip

Explain how you use commands with Sidekiq/Resque to build robust background job pipelines and how you would implement undo or logging if required.
