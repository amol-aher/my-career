Handling multi-step form workflows in Rails

Multi-step forms (wizards) require orchestration of state, validation and persistence. Options range from lightweight Form Objects + session storage to robust state-machine based flows with resumability.

Approaches

  1. Form Object + Session — keep partial data in session until final submit; simple and fast for short-lived flows.
  2. Persisted Wizard (Form Object + DB) — persist progress to DB so users can resume later; use a wizard_state column.
  3. State machine + Step definitions — use AASM to represent steps and transitions, helpful when rules are complex.
  4. Use a gem (Wicked) — provides routing & step management; still preferable to keep validation/persistence in your form objects/services.

Example: FormObject-based wizard (persisted)

class SignupWizard
  include ActiveModel::Model
  attr_accessor :step, :email, :name, :address

  def initialize(user:, params: {})
    @user = user
    super(params)
  end

  def save
    case step
    when 'personal'
      validate_personal && persist_personal
    when 'address'
      validate_address && persist_address
    end
  end

  def persist_personal
    @user.update!(email: email, name: name)
  end

  def persist_address
    @user.create_address!(address: address)
  end
end

# controller
def update
  wizard = SignupWizard.new(user: current_user, params: wizard_params)
  if wizard.save
    redirect_to next_step
  else
    render :show
  end
end

Resumability and persistence

  • Persist intermediate state to a wizard_sessions table or store in Redis with TTL for resume capability.
  • Store only minimal necessary data and reference IDs to avoid serialization issues.

Validation strategy

  • Validate per-step attributes to show immediate feedback.
  • Run full validation before final commit if necessary.

When to use state machines

When transitions have guards, side-effects, or complex branching (e.g., payment required only on certain conditions). Example: AASM for wizard_state column with states like personal, address, confirm.

UX considerations

  • Provide previews of completed steps and allow backward navigation.
  • Show progress indicators and save checkpoints.
  • Protect endpoints and resume tokens from tampering (use signed IDs).

Interview tips

Explain trade-offs: session storage is simpler but not resumable across devices; DB persistence is durable but requires migration strategies. Be ready to show code that migrates partial state to final models.
