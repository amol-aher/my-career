Applying the Proxy pattern in a Rails application

Intent: provide a surrogate or placeholder for another object to control access, add lazy loading, caching, logging, or access control.

Use cases in Rails

  • Lazy-loading heavy resources (e.g., large JSON from external APIs)
  • Caching proxy for expensive service calls
  • Access control layer that validates permissions before delegating

Simple caching proxy example

class ProductApiClient
  def fetch(id)
    # HTTP call to external API
  end
end

class ProductApiProxy
  def initialize(client = ProductApiClient.new)
    @client = client
  end

  def fetch(id)
    Rails.cache.fetch([:product_api, id], expires_in: 5.minutes) do
      @client.fetch(id)
    end
  end
end

# usage
proxy = ProductApiProxy.new
product_data = proxy.fetch(123)

Lazy loading proxy with SimpleDelegator

require 'delegate'
class LazyExternalResource < SimpleDelegator
  def initialize(id, client = ExternalClient.new)
    @id = id
    @client = client
    super(nil)
  end

  def __getobj__
    @real_obj ||= @client.fetch(@id)
  end
end

Considerations

  • Proxy adds a layer — keep it thin and predictable.
  • Ensure errors in underlying service bubble appropriately or are translated to domain errors.
  • Document that a proxy is used to avoid surprise behavior in tests.
