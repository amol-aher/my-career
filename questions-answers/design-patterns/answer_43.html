Background jobs (Sidekiq/ActiveJob) and the Command pattern

Background jobs are a natural fit for the Command pattern: a job encapsulates an action (command) and its parameters; it can be enqueued, serialized, retried, logged, and executed asynchronously.

Example — Command object enqueued as a job

# app/commands/create_invoice_command.rb
class CreateInvoiceCommand
  def initialize(order_id)
    @order_id = order_id
  end

  def call
    order = Order.find(@order_id)
    InvoiceGenerator.generate(order)
  end
end

# Sidekiq worker (invokes command)
class CommandWorker
  include Sidekiq::Worker

  def perform(command_klass, *args)
    klass = Object.const_get(command_klass)
    klass.new(*args).call
  end
end

# enqueue
CommandWorker.perform_async('CreateInvoiceCommand', order.id)

How ActiveJob fits

ActiveJob provides a framework to write jobs that can target multiple backends (Sidekiq, Resque, DelayedJob). Jobs act as command wrappers around business logic.

class CreateInvoiceJob < ApplicationJob
  queue_as :default

  def perform(order_id)
    CreateInvoiceCommand.new(order_id).call
  end
end

# enqueue
CreateInvoiceJob.perform_later(order.id)

Benefits

  • Encapsulation: commands hold everything needed to run an action.
  • Observability: enqueue, retries and failures are tracked by job system.
  • Testability: test command logic without the worker infrastructure; test worker wiring separately.

Considerations

  • Serialize simple args only (IDs, primitives) — avoid serializing AR objects.
  • Ensure commands are idempotent or handle duplicates (job retries).
  • Version commands carefully if you deploy code changes while jobs are queued (use job versioning or migration strategies).

Interview talking points

  • Describe how you implemented audit/logging for commands and job retries in production.
  • Explain trade-offs of pushing orchestration into jobs vs using a workflow engine for long-running processes.

In interviews, present a concrete example showing how commands were enqueued, retried, and monitored, and how you handled idempotency and job failures.
