Form Object pattern and improving complex forms

Problem: multi-model forms (signup + profile + preferences), complex validation flows, or transient data that doesn't map to a single ActiveRecord model.

Form Object — what it is

A Form Object is a PORO that includes ActiveModel::Model to get validations, conversions and form-style behaviors while orchestrating multiple models or transient attributes.

Example: Signup form that creates User + Profile

class SignupForm
  include ActiveModel::Model

  attr_accessor :email, :password, :first_name, :last_name, :newsletter

  validates :email, :password, presence: true
  validates :email, format: { with: URI::MailTo::EMAIL_REGEXP }

  def save
    return false unless valid?

    ActiveRecord::Base.transaction do
      user = User.create!(email: email, password: password)
      Profile.create!(user: user, first_name: first_name, last_name: last_name)
      NewsletterSubscription.create!(user: user) if newsletter == '1'
    end
    true
  rescue ActiveRecord::RecordInvalid => e
    errors.add(:base, e.message)
    false
  end
end

# controller
def create
  form = SignupForm.new(signup_params)
  if form.save
    redirect_to success_path
  else
    render :new
  end
end

Benefits

  • Keeps models small and focused; controllers become thin—delegate orchestration to the form object.
  • Easier to test validations and save flows isolated from controllers.
  • Supports complex validations that span multiple models.

Alternatives

  • Reform gem — powerful form objects with coercions, composition and nested forms.
  • Nested attributes — Rails built-in but can become complex and less explicit.

Interview tips

Show the simple example, explain why nested attributes are sometimes insufficient, and mention how you test forms and handle error propagation to views.
