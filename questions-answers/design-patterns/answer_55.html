Using Decorator / Presenter pattern to clean up Rails views

Views often accumulate formatting, conditional logic and small composition tasks. Decorators/Presenters move presentation logic out of models and views, making templates simple and testable.

Options

  • Draper gem — widely used, provides helpers & integration with Rails.
  • SimpleDelegator — lightweight, no external dependency.
  • ViewComponent / Cells — component-based approach where presentation logic lives in components.

Example using Draper

class ProductDecorator < Draper::Decorator
  delegate_all

  def display_price
    h.number_to_currency(object.price_cents / 100.0)
  end

  def availability_label
    object.in_stock? ? 'In stock' : 'Out of stock'
  end
end

# controller
@product = Product.find(params[:id]).decorate

# view (erb)
<%= @product.display_price %>
<%= @product.availability_label %>

SimpleDelegator example (no gem)

require 'delegate'
class ProductPresenter < SimpleDelegator
  include ActionView::Helpers::NumberHelper

  def initialize(product)
    super(product)
  end

  def display_price
    number_to_currency(__getobj__.price_cents / 100.0)
  end
end

# usage in controller
@presenter = ProductPresenter.new(Product.find(...))

Benefits

  • Cleaner templates with one-liners.
  • Presentation logic isolated and unit-testable.
  • Encourages SRP by keeping models domain-focused.

Performance & caching

  • Decorators should avoid expensive DB calls; delegate to preloaded associations when possible.
  • Cache rendered fragments keyed by presenter state for heavy pages.

Interview tip

Show a before/after snippet of a messy partial moved into a decorator and mention how tests became simpler. If asked about alternatives, mention ViewComponent for more complex UI logic.
