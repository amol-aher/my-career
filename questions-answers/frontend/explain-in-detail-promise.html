Explain in detail Promise?

Summary:
A Promise represents the eventual result (fulfillment or rejection) of an asynchronous operation. It provides a composable abstraction for async control flow, avoiding deeply nested callbacks (callback hell) and enabling techniques like chaining and concurrency with Promise utilities.

Deep dive — states and methods:
- States: `pending` -> `fulfilled` or `rejected`. Once settled, state is immutable.
- API: `new Promise((resolve, reject) => { /* async work */ })`.
- Methods: `.then(onFulfilled, onRejected)`, `.catch(onRejected)`, `.finally(fn)`.
- Static helpers: `Promise.all`, `Promise.race`, `Promise.allSettled`, `Promise.any` — each has distinct semantics for combining multiple promises.
- Error handling: Unhandled Promise rejections should be caught; in Node they can crash processes depending on settings. Use `.catch` or `try/catch` with `async/await`.

Promise chaining and composition:
- Returning a value in `then` passes the value down the chain.
- Returning a Promise in `then` waits for it to settle before continuing.
- Use `async/await` syntax to make async flows read like synchronous code, but handle errors with try/catch.

Common pitfalls and patterns:
- Ignoring returned Promises (not returning inside .then) leads to unexpected behavior.
- Race conditions with `Promise.race` — the first settled promise (fulfill or reject) wins.
- Use timeouts/AbortController to avoid hanging Promises for network calls.

Examples:
```js
// Creating a promise
function fetchJson(url) {
return fetch(url).then(res => {
if (!res.ok) throw new Error(res.statusText);
return res.json();
});
}

// Using async/await
async function getData() {
try {
const data = await fetchJson('/api/data');
return data;
} catch (err) {
console.error(err);
}
}

// Promise.all usage
const [a,b] = await Promise.all([fetchJson('/a'), fetchJson('/b')]);
```

Interviewer follow-ups:
- Q: When to use Promise.all vs Promise.allSettled?
A: Use `all` when all must succeed; use `allSettled` when you want results regardless of individual failures.
- Q: How to avoid unhandled promise rejections?
A: Always return promises, chain `.catch`, or use process-level handlers for logging and safe shutdown in Node apps.
