Explain in detail event.preventDefault vs event.stopPropagation?

Summary:
- `event.preventDefault()` cancels the browser's default action for an event (e.g., following a link, form submission).
- `event.stopPropagation()` prevents the event from propagating (bubbling or capturing) to ancestor elements' event listeners.

Deep dive:
- Event phases: capture (top-down), target, bubble (bottom-up). Listeners can be registered for capture or bubble phase.
- preventDefault affects only the default browser behavior. It does not stop other listeners from running.
- stopPropagation stops the event from reaching other listeners in the propagation chain. `stopImmediatePropagation` stops other listeners on the same element too.

Common use cases & examples:
- Prevent form submit to validate via JavaScript:
```js
form.addEventListener('submit', (e) => {
e.preventDefault();
// perform validation and AJAX submit
});
```
- Stop a click from closing a modal when using event delegation:
```js
modalContent.addEventListener('click', (e) => {
e.stopPropagation();
});
document.body.addEventListener('click', () => closeModal());
```

Best practices:
- Prefer specific selectors and delegation patterns; avoid overusing stopPropagation because it can interfere with other components.
- Use preventDefault for UX control; document places where default behavior is suppressed to avoid surprises.

Interviewer follow-ups:
- Q: What is event delegation and how does it interact with stopPropagation?
A: Event delegation attaches a listener to a parent and checks `event.target` — stopPropagation can prevent delegated handlers from receiving events, so use it sparingly.
- Q: What's the difference between stopPropagation and stopImmediatePropagation?
A: stopImmediatePropagation stops other listeners on the same element in addition to bubbling up; stopPropagation only prevents bubbling to ancestors.
