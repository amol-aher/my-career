Explain in detail arrow function in JavaScript??

Summary:
Arrow functions (introduced in ES6) are a shorthand syntax for function expressions using the => token. They provide lexical binding of `this` (they don't create their own `this`), do not have a prototype, cannot be used as constructors, and do not have their own `arguments` object.

Deep dive and behavior:
- Syntax forms:
- Concise: `(a, b) => a + b` (implicit return)
- Block body: `(a, b) => { return a + b; }`
- Single parameter: `x => x * 2` (no parentheses necessary)
- Lexical `this`:
- Arrow functions capture `this` from the surrounding scope (closure), making them ideal for callbacks where you want to preserve the outer `this` without `bind`.
- No `arguments` object:
- Use rest parameters (`...args`) if you need argument list behavior.
- Not constructible:
- `new (() => {})` throws — arrow functions have no `[[Construct]]` internal method nor `prototype` property.
- No `super` binding and no `new.target`.

Common pitfalls:
- Arrow as object methods: avoid defining prototypes or methods that require their own `this` using arrow functions — they will inherit the outer `this` unexpectedly.
- Readability: overusing concise arrow functions for complex logic reduces readability; prefer named functions for stack traces.

Examples:
- Preserving `this` in callbacks:
```js
class Counter {
constructor() { this.count = 0; }
start() {
setInterval(() => { this.count++; console.log(this.count); }, 1000);
}
}
```
- Using rest parameters instead of `arguments`:
```js
const sum = (...nums) => nums.reduce((a,b) => a+b, 0);
```

Interviewer follow-ups:
- Q: When should you not use arrow functions?
A: When a function needs to be used as a constructor, or when you need its own `this` context (e.g., object prototype methods, event handlers that rely on `this` set by the platform).
- Q: Do arrow functions affect performance?
A: Not significantly in most apps. Choose for clarity and correct `this` binding; optimize hotspots via profiling if needed.
