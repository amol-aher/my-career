Explain in detail box-sizing in CSS?

Summary:
`box-sizing` determines how the browser calculates an element's total width and height. With `content-box` (default), width/height apply to the content box and padding/border are added outside. With `border-box`, width/height include padding and border, making layout more predictable.

Deep dive:
- content-box (default): element's `width` sets the content area; total rendered width = width + padding + border + margin.
- border-box: element's `width` includes padding and border; total width = specified width + margin.
- Why switch to border-box: simplifies responsive layouts and prevents unexpected overflow when adding padding/border. It’s common to apply globally:
```css
*, *::before, *::after { box-sizing: border-box; }
```

Practical considerations:
- Third-party components: some libraries assume content-box — verify visually after global change.
- Calculations: with border-box you avoid the need to subtract padding/border from width calculations in CSS/JS.
- Legacy IE quirks: ancient IE versions used a different box model, but modern browsers are consistent.

Examples:
```html
<style>
.box { width: 200px; padding: 20px; border: 5px solid #000; }
/* With content-box total width = 200 + 40 + 10 = 250px */
/* With border-box total width = 200px (padding and border included) */
</style>
<div class="box">Hello</div>
```

Interviewer follow-ups:
- Q: When might you prefer content-box?
A: When you deliberately want padding outside the specified width or when integrating a library that expects content-box.
- Q: Does border-box affect height calculations?
A: Yes — padding and border are included in the specified height with border-box too.
