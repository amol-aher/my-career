Explain in detail fetch?

Summary:
`fetch()` is a modern browser API to make network requests. It returns a Promise resolving to a `Response` object. It improves on older `XMLHttpRequest` by being Promise-based, supporting streaming, and integrating cleanly with async/await.

Deep dive — behavior and features:
- `fetch(url, options)` returns a Promise even for HTTP errors (4xx/5xx); check `response.ok` (boolean) or `response.status`.
- The `Response` has methods: `response.json()`, `response.text()`, `response.blob()`, `response.arrayBuffer()`, and `response.body` (ReadableStream) for streaming.
- Options allow `method`, `headers`, `body`, `mode` (cors/no-cors), `credentials` (omit, same-origin, include), `cache`, `redirect`, and `signal` (AbortController).
- CORS and credentials: by default, `fetch` does not send credentials; set `credentials: 'include'` to send cookies cross-origin (and the server must allow it).

Advanced topics:
- AbortController: cancel an in-flight fetch to save resources.
- Streaming responses: process large responses incrementally using `ReadableStream` (useful for large NDJSON responses or progressive rendering).
- Service workers: intercept `fetch` events for offline capability, caching and request manipulation.

Examples:
```js
// Basic
const res = await fetch('/api/users');
if (!res.ok) throw new Error(res.statusText);
const users = await res.json();

// Abort example
const ctrl = new AbortController();
fetch('/api/long', { signal: ctrl.signal }).catch(err => {
if (err.name === 'AbortError') console.log('fetch aborted');
});
ctrl.abort();
```

Interviewer follow-ups:
- Q: Does fetch reject on HTTP 404/500?
A: No — it resolves. Check `response.ok` to detect HTTP-level errors.
- Q: How to stream a JSON array?
A: Convert server output to NDJSON or stream by chunks and parse incrementally; streaming a standard JSON array is harder because it requires parsing partial JSON.
