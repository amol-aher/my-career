What is the difference between fetch and Ajax? Why are we using fetch instead of Ajax?

Summary:
'Ajax' historically refers to asynchronous requests using `XMLHttpRequest` (XHR). `fetch` is the modern, Promise-based API that replaces many use-cases of XHR with a cleaner interface, streaming capabilities, and better composability with modern JavaScript.

Detailed comparison:
- API surface: XHR is callback/event-driven; fetch uses Promises and async/await for clearer control flow.
- Streaming: fetch supports ReadableStreams for progressive processing; XHR has limited streaming options (progress events but not a true stream API).
- CORS and credentials: both support CORS, but fetch requires explicit `credentials` setting to send cookies; XHR previously had different defaults and more verbosity.
- Response handling: fetch resolves the Promise for any HTTP response; XHR provides status codes via callbacks. fetch offers a unified `Response` object with convenience methods.
- Abort/Cancel: fetch uses AbortController; XHR uses `xhr.abort()` but without Promise semantics.

Why use fetch today:
- Cleaner syntax with Promises / async-await.
- Better composability (Promise utilities, chaining, concurrency patterns).
- Streaming support and integration with Service Workers for offline/caching features.
- Simpler API surface reduces bugs and improves readability.

Caveats:
- Older browsers may need polyfills for fetch and AbortController.
- fetch does not automatically reject HTTP errors, so you must check `response.ok`.

Interviewer follow-ups:
- Q: How do you handle request timeouts with fetch?
A: Use AbortController to implement a timeout wrapper that aborts the fetch after a set time.
- Q: Do you still use XHR sometimes?
A: Rarely in modern apps; only for legacy support or very specific browser APIs not supported by fetch.
