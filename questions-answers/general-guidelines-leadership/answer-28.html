Test-Driven Development (TDD) — Thoughts & Practice

Philosophy

I practice TDD in scenarios where correctness is critical (core business logic, financial transactions, APIs). TDD improves design clarity and reduces regressions, but I apply it pragmatically — not dogmatically.

Benefits

  • Clearer requirements: writing tests forces clarity.
  • Confidence in refactoring: tests safeguard behavior.
  • Smaller, decoupled design: encourages modular code.

Challenges

  • Slower initial velocity.
  • UI-heavy flows can be harder to test-first.

Example

# Example: TDD for order discount logic (Rails RSpec)
describe OrderCalculator do
  it "applies discount for premium users" do
    user = create(:user, premium: true)
    order = create(:order, user: user, amount: 100)
    calc = OrderCalculator.new(order)
    expect(calc.total).to eq(90) # 10% discount
  end
end
