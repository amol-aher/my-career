Architectural Patterns — Most Useful and Why

Strangler Pattern

Useful for incremental migration of legacy systems — replace parts of a monolith gradually with services.

Event-Driven Architecture

Great for decoupling systems, improving scalability, and enabling eventual consistency where appropriate. Use cases: analytics pipelines, integrations, async processing.

Hexagonal (Ports & Adapters)

Encourages separation between business logic and external systems (DB, APIs), making components testable and replaceable.

CQRS (Command Query Responsibility Segregation)

Useful for read-heavy systems needing different models/optimizations for read and write workloads.

Microservices with Bounded Contexts

Enables team autonomy and independent scaling when boundaries are well-defined; avoid premature decomposition.

When to use which

  • Start with modular monolith if team is small.
  • Use event-driven or microservices when scale or organizational structure demands it.
  • Prefer hexagonal architecture to keep core logic independent from infra.
