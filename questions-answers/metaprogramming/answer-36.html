Enforcing immutability via metaprogramming

You can enforce immutability in Ruby using a combination of metaprogramming techniques: remove/override mutator methods, freeze objects, and validate attempted mutations. Below are safe approaches and examples.

1. Shallow freeze on construction

class FrozenStruct
  def initialize(hash)
    hash.each { |k,v| instance_variable_set("@\#{k}", v.freeze) }
    freeze
  end
end

This prevents replacing instance variables and freezes immediate values, but nested mutable objects might still be mutable unless frozen recursively.

2. Deep freeze utility

def deep_freeze(obj, seen = {})
  return obj if seen[obj.object_id]
  seen[obj.object_id] = true
  if obj.respond_to?(:each_pair)
    obj.each_pair { |k,v| deep_freeze(v, seen) }
  elsif obj.respond_to?(:each)
    obj.each { |v| deep_freeze(v, seen) }
  end
  obj.freeze
end

3. Macro to remove mutators and define readers

module Immutable
  def immutable_attr(*names)
    names.each do |n|
      attr_reader n
      remove_method "#{n}=" if method_defined?("#{n}=") rescue nil
    end
  end
end

class Person
  extend Immutable
  immutable_attr :name, :age

  def initialize(name, age)
    @name = name.freeze
    @age = age
    freeze
  end
end

4. Override mutating methods to raise

module PreventMutations
  def initialize(*); super; freeze end

  def []=(k, v) raise TypeError, "frozen" end
  def <<(v) raise TypeError, "frozen" end
end

class ImmutableArray < Array
  include PreventMutations
end

5. Runtime enforcement via method hooks

Intercept attempts to define writers on an immutable class and prevent them:

module ImmutableEnforcer
  def method_added(name)
    if name.to_s.end_with?('=') && @immutable
      remove_method(name) # block the writer
      raise "Cannot add mutator to immutable class"
    end
    super
  end

  def make_immutable!
    @immutable = true
    freeze
  end
end

Notes & trade-offs

  • Shallow vs deep: Deep freezing may be expensive; decide based on your data shapes.
  • Compatibility: Some libraries mutate objects; immutable objects may not work with them unless you adapt.
  • Performance: Freezing is cheap; deep freeze and guards add cost.

Summary

Combine frozen construction, removal/override of mutators, and defensive programming (raise on modifications) to enforce immutability. Provide clear API and tests so other team members understand the constraints.
