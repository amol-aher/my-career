How Proxies and Reflect support metaprogramming in JavaScript

Summary: Proxy provides traps to intercept fundamental operations (property access, assignment, function calls, construction, enumeration, etc.). Reflect provides default operation implementations and is used within traps to delegate to the original behavior safely. Together they form a powerful, standard metaprogramming surface for building virtualized objects, validation layers, DSLs, mocking & testing helpers, and more.

Key Proxy traps

Common traps you will use:

  • get(target, prop, receiver) — intercept property reads.
  • set(target, prop, value, receiver) — intercept writes.
  • apply(target, thisArg, args) — intercept function calls (when target is a function).
  • construct(target, args, newTarget) — intercept new invocations.
  • has(target, prop) — for the in operator.
  • ownKeys(target) — intercept Object.keys, Reflect.ownKeys, and enumeration.
  • getOwnPropertyDescriptor, defineProperty, deleteProperty, preventExtensions, getPrototypeOf, etc.

Role of Reflect

Reflect exposes the same low-level operations as the proxy traps, but as functions (e.g., Reflect.get, Reflect.set, Reflect.apply). Use Reflect inside traps when you want to defer to the default behavior or implement consistent semantics across traps. It makes it easy and safe to forward operations.

Examples

1) Logging reads and writes

const target = { a: 1 };

const logger = new Proxy(target, {
  get(t, prop, receiver) {
    console.log("get", prop);
    return Reflect.get(t, prop, receiver);
  },
  set(t, prop, value, receiver) {
    console.log("set", prop, "=", value);
    return Reflect.set(t, prop, value, receiver);
  }
});

logger.a;      // logs: get a
logger.b = 2;  // logs: set b = 2

2) Validation layer

function createValidatedObject(schema) {
  return new Proxy({}, {
    set(target, prop, value) {
      if (schema[prop] && !schema[prop](value)) {
        throw new TypeError(`Invalid value for ${prop}`);
      }
      return Reflect.set(target, prop, value);
    }
  });
}

const user = createValidatedObject({ age: v => Number.isInteger(v) && v >= 0 });
user.age = 30;    // ok
// user.age = "x"; // throws TypeError

3) Virtual properties / computed fields

const person = new Proxy({}, {
  get(target, prop) {
    if (prop === 'fullName') {
      return `${target.first || ''} ${target.last || ''}`.trim();
    }
    return Reflect.get(target, prop);
  }
});

person.first = "Ada";
person.last = "Lovelace";
console.log(person.fullName); // "Ada Lovelace"

4) Revocable proxy

const { proxy, revoke } = Proxy.revocable({}, {});
proxy.x = 10;
console.log(proxy.x); // 10
revoke();
// proxy.x; // throws TypeError after revoke()

Why use Reflect?

  • Ensures consistent internal behavior and return codes required by the proxy invariants.
  • Makes it easy to call the default operation without duplicating logic.
  • Helps avoid subtle bugs in trap implementations (e.g., forgetting to return the boolean expected by set).

When to use proxies (metaprogramming scenarios)

  • Creating virtualization layers (remote objects, RPC proxies).
  • Backward-compatible shims and deprecation warnings.
  • Mocking and spying in tests.
  • DSLs that want to treat property names as commands (e.g., chained query builders).
  • Validation, security checks, access control.

Pitfalls & performance

  • Proxies add overhead — avoid them in hot loops or micro-optimized paths.
  • Some engine optimizations (inline caching) are inhibited by proxies.
  • Debugging can be harder — stack traces may skip intermediate proxies logic.
  • Carefully implement traps and forward to Reflect where appropriate to maintain invariants.

Subquestions you might be asked (and short answers)

Q: Can proxies intercept private fields (e.g., #private)?

A: No — proxies operate at the public property/slot level and cannot observe or intercept true language-private fields declared with #.

Q: Are proxies transparent to instanceof?

Proxies with an object target preserve instanceof behavior. If the target is a function and you use the construct trap, you must be careful to preserve prototype invariants.

Q: How do proxies interact with Reflect.ownKeys and enumeration?

Implement ownKeys and getOwnPropertyDescriptor consistently. The runtime enforces invariants such as returning non-configurable properties found on the target.

Conclusion

Proxies + Reflect form a modern, standardized metaprogramming toolset in JavaScript. Use them to implement clean abstraction layers, but be mindful of performance and invariants. Prefer Reflect for default behavior delegation and always think about the contract each trap must satisfy.
