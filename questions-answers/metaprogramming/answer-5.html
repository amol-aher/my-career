What is metaprogramming, and how it differs from reflection, code generation, and dynamic typing?

Metaprogramming: writing programs that write or manipulate other programs (or themselves) — usually at runtime, sometimes at compile-time. In practice it includes creating methods, classes, or behaviors dynamically, intercepting calls, generating code, or altering program structure.

Short definitions & differences

TermDefinitionTypical mechanisms
MetaprogrammingProgrammatic modification or generation of program structure/behavior (methods, classes) at runtime or compile-time.define_method, method_missing, macros, templates, code-gen, AST transforms
ReflectionIntrospection: examining program structure at runtime (what methods exist, types, fields).Object#methods, introspection APIs, type metadata
Code generationProducing source code or bytecode as output, typically before runtime or at build time.Template engines, compilers, annotation processors
Dynamic typingA language property: types checked at runtime. Easier to write metaprogramming, but distinct concept.duck typing, runtime method dispatch

Examples to clarify

  • Metaprogramming: Ruby's define_method creates methods at runtime; C++ template metaprogramming generates code at compile time.
  • Reflection: Querying object.methods or Java's Class.getDeclaredMethods().
  • Code generation: Running an annotation processor that writes Java source files during build; using erb to produce a class file.
  • Dynamic typing: Ruby allows you to call foo.bar without declaring types; this makes metaprogramming easier but is not metaprogramming itself.

How they relate

Reflection is often a tool used inside metaprogramming (you reflect on the structure to decide what to generate). Code generation is one way to implement metaprogramming but is usually an offline step. Dynamic typing removes some obstacles but languages that are statically typed (C++ templates, Rust macros) still provide very powerful metaprogramming.

When you see each

  • Use reflection to inspect objects for debugging, logging, or serialization.
  • Use metaprogramming for DRY DSLs, ORMs, proxies, or removing repetitive boilerplate.
  • Use code generation when runtime costs are too high or language limitations force you to generate static artifacts.
  • Remember: dynamic typing makes metaprogramming easier but isn't the same thing.
