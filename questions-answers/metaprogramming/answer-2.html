Implementing method_missing without respond_to_missing?

Short answer: Yes, you can implement method_missing without implementing respond_to_missing? — calls to missing methods will be handled — but reflection (respond_to?, methods, documentation tools, and some libraries) will not indicate that those methods exist. This can cause surprising behavior.

Example

class DynamicGreeter
  def method_missing(name, *args)
    if name.to_s.start_with?("greet_")
      person = name.to_s.split("_", 2)[1]
      "Hello, #{person.capitalize}"
    else
      super
    end
  end
end

g = DynamicGreeter.new
g.greet_alice           # => "Hello, Alice"
g.respond_to?(:greet_alice)  # => false (surprising)

What happens and why it matters

  • Positive: Calls work — Ruby will dispatch to method_missing when a method is not found.
  • Negative: Introspection fails: respond_to? will usually return false for names handled only by method_missing. Many libraries rely on respond_to? to decide behavior — without respond_to_missing? integration, those libraries may behave incorrectly.

Concrete impacts

  • Auto-completion and IDE hints won't show the dynamic methods.
  • Gems and frameworks that call respond_to? before invoking methods will not call your dynamic methods (e.g., some serialization or templating code).
  • Tools like RDoc / YARD won't document the dynamic methods unless you add explicit documentation.
  • Delegation and proxy patterns rely on respond_to_missing? to remain transparent.

How to fix / recommended approach

Implement respond_to_missing? alongside method_missing. Example fix for the above class:

class DynamicGreeter
  def method_missing(name, *args)
    if name.to_s.start_with?("greet_")
      person = name.to_s.split("_", 2)[1]
      "Hello, #{person.capitalize}"
    else
      super
    end
  end

  def respond_to_missing?(name, include_private = false)
    name.to_s.start_with?("greet_") || super
  end
end

g = DynamicGreeter.new
g.respond_to?(:greet_alice) # => true

Other options

  1. Define methods at runtime the first time they are called (use define_singleton_method / define_method). That makes the methods true members of the object/class and respond_to? will work automatically.
  2. Override respond_to? — avoid this unless you fully understand the responsibilities; prefer implementing respond_to_missing?.

Summary

Technically possible but fragile. For robust, predictable behavior — and for compatibility with other libraries — always pair method_missing with respond_to_missing? or define methods dynamically instead.
