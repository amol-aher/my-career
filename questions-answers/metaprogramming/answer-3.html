What respond_to? returns when a method is defined using method_missing

Short answer: If a method is handled only by method_missing and you did not implement respond_to_missing? (or otherwise override respond_to?), then respond_to? will usually return false. If you implement respond_to_missing? correctly, respond_to? will return true for the virtual method.

Details

respond_to? is used by Ruby and many libraries to ask whether an object implements a given message. Its behavior:

  1. Checks method tables for a concrete method.
  2. If not found, calls respond_to_missing?(method_name, include_private) to allow classes to report dynamic capabilities.
  3. If still not found, returns false.

Example comparisons

# Only method_missing (no respond_to_missing?)
class A
  def method_missing(name, *args)
    :handled
  end
end

A.new.respond_to?(:foo) # => false

# method_missing + respond_to_missing?
class B
  def method_missing(name, *args)
    :handled
  end

  def respond_to_missing?(name, include_private=false)
    true
  end
end

B.new.respond_to?(:foo) # => true

Notes & edge cases

  • If you define the method at runtime (e.g., via define_singleton_method), then respond_to? will see the newly-defined method and return true.
  • Some libraries call respond_to? with include_private = true; honor that parameter if your dynamic methods should be visible to private-call checks.
  • Overriding respond_to? is possible but more brittle than implementing respond_to_missing?, and you should prefer the latter for compatibility with Ruby core.

Recommendation

When building dynamic dispatch with method_missing, implement respond_to_missing? to keep reflection accurate and avoid surprising third-party code.
