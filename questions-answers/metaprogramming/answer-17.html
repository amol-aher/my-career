Implementing a simple DSL using Ruby metaprogramming

We'll build a small routes-like DSL that reads nice declarations and builds an internal structure. This demonstrates instance_eval, method_missing, and define_method to materialize route helpers.

DSL surface

routes.draw do
  get '/users', to: 'users#index'
  post '/users', to: 'users#create'
end

Implementation

class Routes
  Route = Struct.new(:verb, :path, :controller, :action)

  def initialize
    @routes = []
  end

  def draw(&block)
    instance_eval(&block)
    freeze_routes
  end

  # Basic handlers
  %i[get post put patch delete].each do |verb|
    define_method(verb) do |path, to:|
      controller, action = to.split('#')
      @routes << Route.new(verb.to_s.upcase, path, controller, action)
      define_route_helper(controller, action, path)
    end
  end

  def routes; @routes end

  private

  def define_route_helper(controller, action, path)
    helper_name = "#{controller}_#{action}_path"
    # define helper on singleton so consumers can call on instance
    define_singleton_method(helper_name) { path }
  end

  def freeze_routes
    @routes.freeze
  end
end

# Usage
routes = Routes.new
routes.draw do
  get '/users', to: 'users#index'
  post '/users', to: 'users#create'
end

routes.routes.each { |r| puts "#{r.verb} #{r.path} => #{r.controller}##{r.action}" }
puts routes.users_index_path # "/users"

Notes

  • We used instance_eval to evaluate the block in the context of the DSL object so get and post are available as methods.
  • define_method and define_singleton_method were used to create helpers dynamically.
  • We avoided method_missing here by explicitly defining verbs; for more flexible keywords you could use method_missing but should also provide respond_to_missing?.

Tests (brief)

RSpec.describe Routes do
  it "builds routes and helpers" do
    routes = Routes.new
    routes.draw do
      get '/foo', to: 'foo#index'
    end
    expect(routes.routes.first.path).to eq('/foo')
    expect(routes.foo_index_path).to eq('/foo')
  end
end

Variants and extensibility

  • Add namespacing, constraints, or parameterized paths.
  • Use method_missing for verbs you don't want to list explicitly.
  • Generate reverse lookup maps and URL builders with placeholders.

Conclusion

This pattern shows a pragmatic, testable approach to building a small DSL: keep the interpreter separate, use instance_eval for nice syntax and define_method/define_singleton_method to add helpers for usability and performance.
