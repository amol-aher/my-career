How Rails' before_action and validates macros work under the hood

before_action (ActionController callbacks)

Rails implements action callbacks using ActiveSupport::Callbacks. When you call before_action :authenticate, Rails registers the symbol as a callback for the process action event.

Simplified flow:

  1. Controller class includes callback support.
  2. before_action is a macro that adds a callback to a callback chain (e.g., _process_action_callbacks).
  3. When an action is invoked, Rails runs the callback chain in order—before callbacks, around callbacks, action, after callbacks.
# Simplified conceptual implementation
module SimpleCallbacks
  def self.included(base)
    base.extend(ClassMethods)
  end

  module ClassMethods
    def before_action(method_name)
      @before_actions ||= []
      @before_actions << method_name
    end

    def run_before_actions(instance)
      Array(@before_actions).each { |m| instance.send(m) }
    end
  end

  def process_action
    self.class.run_before_actions(self)
    action_method
  end
end

Real Rails implementation supports per-action options (only:, except:), filters as procs, and halting the chain (render / head stops further processing).

validates (ActiveModel validations)

The validates macro is part of ActiveModel::Validations. When you call:

validates :name, presence: true, length: {minimum: 3}

Rails registers validator objects for the attribute and options. At validation time, the valid? method runs through registered validators and collects errors.

# conceptual sketch
module SimpleValidations
  def self.included(base) base.extend(ClassMethods) end

  module ClassMethods
    def validates(*attrs, **opts)
      @validators ||= []
      @validators << [attrs, opts]
    end

    def validators; @validators || [] end
  end

  def valid?
    self.class.validators.each do |attrs, opts|
      attrs.each do |a|
        value = send(a)
        # run checks like presence, length etc based on opts and add errors
      end
    end
  end
end

Metaprogramming aspects

  • Macros like before_action and validates are class-level methods that register behavior via instance variables or class-level registries.
  • Macros may also dynamically define helper methods (e.g., validate_!), using define_method.
  • Rails makes heavy use of ActiveSupport::Concern, Module#prepend, and method_added hooks to wire up behavior.

Why macros are handy

  • They provide declarative, easy-to-read configuration.
  • They let the framework hook into the class lifecycle and register runtime behavior.

Testing and extension

You can inspect registered callbacks and validators in tests (Rails exposes APIs). When modifying these macros, ensure compatibility with options and maintain clear ordering guarantees.

Summary

Both before_action and validates are macros that register configuration and runtime hooks. Under the hood, they store metadata and use callback runners/validator runners to execute behavior at runtime.
