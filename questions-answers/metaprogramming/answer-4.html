Defining methods at runtime in Ruby (metaprogramming with define_method)

Ruby's reflective and metaprogramming facilities let you create methods at runtime. The common approaches are define_method, define_singleton_method, class_eval/module_eval, and manipulating constants and classes. Below are examples and recommendations.

1) define_method (instance methods)

class Person
  [:name, :email, :age].each do |attr|
    define_method(attr) do
      instance_variable_get("@#{attr}")
    end

    define_method("#{attr}=") do |val|
      instance_variable_set("@#{attr}", val)
    end
  end
end

p = Person.new
p.name = "Ada"
p.name # => "Ada"

2) define_singleton_method (per-object methods)

obj = Object.new
obj.define_singleton_method(:greet) { |name| "Hi #{name}" }
obj.greet("Sam") # => "Hi Sam"

3) class_eval / module_eval (string or block eval within class/module)

klass = Class.new
klass.class_eval do
  def dynamic
    "I'm a runtime method"
  end
end

klass.new.dynamic # => "I'm a runtime method"

4) Creating class (or module) constants

MyWorker = Class.new do
  def perform; "work" end
end

MyWorker.new.perform # => "work"

Notes & patterns

  • Capturing variables: define_method creates closures that capture local variables, which is safer than using string-eval for the same goal.
  • Class methods: Use define_singleton_method on the class object, or open the singleton class (class << self; define_method ...; end).
  • Performance: Defining methods explicitly is cheaper at call time than handling calls with method_missing. For repeated calls prefer dynamic definition on first call.

Example: Define-on-first-call pattern

class LazyBuilder
  def method_missing(name, *args, &block)
    # Create a concrete method to avoid future method_missing overhead
    self.class.define_method(name) do |*a, &b|
      "computed: #{name} with #{a.inspect}"
    end
    send(name, *args, &block)
  end

  def respond_to_missing?(name, include_private=false)
    true
  end
end

x = LazyBuilder.new
x.foo(1)  # defines method foo, returns computed value
x.foo(2)  # calls concrete method (faster)

Guidelines

  1. Prefer define_method over class_eval with strings: it's safer and avoids parse-time mixing.
  2. Use dynamic-definition patterns to convert expensive method_missing dispatches into normal method calls.
  3. Keep generated methods small, documented, and test-covered.
