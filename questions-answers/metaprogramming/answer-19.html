What happens behind the scenes when you call extend, include, and prepend?

All three change the method lookup chain but in different ways:

include

include ModuleName inserts the module into the including class's ancestor chain after the class but before its superclass. Methods in the module become instance methods of the class.

module M; def foo; "m" end; end
class C; include M; def foo; "c" end; end
C.new.foo # => "c" (class method overrides module when class defines same name)

prepend

prepend ModuleName inserts the module before the class in the ancestor chain. Module methods take precedence over the class's methods. Module can call super to access the class implementation.

module M; def foo; "m" end; end
class C; prepend M; def foo; "c" end; end
C.new.foo # => "m" (module wins)

extend

object.extend(ModuleName) adds the module to the object's singleton class. The module's methods become singleton methods of the object (or class methods if you extend a class object).

module M; def foo; "m" end; end
o = Object.new
o.extend(M)
o.foo # => "m"

Under the hood (conceptually)

  1. include creates an anonymous proxy in the ancestor chain referencing the module's method table so that method lookup will find the module methods after the class's methods.
  2. prepend inserts the module even earlier so its methods are consulted before the class's own methods.
  3. extend modifies the object's singleton class so that the module appears in the ancestor chain for that object's singleton class.

Implications & use cases

  • Use include to share instance behavior across classes.
  • Use prepend when you want to override class behavior but still call super to reach the original implementation (good for instrumentation or aspect-oriented patterns).
  • Use extend to add behavior to a single object or to add class-level methods by extending the class object.

Example: using prepend for instrumentation

module Logging
  def call(*args)
    puts "calling \#{self.class}#call"
    super
  end
end

class Worker
  def call; "done" end
end

Worker.prepend(Logging)
Worker.new.call
# logs "calling Worker#call" then returns "done"

Edge cases

  • Method resolution order is important when multiple modules are included or prepended — the last inserted appears earlier in the chain.
  • Prepending modules can be surprising for maintainers — document intentions clearly.

Conclusion

include, prepend, and extend are declarative ways to shape the ancestor chain and the method lookup strategy. prepend is especially useful for wrappers/instrumentation while extend is ideal for per-object behavior.
