What are eigenclasses (singleton classes) in Ruby and how they enable metaprogramming

Definition: An eigenclass (or singleton class) is a hidden, anonymous class created by Ruby for each object that stores methods defined only for that specific object (singleton methods). It sits in the object's ancestor chain immediately above the object's original class.

How to create / use an eigenclass

# define a singleton method
obj = Object.new
def obj.greet; "hi" end
obj.greet # => "hi"

# open the singleton class
class << obj
  def another; "x" end
end

Class methods are singleton methods on classes

Classes are objects too. When you write class A; def self.foo; end; end, you're defining a singleton method on the class object — stored in the class's eigenclass. That's why eigenclasses are fundamental to how Ruby models 'class methods'.

Method lookup chain

When a message is sent to obj, Ruby first looks in the eigenclass for matching singleton methods, then proceeds down to the object's class, and then its ancestors.

Use cases and metaprogramming patterns

  • Per-object behavior: Add behavior to a single instance without affecting its class.
  • Per-class behavior: Implement class methods, extend objects with modules by including them into eigenclass (class << obj; include M; end).
  • Dynamic mixins: Extend a single object with a module at runtime using object.extend(Module) (which adds the module to the eigenclass).
  • DSLs: Many DSLs define methods on a per-object basis so that each DSL invocation can alter only its context.

Example: extending single object

module Greeting
  def greet; "hello from module" end
end

o1 = Object.new
o2 = Object.new

o1.extend(Greeting)
o1.greet # => "hello from module"
# o2.greet would raise NoMethodError

Caveats

  • Singleton classes increase object memory usage slightly — avoid creating many singleton methods on huge numbers of objects unless needed.
  • Serialization and marshalling can be tricky if objects rely on eigenclass methods.
  • Singleton class method lookup can be surprising for developers unfamiliar with the concept — document per-object behavior clearly.

Conclusion

Eigenclasses are a core enabler of Ruby's flexible object model — they allow per-object and per-class behavior, dynamic mixins, and are essential for advanced metaprogramming patterns.
