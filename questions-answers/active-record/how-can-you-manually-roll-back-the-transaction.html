How can you manually roll back the transaction?

Summary

To manually roll back a transaction in Rails, you can raise ActiveRecord::Rollback inside the transaction block. This will rollback the transaction but (by design) does not re-raise the exception outside the transaction block. Alternatively, raising any other exception will also rollback but will bubble out unless rescued.

Deep dive — behaviors and differences

  • raise ActiveRecord::Rollback: Rolls back the transaction but is rescued by Rails' transaction machinery so it does not propagate beyond the transaction block. Use when you want to rollback quietly and continue program flow.
  • raise SomeError: Any unrescued exception will rollback the transaction and propagate the exception up the stack, which may be desired for error handling or logging.
  • savepoints and nested transactions: When using nested transactions (ActiveRecord uses savepoints for requires_new: true), raising ActiveRecord::Rollback will rollback to the savepoint for the inner transaction, not necessarily the outer one.

Examples

# Quiet rollback (no exception raised to caller)
ActiveRecord::Base.transaction do
  a = A.create!(...)
  unless some_condition?
    raise ActiveRecord::Rollback
  end
  b = B.create!(...)
end
# Execution continues here; transaction rolled back.

# Raise a custom error (will propagate)
ActiveRecord::Base.transaction do
  a = A.create!(...)
  raise MyCustomError, "something went wrong"
end
# MyCustomError propagates out and can be rescued by caller.

Notes and best practices

  • Prefer ActiveRecord::Rollback when you want to abort DB work without treating it as an exceptional flow for callers.
  • Be careful: since ActiveRecord::Rollback is swallowed by the transaction machinery, code after the transaction will not see an exception — ensure you return appropriate status or set flags if the caller needs to know about the rollback.
  • For nested transactions, understand savepoint semantics — a rollback to an inner savepoint won't affect the outer transaction if you want broader rollback use exceptions that bubble or design accordingly.

Interviewer follow-ups

  • Q: When to use raise ActiveRecord::Rollback vs raising an error?
    A: Use ActiveRecord::Rollback for controlled aborts where you don't need to treat the event as an error for upstream code; raise other exceptions when you want to notify callers or trigger retry/failure logic.
  • Q: How do nested transactions behave with rollback?
    A: Rails uses savepoints: an inner rollback via ActiveRecord::Rollback rolls back to the inner savepoint; to rollback outer transaction, propagate a different exception or avoid nested savepoints as needed.
