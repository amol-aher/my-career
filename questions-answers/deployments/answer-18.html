Tools I've Used to Build Pipelines (Jenkins, GitHub Actions, GitLab CI, AWS CodePipeline, etc.)

Overview

I've built CI/CD using a range of tools — hosted and self-managed — choosing each by constraints like team skillset, integration needs and scale.

Tool experience summary

ToolWhere I used itStrengths
JenkinsOn-prem & cloud for complex enterprise pipelinesHighly extensible, lots of plugins, pipelines as code (Jenkinsfile)
GitHub ActionsCloud-native for OSS and many internal projectsSimple integration with GitHub, OIDC support, hosted runners

SpinnakerLarge-scale multi-cloud CDPowerful deployment strategies, multi-cloud orientation

How I choose a CI/CD tool

  • Repository location & ecosystem (GitHub Actions if on GitHub).
  • Need for managed vs self-hosted runners.
  • Integration with cloud provider and security requirements.
  • Pipeline complexity and approval/enterprise governance needs.

Practical patterns I've implemented

  • PR checks (lint, unit tests) using GitHub Actions for speed and integration.
  • Build agents with Jenkins for long-running integration tests and monorepo builds.
  • GitOps with ArgoCD + Helm for k8s CD and automated drift healing.
  • AWS CodePipeline for end-to-end AWS deployments when teams prefer AWS-managed tooling.

Subquestions

How do you handle secrets in these tools?

Use native secrets store (GitHub Secrets, GitLab CI Variables) with OIDC for short-lived AWS creds or external vaults (HashiCorp Vault) integrated with runners.

Which tool for monorepo?

Prefer orchestrators that support targeted builds: Bazel with custom pipelines, or GitHub Actions with path filters and caching. Jenkins works too for more complex setups.

Conclusion

I've used the right tool for the job — GitHub Actions for developer-friendly CI, Jenkins for complex enterprise needs, and GitOps tools for Kubernetes. If you tell me your repo/provider and constraints, I can propose a concrete pipeline architecture and sample CI config.
