Securing Application Deployments (IAM Roles, Secrets, etc.)

Security principles

  • Least privilege: give each principal the minimal permissions required.
  • Defense in depth: combine network, identity, data and runtime protections.
  • Secrets as first-class: never store secrets in code or images.
  • Automate and audit: rotate keys, log access and enforce policies via IaC.

IAM & identity best practices

  • Use roles not long-lived keys: assign IAM roles to compute resources (EC2 roles, ECS task roles, Lambda execution roles, EKS IRSA).
  • Role separation: separate CI/CD role from runtime roles and use least privilege policies.
  • Use temporary credentials / STS: when pipelines need AWS access prefer assume-role with short-lived tokens.
  • Use OIDC for external CI: configure GitHub/GitLab OIDC provider so GitHub Actions can get temporary credentials without secrets in repo.
  • Apply IAM boundaries & SCPs: in multi-account orgs, use Service Control Policies to enforce guardrails.

Secrets management

  • AWS Secrets Manager: store DB passwords, API keys with automatic rotation using Lambda if supported by the service.
  • SSM Parameter Store (SecureString): good for configuration values; cheaper than Secrets Manager for many values.
  • HashiCorp Vault: enterprise-grade option for multi-cloud and advanced workflows.
  • Inject at runtime: fetch secrets via SDK/agents at startup or use secret integration (ECS secrets, Kubernetes Secrets with KMS/SealedSecrets).
  • Avoid env var leakage: do not echo envs to logs; mask secrets in CI output.

Encryption & key management

  • Use AWS KMS CMKs for encrypting secrets at rest and S3/EBS/RDS encryption.
  • Rotate keys periodically and limit KMS key usage to tightly scoped roles.

Network & runtime protections

  • Use private subnets for internal services; only expose APIs through ALB/NGINX/API Gateway.
  • Use security groups and NACLs following least-privilege network rules.
  • Use VPC endpoints for S3/SecretsManager to avoid egress through internet.
  • Enable TLS everywhere; manage certificates with ACM.
  • Run runtime protection: ECR image scanning, ECR image signing, container vulnerability scanning, and runtime policies (PSP/OPA for k8s).

Supply-chain & artifact security

  • Sign artifacts and containers and verify signatures at deploy time (Sigstore/Cosign).
  • Use an immutable artifact repository (ECR, Artifactory) and only deploy tagged artifacts.
  • Scan dependencies using SCA tools (Dependabot, Snyk, Sonatype).

CI/CD-specific security

  • Use separate minimal roles for CI with only the permissions needed to publish artifacts and trigger deployments.
  • Prefer OIDC or short-lived creds over storing AWS keys in CI secrets.
  • Limit who can approve production deploys and apply MFA for sensitive operations.
Audit & monitoring: enable CloudTrail, AWS Config, GuardDuty and log access to secrets. Review permission usage with Access Analyzer.

Common interview subquestions

How do you rotate secrets without downtime?

Use Secrets Manager rotation or dual-writing/dual-reading: deploy new secret, update consumers to accept both, perform atomic switch once consumers succeed and then remove old secret after safe period.

How do you prevent leaked secrets from being useful?

Enforce short-lived credentials, revoke/rotate compromised secrets, restrict network access and monitor unusual use via CloudTrail and GuardDuty.

How to protect credentials in Terraform state?

Avoid embedding secrets in terraform code and outputs; use data sources to reference external secrets at apply time if possible and encrypt remote state (S3 with KMS) and use DynamoDB locking.

Final checklist for secure deployment

  • Least-privilege IAM roles for every principal.
  • Secrets in Secrets Manager/ Vault, not in code.
  • Immutable, signed artifacts and image scanning.
  • Encryption at rest & in transit with KMS-managed keys.
  • Logging, alerting & automated rotation/audit.
