Differences Between CodePipeline, CodeBuild, and CodeDeploy

Short definitions

  • CodePipeline: Orchestrates stages and actions for the entire release process.
  • CodeBuild: Fully-managed build service that compiles code, runs tests and produces build artifacts.
  • CodeDeploy: Manages deployments to compute platforms (EC2, ECS, Lambda, on-premise) with strategies like in-place or blue-green.

Comparison table

ServicePrimary purposeTypical usage
CodePipelineOrchestrationWire up source -> build -> test -> deploy steps and approvals
CodeBuildBuild & testRun buildspec.yml to build artifacts and run tests
CodeDeployDeploymentPerform ECS blue-green, EC2 in-place or Lambda deployments with lifecycle hooks

How they work together

A typical flow: CodePipeline detects a change, triggers CodeBuild to build artifacts and run tests, then CodeDeploy (or CloudFormation) deploys the artifacts to target environments. CodePipeline coordinates and stores artifacts between actions.

When to use alternatives

  • Use Jenkins/GitHub Actions for richer plugin ecosystems or advanced orchestration features if needed.
  • Use ArgoCD for Kubernetes GitOps-style continuous delivery.

Subquestions

How do I implement blue-green deployments with these?

A: Use CodeDeploy (ECS) or CloudFormation with CodePipeline orchestrating the workflow. CodeDeploy will shift traffic and supports lifecycle hooks for validation and rollback.

How to run tests in CodeBuild?

A: Provide a buildspec.yml that runs tests during the build phase and outputs JUnit reports to be consumed by the pipeline.

Conclusion

Use CodePipeline for orchestration, CodeBuild for building/testing, and CodeDeploy for safe, auditable deployments. They integrate tightly and let you build robust end-to-end AWS-native CI/CD systems.
