Managing Blue-Green and Canary Deployments with AWS CodeDeploy

Key concepts

CodeDeploy supports deployment to EC2/On-Prem, ECS, and Lambda. For ECS it supports blue-green via separate target groups and ALB weight shifting; for Lambda it supports traffic shifting between aliases (canary/linear).

Blue-Green for ECS with CodeDeploy

  1. Create two target groups: one (blue) for the current running tasks and one (green) for the new task set.
  2. CodeDeploy registers the green task set in the green target group, runs lifecycle hooks (pre-traffic), and shifts traffic by changing ALB listener weights according to deployment configuration.
  3. Run validation hooks (tests). If validation passes, continue to shift traffic fully to green. If it fails, CodeDeploy can rollback traffic to blue.

Example AppSpec for ECS (conceptual)

version: 0.0
Resources:
  - TargetService:
      Type: AWS::ECS::Service
      Properties:
        TaskDefinition: "arn:aws:ecs:region:acct:task-definition/mytask:3"
        LoadBalancerInfo:
          ContainerName: web
          ContainerPort: 80
Hooks:
  BeforeInstall: - location: scripts/pre_install.sh
  AfterAllowTestTraffic: - location: scripts/run_smoke_tests.sh
  AfterInstall: - location: scripts/post_install.sh

Canary & Linear traffic shifting (Lambda)

CodeDeploy can shift traffic incrementally to a Lambda alias: canary (e.g., 10% then 100% after a wait) or linear (e.g., 10% every 5 minutes). You define deploymentConfig in CodeDeploy to control these steps.

Automatic rollback integration

CodeDeploy integrates with CloudWatch Alarms — if an alarm triggers during the verification window, CodeDeploy marks the deployment as failed and shifts traffic back to the original environment.

Best practices

  • Define robust validation hooks (synthetic tests and smoke checks).
  • Use CloudWatch or Prometheus metrics as rollback triggers.
  • Keep the old environment warm to allow fast rollback.
  • For DB changes, use backward-compatible migrations and coordinate with deploys.

Subquestions & answers

How long should verification windows be?

Depends on traffic and metrics — often 5–30 minutes. For critical flows, longer windows (hours) and staged promotions may be required.

Can I run custom validation during shift?

Yes — use AppSpec hooks (BeforeAllowTraffic, AfterAllowTraffic) to run tests and gate traffic shifting.

Limitations

  • CodeDeploy manages traffic routing at ALB/target-group level for ECS; advanced traffic shaping may require service mesh or external proxies.
  • Complex multi-service orchestrated changes may need orchestration beyond single CodeDeploy deployment (coordinate via pipeline).

Conclusion

CodeDeploy provides solid primitives for blue-green and canary deployments with automatic rollback and lifecycle hooks — a good fit when paired with ALB, ECS, or Lambda and appropriate validation strategies.
