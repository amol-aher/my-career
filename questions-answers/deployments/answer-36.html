How to Troubleshoot a Deployment That Failed Halfway Through

Immediate steps (incident triage)

  1. Stop further changes: Prevent additional deployments or CI runs that may worsen the state.
  2. Set incident channel: Open Slack/PagerDuty incident and notify stakeholders and on-call engineers.
  3. Record timeframe & versions: Note artifact IDs, commit SHAs and pipeline execution IDs.

Gather data

  • Pipeline logs: CodePipeline/CodeBuild/CodeDeploy logs; CI runner logs.
  • Service logs: CloudWatch, application logs, and container logs (kubectl logs).
  • Deployment/platform status: kubectl rollout status, aws ecs describe-services, or CodeDeploy console.
  • Health & metrics: CloudWatch / Prometheus dashboards (error rate, latency, CPU).
  • Events: CloudTrail, Kubernetes events, load balancer health check failures.

Common root causes

  • Failed health checks causing new instances/pods to be terminated.
  • Schema or migration causing runtime exceptions.
  • Missing environment variables or secrets leading to crashes.
  • Dependency or upstream service failure.
  • IAM permissions or role misconfiguration blocking API calls.

Recovery actions

  • Rollback: If safe, roll back to the last known good artifact (ECS task revision, kubectl rollout undo, previous Lambda alias).
  • Manual remediate: If rollback unsafe (db changes), fix the issue (e.g., restore secrets, increase resource limits) and redeploy patch.
  • Scale up: If resource exhaustion, increase capacity temporarily.

Commands & checks (examples)

# Kubernetes
kubectl get pods -n production
kubectl describe pod myapp-abc -n production
kubectl logs myapp-abc -n production

# ECS
aws ecs describe-services --cluster mycluster --services myservice
aws ecs describe-tasks --cluster mycluster --tasks 

# CodeDeploy / CodePipeline
aws deploy list-deployments --application-name MyApp
aws codepipeline get-pipeline-execution --pipeline-name MyPipeline --pipeline-execution-id

After action: Postmortem

  • Write a blameless postmortem: timeline, root cause, remediation, and preventive actions.
  • Apply fixes: improve tests, tighten deployment gates, add monitoring and alerts.
  • Practice runbooks and drills for similar incidents.

Prevention

  • Use canary or blue-green to reduce blast radius.
  • Require smoke tests and automatic verification before switching traffic.
  • Automate pre-deploy checks for DB migrations, secrets and IAM permissions.

Conclusion

Triage quickly, gather logs and metrics, decide whether to rollback or remediate, and after recovery perform a thorough postmortem with actionable preventions to reduce recurrence.
