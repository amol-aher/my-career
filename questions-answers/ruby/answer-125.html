Question 125: How does Process.fork interact with threads and resources in Ruby?

Concept

fork duplicates the current process; only the calling thread is copied into the child (other threads are not). Resources like open file descriptors are copied but may need reinitialization (DB connections).

Optimal answer (concise)

After fork, re-establish thread pools and external connections in the child. Be careful with locks and shared resources; prefer fork-then-exec patterns for safety.

Subquestions & answers

  • DB connections: reconnect in child to avoid sharing sockets.
  • Thread pools: threads do not get copied; create new threads in child as needed.

Example

# fork example: reconnect DB
pid = fork do
  ActiveRecord::Base.establish_connection
  # child work
  exit 0
end
Process.wait(pid)

Best practices

  • Avoid calling fork in heavily threaded processes; prefer spawn or external workers.
