Question 41: Have you used procs and lambdas in Ruby?

Concept

Procs and lambdas are callable objects (closures) in Ruby. They capture surrounding variables, can be stored in variables, passed to methods, and invoked with call.

Optimal answer (concise)

Yes — I use lambdas when I want strict arity and method-like behavior, and Procs for flexible argument passing or when closures are needed. Both are useful in callbacks, functional-style code, and DSLs.

Subquestions & answers

  • How to call them? — p = proc { |x| x*2 }; p.call(3).
  • Arity differences? — Lambdas enforce arity; Procs are lenient.
  • Return behavior? — return inside a Proc can return from the enclosing method; inside a lambda it returns from the lambda only.

Example

arr = [1,2,3]
d = ->(x){ x * 2 }
arr.map(&d) # => [2,4,6]

p = proc { |x, y| [x, y] }
p.call(1) # => [1, nil]

Best practices / Pitfalls

  • Prefer lambdas for predictable behavior in APIs; use Proc when you intentionally want flexible arity.
  • Avoid unexpected return semantics from Procs in library code.
