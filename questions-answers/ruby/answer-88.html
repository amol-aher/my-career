Question 88: How does MRI differ from JRuby or Rubinius?

Concept

MRI (CRuby) is the reference implementation using YARV VM and GVL. JRuby runs on the JVM, offers native threads without GVL, and uses Java GC and tooling. Rubinius (historical) was a Ruby VM with a bytecode VM and JIT, focusing on concurrency and performance.

Optimal answer (concise)

MRI is canonical and widely compatible with C extensions. JRuby offers JVM advantages (parallel threads, GC, JVM libs). Rubinius and TruffleRuby provide alternative runtime models and optimizations.

Subquestions & answers

  • Compatibility: MRI has the widest gem compatibility, especially C-extensions.
  • Performance: JRuby excels in long-running, warm workloads due to JVM JIT; MRI can be faster for short-lived scripts.

Best practices / Pitfalls

  • Choose runtime based on workload (IO vs CPU), gem dependencies, and deployment constraints.
