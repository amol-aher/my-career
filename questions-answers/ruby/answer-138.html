Question 138: Explain how method_missing, define_method, or dynamic code generation interact with thread safety.

Concept

Dynamic method generation modifies class objects at runtime. In multithreaded environments, defining methods concurrently can create race conditions if multiple threads attempt to define the same method.

Optimal answer (concise)

Guard dynamic definitions with synchronization (Mutex) and prefer defining methods at boot time. If using method_missing for dynamic behavior, ensure respond_to_missing? and define_method caching are thread-safe.

Subquestions & answers

  • Define-once pattern: check if method exists and synchronize defining it to avoid duplicate defs.
  • method_missing perf: method_missing is slower; consider defining concrete methods under lock after first hit.

Example

m = Mutex.new
def dynamic_define(klass, name, &blk)
  return if klass.method_defined?(name)
  m.synchronize do
    unless klass.method_defined?(name)
      klass.define_method(name, &blk)
    end
  end
end

Best practices / Pitfalls

  • Avoid heavy dynamic generation at runtime in a multithreaded server; prefer AOT generation at startup.
