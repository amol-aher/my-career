Question 85: How does Ruby’s Global Interpreter Lock (GIL) affect threading?

Concept

MRI's Global VM Lock (GVL/GIL) ensures only one thread executes Ruby bytecode at a time. It simplifies C extensions but prevents parallel execution of Ruby bytecode on multiple cores.

Optimal answer (concise)

GVL limits CPU-bound parallelism in MRI: threads are context-switched but cannot execute Ruby code simultaneously. IO-bound tasks and native extensions that release the GVL can still achieve parallelism.

Subquestions & answers

  • Alternatives: JRuby/TruffleRuby have no GVL and support real parallelism.
  • Extensions releasing GVL: C extensions can release GVL during blocking operations.

Best practices / Pitfalls

  • For CPU-bound work on MRI, prefer processes or GVL-free runtimes.
