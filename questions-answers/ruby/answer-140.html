Question 140: How would you implement lock-free or wait-free algorithms in Ruby? When is it reasonable?

Concept

Lock-free/wait-free algorithms avoid blocking locks, using atomic primitives for coordination. Ruby's standard runtime lacks low-level atomics in core, but libraries (concurrent-ruby) provide atomic types; JRuby can use java.util.concurrent atomics.

Optimal answer (concise)

Implement lock-free algorithms only for performance-critical low-level components, using Atomic classes or JVM atomics. For most applications, mutexes or higher-level abstractions are reasonable and simpler.

Subquestions & answers

  • When reasonable? — high-throughput, low-latency systems where lock contention is measurable and problematic.
  • Implementation: use Compare-And-Swap (CAS) primitives via concurrent-ruby or Java interop in JRuby.

Example

require 'concurrent-ruby'
atomic = Concurrent::AtomicFixnum.new(0)
threads = 10.times.map { Thread.new { 1000.times { atomic.increment } } }
threads.each(&:join)
puts atomic.value

Best practices / Pitfalls

  • Lock-free code is complex and error-prone; profile first and prefer simpler synchronization if sufficient.
