Question 86: What’s the difference between fibers, threads, and processes in Ruby?

Concept

Processes: OS-level isolation and parallelism. Threads: OS threads mapped by interpreter (but GVL may serialize execution). Fibers: lightweight user-space cooperatively-scheduled concurrency units (not preemptive).

Optimal answer (concise)

Use processes for isolation and full parallelism; threads for concurrent IO-bound tasks (on JRuby for CPU-bound); fibers for cooperative concurrency and async IO in Ruby 3's scheduler model.

Subquestions & answers

  • Fibers: resumed explicitly via resume or scheduled via Fiber scheduler APIs.
  • When to use each: Fibers for async IO, threads for lightweight concurrency (subject to GVL), processes for heavy CPU work or isolation.

Example

# fiber simple
f = Fiber.new { |x| Fiber.yield x + 1; 3 }
f.resume(1) # => 2
f.resume    # => 3

Best practices / Pitfalls

  • Understand scheduling model: fibers rely on cooperative yields; long-running operations must yield to allow other fibers to run.
