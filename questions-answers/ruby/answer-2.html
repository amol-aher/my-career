Question 2: Can you explain Turbo/Hotwire in Rails 7?

Concept

Hotwire is a set of techniques (and libraries) for building modern, fast web apps with minimal JavaScript by sending HTML over the wire. In Rails 7, the Hotwire stack centers on Turbo (Drive, Frames, Streams) and pairs well with Stimulus for client behavior.

Optimal answer (concise)

Turbo minimizes client-side JS by accelerating navigation (Turbo Drive), enabling partial DOM updates (Turbo Frames), and pushing real-time changes (Turbo Streams). It favors server-rendered HTML and smaller JS controllers (Stimulus) for behavior.

Subquestions & answers

  • Turbo Drive: intercepts link/form navigation to fetch HTML and replace the body for faster navigation.
  • Turbo Frames: allow partial updates by targeting a named frame; you can update a portion of a page without a full reload.
  • Turbo Streams: let the server broadcast DOM changes (append/replace/remove) over ActionCable or other adapters.
  • When to use Turbo vs SPA: Use Turbo for CRUD-heavy apps with server-rendered UIs. Use an SPA when you need complex client-side state management or offline-first behavior.

Example

<!-- form inside a frame -->
<turbo-frame id="comment_form">
  <%= form_with model: @comment, local: false do |f| %>
    <%= f.text_area :body %>
    <%= f.submit "Post" %>
  <% end %>
</turbo-frame>

Best practices / Pitfalls

  • Keep frames focused and small to avoid complex update logic.
  • Test Turbo Streams and broadcasting paths thoroughly — race conditions can occur with concurrent updates.
  • Combine with Stimulus for client-side behaviors that need lifecycle hooks.
