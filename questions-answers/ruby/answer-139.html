Question 139: What are the trade-offs between using processes (fork) vs threads vs JRuby for scaling Ruby apps?

Concept

Each model has trade-offs in isolation, memory usage, parallelism, and complexity.

Optimal answer (concise)

Processes: strong isolation, heavier memory, easy parallelism on MRI. Threads: lower memory, share state, but MRI GVL limits CPU parallelism. JRuby: threads with true parallelism, JVM ecosystem, higher memory/GC tuning. Choose based on CPU vs IO, gem/native ext needs, and operational constraints.

Subquestions & answers

  • When to use processes? — CPU-bound on MRI, isolation needs, crash containment.
  • When to use threads? — high-concurrency IO-bound workloads and shared in-memory caches (with caution).
  • JRuby trade-offs? — better parallelism and tooling; watch gem compatibility and JVM resource usage.

Best practices / Pitfalls

  • Consider hybrid approaches: processes for isolation, threads within each process for IO concurrency; move heavy compute to services if needed.
