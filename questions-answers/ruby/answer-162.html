Question 162: Compare performance of a CPU-bound workload implemented with threads vs using multiple processes (fork) on MRI. Measure and report.

Concept

On MRI, threads are constrained by GVL for Ruby code, so CPU-bound tasks do not gain parallelism with threads. Processes (fork) run in separate OS processes and can utilize multiple cores.

Optimal answer (concise)

Measure by running the same CPU-heavy function across N workers using threads and processes, and compare elapsed time and CPU usage. Expect processes to scale with cores; threads on MRI will not.

Example measurement approach

# pseudocode
def heavy(n); (1..n).map { |i| Math.sqrt(i) }.reduce(:+) end
workers = 4

# threads
t0 = Time.now
threads = workers.times.map { Thread.new { heavy(10_000_000) } }
threads.each(&:join)
t1 = Time.now; puts "threads elapsed: \#{t1 - t0}"

# processes (fork)
t0 = Time.now
pids = workers.times.map do
  fork { heavy(10_000_000); exit 0 }
end
pids.each { |pid| Process.wait(pid) }
t1 = Time.now; puts "processes elapsed: \#{t1 - t0}"

Expected result

Processes time ≈ single-thread time / workers (up to core count). Threads time ≈ single-thread time due to GVL (no linear speedup).

Notes

Measure on your target environment; consider memory overhead and process startup costs.
