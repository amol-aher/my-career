Question 17: What is the difference between private and protected methods in Ruby?

Concept

Both limit method visibility. private disallows explicit receivers; protected allows explicit receivers but only from the same class hierarchy.

Optimal answer (concise)

Private methods require implicit receiver (can't call with obj.method). Protected methods can be called with explicit receiver but only from instances of the same class or subclasses.

Subquestions & answers

  • Can subclasses call protected methods? — Yes, across instances of the class/subclass.
  • Why use protected? — When you need to compare or access state across instances of the same class (e.g., compare_age(other)).

Example

class Person
  def older_than?(other)
    age > other.age_from(self)
  end

  protected
  def age_from(caller) age end

  private
  def secret; 'x' end
end

Best practices / Pitfalls

  • Prefer clear public APIs and keep protected/private methods small and well-documented.
