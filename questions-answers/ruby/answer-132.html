Question 132: How can volatile or atomic semantics be achieved in Ruby? (e.g., atomics from stdlib/gem)

Concept

Volatile/atomic semantics ensure reads/writes have memory ordering and atomicity properties. Ruby provides gems and stdlib utilities to achieve atomic operations.

Optimal answer (concise)

Use Mutex for coarse-grained atomicity, or use gems like concurrent-ruby which provide AtomicFixnum, AtomicBoolean, and atomics that use native primitives for lock-free updates where supported.

Subquestions & answers

  • concurrent-ruby Atomics: Concurrent::AtomicFixnum.new supports atomic increments.
  • Volatile semantics: JVM provides volatile for visibility in JRuby; use Java interop for advanced needs.

Example

require 'concurrent-ruby'
a = Concurrent::AtomicFixnum.new(0)
threads = 10.times.map do
  Thread.new { 1000.times { a.increment } }
end
threads.each(&:join)
puts a.value # => 10000

Best practices / Pitfalls

  • Use atomic types for counters and lightweight coordination; use Mutex for complex invariants.
