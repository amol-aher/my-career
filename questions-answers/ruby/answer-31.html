Question 31: Would it make sense to run multiple threads or multiple processes on multi-core processors?

Concept

Processes and threads are two approaches to parallelism. Processes have separate memory spaces and can run fully in parallel on multiple cores. Threads share memory in the same process and may be constrained by interpreter locks (e.g., MRI's GVL).

Optimal answer (concise)

On MRI Ruby, prefer multiple processes for CPU-bound workloads to utilize multiple cores. For IO-bound workloads, threads are often more efficient. On runtimes without a GVL (JRuby), threads can be used for CPU-bound parallelism.

Subquestions & answers

  • Memory isolation: Processes isolate memory (safer) but cost more memory.
  • Inter-process communication: More complex (pipes, sockets, Redis) than sharing memory with threads.
  • Use cases: Use processes for CPU-heavy tasks and threads for many IO-concurrent tasks.

Example

# process approach (fork) - Linux/Unix only
pids = 4.times.map do
  fork do
    # CPU-bound work here
    puts "child \#{Process.pid} working"
    exit 0
  end
end
Process.waitall

Best practices / Pitfalls

  • Processes require more memory and careful management (supervisors like systemd, Kubernetes).
  • Use thread pools and backpressure for high-concurrency IO.
