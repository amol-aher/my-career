Question 137: How would you detect and debug a memory leak in a long-running multithreaded Ruby process?

Concept

Memory leaks in multithreaded processes require observing memory growth, heap dumps, and inspecting objects retained by threads, globals, caches, or thread-local variables.

Optimal answer (concise)

Collect memory snapshots over time (ObjectSpace, heap dump tools), inspect retained objects, examine thread-local variables and long-lived caches, and use profilers (memory_profiler, derailed_bench) or native tools (jemalloc, pmap) to find the leak source.

Subquestions & answers

  • Thread-local leaks: thread pools may retain data via Thread.current — clear per-request data.
  • Heap dumps: capture and compare snapshots to find growing object classes and retained paths.

Example steps

# collect counts periodically
Thread.new do
  loop do
    GC.start
    puts ObjectSpace.each_object(ClassName).count
    sleep 60
  end
end

Best practices / Pitfalls

  • Test in staging with similar load; avoid heavy ObjectSpace usage in production unless necessary for investigation.
