Question 24: Can you share your screen and write an example of how you would write concerns for two classes (A and B) with a common property?

Concept

Concerns are modules (often using ActiveSupport::Concern) to share behavior between models/controllers. They allow instance methods, included hooks, and class methods via class_methods.

Optimal answer (concise)

Use ActiveSupport::Concern, define instance methods and class_methods for class-level behavior. Include the concern in both classes.

Example

# app/models/concerns/has_timestamps.rb
module HasTimestamps
  extend ActiveSupport::Concern

  included do
    scope :recent, -> { where('created_at > ?', 1.day.ago) }
  end

  def formatted_created_at
    created_at.strftime('%Y-%m-%d %H:%M:%S')
  end

  class_methods do
    def count_today
      where('created_at > ?', Time.current.beginning_of_day).count
    end
  end
end

# models
class A < ApplicationRecord
  include HasTimestamps
end

class B < ApplicationRecord
  include HasTimestamps
end

Best practices / Pitfalls

  • Avoid concerns that mix unrelated responsibilities—keep them cohesive.
  • Prefer explicit modules over deep concern hierarchies for clarity.
