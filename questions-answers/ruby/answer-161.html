Question 161: Write tests that reliably reproduce a race condition, then fix the underlying code.

Concept

Reproducing races in tests requires controlling timing and creating antagonistic interleavings. Use hooks, barriers, and injected sleeps to force problematic scheduling. Fixes usually add synchronization or redesign to remove shared mutable state.

Optimal answer (concise)

Create a deterministic test that exercises the critical interleaving, assert the broken behavior reproduces, then apply synchronization (Mutex) or redesign to make it deterministic, and assert the fix prevents the race.

Example (test + fix)

# vulnerable counter
class Counter
  def initialize; @n = 0 end
  def increment
    temp = @n
    sleep 0.001 # force a race window in test
    @n = temp + 1
  end
  def value; @n end
end

# test to reproduce race
def reproduce_race
  c = Counter.new
  threads = 10.times.map { Thread.new { 100.times { c.increment } } }
  threads.each(&:join)
  puts "value = \#{c.value}" # often < 1000 due to race
end

# fix: synchronize
class SafeCounter < Counter
  def initialize; super; @mutex = Mutex.new end
  def increment
    @mutex.synchronize do
      super_without_sleep = begin
        temp = @n
        @n = temp + 1
      end
    end
  end
end

# test fixed version should reliably be 1000

Notes

In tests, add instrumentation (sleep, barriers) to increase chance of exposing race. Use deterministic schedulers for stronger guarantees when available.
