Question 174: Write tests that reliably reproduce a race condition, then fix the underlying code. (Advanced: using Ractors where applicable)

Concept

Ractors (Ruby 3) provide actor-like isolation. Reproducing races may involve Ractors when testing cross-ractor coordination issues, but Ractors avoid shared-state races by design.

Optimal answer (concise)

Use Ractors to isolate state; to reproduce races in shared-memory code, use threads and barriers. For Ractor-specific bugs, test message ordering and data transfer semantics.

Example (Ractor isolation demonstration)

# Ractors can't share mutable objects; use them to avoid many races
r = Ractor.new do
  msg = Ractor.receive
  Ractor.yield msg * 2
end
r.send 10
p r.take # => 20

Notes

Ractors change concurrency model and require designs using message passing; they aren't a drop-in replacement for threads.
