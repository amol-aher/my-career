Question 122: What is Concurrent::Future / Concurrent::Promise (from the concurrent-ruby gem)? When is it useful?

Concept

concurrent-ruby provides high-level concurrency abstractions. Concurrent::Future represents a value computed asynchronously; Concurrent::Promise models a chainable async computation that can be resolved or failed.

Optimal answer (concise)

Use Future for fire-and-forget tasks where you later need the result. Use Promise for chaining async operations and representing success/failure with callbacks.

Example

require 'concurrent-ruby'
f = Concurrent::Future.execute { heavy_calc }
# do other work
result = f.value # blocks until ready

p = Concurrent::Promise.execute { do_step1 }
               .then { |r| do_step2(r) }
               .rescue { |err| handle(err) }

Best practices

  • Use thread pools and configure Executors to control concurrency resources.
  • Handle exceptions and timeouts explicitly.
