Question 160: Create a small example that demonstrates a deadlock; then fix it and explain your changes.

Concept

Deadlocks happen when locks are acquired in inconsistent order. Fix by ordering lock acquisition, using try_lock with timeout, or refactoring to reduce locking.

Optimal answer (concise)

Show two threads acquiring locks in opposite order causing deadlock; fix by acquiring locks in a consistent global order.

Code (deadlock)

m1 = Mutex.new
m2 = Mutex.new

t1 = Thread.new do
  m1.synchronize do
    sleep 0.1
    m2.synchronize { puts 't1 done' }
  end
end

t2 = Thread.new do
  m2.synchronize do
    sleep 0.1
    m1.synchronize { puts 't2 done' }
  end
end

[t1, t2].each(&:join) # deadlock

Fixed version

# enforce global ordering: always lock m1 then m2
t1 = Thread.new do
  m1.synchronize do
    sleep 0.1
    m2.synchronize { puts 't1 done' }
  end
end

t2 = Thread.new do
  m1.synchronize do          # changed order to match t1
    sleep 0.1
    m2.synchronize { puts 't2 done' }
  end
end

[t1, t2].each(&:join) # completes

Explanation

By ensuring both threads acquire locks in the same order (m1 then m2), we prevent circular wait, eliminating the deadlock.
