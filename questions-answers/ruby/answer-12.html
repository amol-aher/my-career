Question 12: Since JRuby supports multithreading, how does it handle race conditions or thread locks? Is it similar to Ruby or different?

Concept

JRuby maps Ruby threads to JVM threads, so concurrency uses native OS threads. Race conditions are still possible and must be handled via synchronization primitives.

Optimal answer (concise)

JRuby uses JVM-backed thread primitives. Race conditions are handled like in Java: use Mutex, Monitor, synchronized blocks, atomics. It's similar conceptually but runs in real parallelism (no GVL).

Subquestions & answers

  • Mutex semantics? — Same API (Mutex, Monitor) but implemented on JVM primitives.
  • Memory model? — JVM memory model applies; visibility and ordering follow Java specs.

Example

mutex = Mutex.new
threads = 10.times.map do
  Thread.new do
    1000.times { mutex.synchronize { $counter += 1 } }
  end
end
threads.each(&:join)

Best practices / Pitfalls

  • Because JRuby executes truly in parallel, missing locks lead to real data races — be stricter with synchronization.
  • Consider java.util.concurrent tools if integrating tightly with Java libraries.
