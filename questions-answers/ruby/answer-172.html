Question 172: Write tests that reliably reproduce a race condition, then fix the underlying code. (Advanced: use barriers and deterministic scheduling)

Concept

Use synchronization primitives (barriers, latches) to force specific interleavings in tests. Deterministic scheduling can be simulated by controlling when threads proceed.

Optimal answer (concise)

Introduce barriers that pause threads until all reach a point, then release them to create desired races. After reproducing, add synchronization (Mutex) in code and assert the race no longer occurs.

Example (barrier-based test)

require 'thread'

class Barrier
  def initialize(n)
    @n = n
    @count = 0
    @mutex = Mutex.new
    @cond = ConditionVariable.new
  end

  def wait
    @mutex.synchronize do
      @count += 1
      if @count < @n
        @cond.wait(@mutex)
      else
        @cond.broadcast
      end
    end
  end
end

# vulnerable counter (same as earlier)
class Counter
  def initialize; @n = 0 end
  def increment
    temp = @n
    sleep 0.001
    @n = temp + 1
  end
  def value; @n end
end

def reproduce_with_barrier
  c = Counter.new
  barrier = Barrier.new(10)
  threads = 10.times.map do
    Thread.new do
      100.times do
        barrier.wait
        c.increment
      end
    end
  end
  threads.each(&:join)
  puts c.value # often < 1000
end

# fix by synchronizing increment
class SafeCounter
  def initialize; @n = 0; @m = Mutex.new end
  def increment
    @m.synchronize do
      @n += 1
    end
  end
  def value; @n end
end

Notes

Barriers make tests deterministic by aligning execution points; combine with injected sleeps if necessary.
