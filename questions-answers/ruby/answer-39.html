Question 39: Have you used parallel/async processing methods in Ruby (like pmap)?

Concept

Parallel and async patterns help with concurrency. Libraries like parallel, concurrent-ruby, and async provide abstractions for concurrent/parallel computation and IO.

Optimal answer (concise)

Yes — used concurrent-ruby for thread pools/futures, parallel for map-like parallelism, and async for structured concurrency with fibers. Choice depends on runtime (MRI vs JRuby) and workload.

Subquestions & answers

  • parallel gem: runs tasks in multiple processes by default (good for MRI CPU-bound work).
  • concurrent-ruby: thread pools, futures, promises — works across interpreters.
  • async gem: uses fibers/schedulers for non-blocking IO.

Example

require 'parallel'
results = Parallel.map([1,2,3,4], in_processes: 4) { |i| heavy(i) }

# concurrent-ruby future
require 'concurrent-ruby'
f = Concurrent::Future.execute { long_task }
f.value

Best practices / Pitfalls

  • Beware of shared mutable state when using threads.
  • Use processes for CPU-bound tasks on MRI to avoid GVL limits.
