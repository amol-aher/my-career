Question 15: Does Ruby support multithreading? What are its limitations?

Concept

Ruby supports threads at the language level. MRI historically enforces a Global VM Lock (GVL/GIL) that prevents true parallel execution of Ruby bytecode; JRuby and others don't have this limitation.

Optimal answer (concise)

Yes — Ruby threads exist, but on MRI the GVL limits CPU-bound parallelism. IO-bound tasks still benefit; use native extensions, JRuby, or process-based parallelism for CPU-bound workloads.

Subquestions & answers

  • When can threads be parallel in MRI? — When extensions release the GVL (e.g., blocking IO implemented in C) or when using JRuby.
  • Alternatives for CPU-bound jobs? — Process.fork, background workers, or JRuby for true parallelism.

Best practices / Pitfalls

  • Prefer thread pools and proper synchronization; avoid unbounded thread creation.
  • Prefer processes for CPU-heavy tasks on MRI to utilize multiple cores.
