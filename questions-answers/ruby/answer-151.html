Question 151: Explain priority inversion and possible remedies in Ruby systems.

Concept

Priority inversion happens when a low-priority thread holds a resource needed by a high-priority thread, and a medium-priority thread prevents the low-priority thread from running to release the resource.

Optimal answer (concise)

In Ruby, thread priorities are advisory and platform-dependent, so priority inversion is usually addressed by avoiding reliance on priorities: keep critical sections short, use timeouts, and design fairness into queues. If using priority-based scheduling, consider priority inheritance or use dedicated worker pools per priority.

Subquestions & answers

  • Priority inheritance: temporarily raise the priority of the lock-holder to the highest waiting priority to reduce inversion.
  • Alternative: use multiple queues or executors for different priority classes.

Example

# approach: separate pools per priority
high_pool = ThreadPool.new(5)
low_pool = ThreadPool.new(1)
# schedule high-priority tasks to high_pool to avoid blocking by low-priority work

Best practices / Pitfalls

  • Avoid depending on Thread#priority for correctness. Design queues and backpressure rather than priority juggling.
