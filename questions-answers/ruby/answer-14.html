Question 14: How does Ruby know when objects are no longer required and can free up memory?

Concept

Ruby uses reachability analysis: starting from GC roots (globals, stack locals, currently referenced objects), it marks reachable objects. Unmarked objects are considered garbage and collected.

Optimal answer (concise)

GC mark phase marks reachable objects from roots; sweep phase reclaims unmarked objects. Finalizers may run but should be used sparingly.

Subquestions & answers

  • What are roots? — Globals, constants, stack variables, active frames, and internal VM references.
  • Are there weak references? — Ruby provides WeakRef (stdlib) for references that don't prevent GC.

Best practices / Pitfalls

  • Avoid holding references (caches, global arrays) that prevent GC.
  • Use profiling to find leaked references (GC.stat, ObjectSpace.each_object).
