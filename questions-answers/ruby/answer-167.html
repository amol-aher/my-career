Question 167: How do you design for observability in concurrent systems (metrics, tracing, logging)?

Concept

Observability in concurrent systems requires correlating context across threads/fibers, tracking queue lengths, contention, and resource usage, and capturing traces for distributed flows.

Optimal answer (concise)

Emit structured logs with request IDs, instrument metrics for queue depths, worker latencies, GC and thread metrics, and add distributed tracing for cross-service flows. Correlate logs and traces with a unique context propagated through threads/fibers.

Subquestions & answers

  • Context propagation: pass context explicitly or use fiber-local storage with careful cleanup for async code.
  • Metrics: expose histograms, gauges, and counters for concurrency hotspots.

Example

# pseudo: set request id in fiber-local storage
Fiber.current[:req_id] = SecureRandom.uuid
logger.info("start", req_id: Fiber.current[:req_id])

Best practices

  • Keep metric cardinality low, and instrument points of contention (lock wait times, queue lengths).
