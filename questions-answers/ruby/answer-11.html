Question 11: Why should one choose JRuby instead of Ruby?

Concept

JRuby runs Ruby code on the JVM. It trades the MRI ecosystem for the JVM's strengths: mature GC, native threading, JVM tooling, and Java interoperability.

Optimal answer (concise)

Choose JRuby if you need true parallelism, JVM ecosystem access, or JVM production benefits (profiling, GC tuning). For heavy CPU parallelism or Java interop, JRuby can be advantageous.

Subquestions & answers

  • C extensions? — Many C-based gems won't work; look for Java alternatives or JRuby-friendly gems.
  • Memory & startup? — Higher memory footprint and slower startup due to JVM.
  • Performance? — Varies; JVM JIT may give excellent throughput after warmup.

Best practices / Pitfalls

  • Benchmark under realistic workloads. Watch GC tuning and heap sizes.
  • Prepare for gem compatibility checks and potential rework for native extensions.
