Question 115: How does JRuby’s threading model differ from MRI’s?

Concept

JRuby maps Ruby Thread to JVM threads and doesn't have a GVL, enabling true parallel execution of Ruby code across cores.

Optimal answer (concise)

JRuby supports native parallelism via JVM threads, so code can run on multiple cores simultaneously. This requires careful synchronization (JVM memory model) but enables better CPU utilization.

Subquestions & answers

  • Implications: race conditions are more likely; use Mutex/atomic primitives; leverage JVM tooling for profiling.
  • Performance: JVM JIT can optimize long-running code, often yielding high throughput after warmup.

Best practices

  • Benchmark and tune GC and thread pools; be mindful of differences in native extension support.
