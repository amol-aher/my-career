Question 34: Have you used practices like frozen literals, symbols, memoization in Ruby for optimization?

Concept

Minimizing allocations and object churn reduces GC pressure. Frozen string literals, symbols, and memoization help reduce allocations and improve performance.

Optimal answer (concise)

Yes — I use frozen string literals (or .freeze), prefer symbols for static identifiers, and memoize expensive computations to avoid repeated allocations and CPU work.

Subquestions & answers

  • Frozen literals pragma: # frozen_string_literal: true reduces temporary string allocations.
  • Symbols vs strings: Symbols are immutable and reused, reducing allocations, but excessive dynamic symbols can leak memory (symbol GC exists in modern Ruby).
  • Memoization: Use @memo ||= expensive carefully (false/nil pitfalls) or use defined? patterns.

Example

# frozen_string_literal: true
def greeting(name)
  "Hello, \#{name}" # avoids extra mutable string when possible
end

def config_value
  @config_value ||= compute_config # memoize expensive call
end

Best practices / Pitfalls

  • Avoid memoization that holds large objects forever; clear caches when appropriate.
  • Use symbolization only for stable keys; avoid dynamically creating many symbols in old Ruby versions.
