Question 145: How does concurrent-ruby implement thread pools, futures, and actors? What are the actor-model pros/cons here?

Concept

concurrent-ruby provides abstractions for concurrency: thread pools (fixed, cached), futures/promises for async values, and actors for isolated state/message-passing.

Optimal answer (concise)

Thread pools reuse worker threads to run tasks efficiently. Futures/Promises represent async computations. Actors isolate state and process messages sequentially, avoiding explicit locks. Pros: safety and isolation; Cons: higher messaging overhead and debugging complexity.

Example

require 'concurrent-ruby'
pool = Concurrent::FixedThreadPool.new(5)
future = Concurrent::Future.execute(executor: pool) { heavy_work }
puts future.value

Best practices

  • Use actors when you want isolated state. Use futures for async pipelines. Tune pools carefully.
