Question 92: What’s the difference between eager and lazy evaluation in Ruby?

Concept

Eager evaluation computes results immediately; lazy evaluation defers computation until needed. Ruby's Enumerable#lazy allows chaining operations without creating intermediate arrays.

Optimal answer (concise)

Eager: map/select produce new arrays immediately. Lazy: build a pipeline that's evaluated when needed (e.g., first, take), saving memory and CPU for large datasets.

Subquestions & answers

  • When to use lazy? — long chains, large data, or infinite enumerables.
  • Performance tradeoffs: lazy reduces allocations but may add overhead for small collections.

Example

result = (1..1_000_000).lazy.select { |i| i % 3 == 0 }.first(5)

Best practices

  • Use lazy when dealing with large or streamed data; use eager for simple small collections.
