Question 70: How do you handle exceptions in Ruby? Difference between raise and throw/catch.

Concept

Exceptions use raise and rescue. throw and catch implement non-local flow control (labels) and are not for error handling.

Optimal answer (concise)

Use raise to signal exceptional conditions and rescue to handle them. Use catch/throw for controlled non-local exits (like breaking out of deeply nested loops) — not as replacement for exceptions.

Subquestions & answers

  • raise usage: raise "msg" or raise SomeError, "msg".
  • throw/catch: catch(:done) { throw :done if condition }.
  • ensure: always runs cleanup regardless of exceptions.

Example

begin
  raise ArgumentError, 'bad'
rescue ArgumentError => e
  puts e.message
ensure
  puts 'cleanup'
end

# throw/catch
catch(:found) do
  [1,2,3].each do |i|
    throw :found, i if i == 2
  end
end

Best practices / Pitfalls

  • Rescue specific exceptions rather than rescue <Exception> broadly.
  • Use ensure for deterministic cleanup and avoid using throw/catch for error handling.
