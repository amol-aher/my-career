Question 13: Do you know how garbage collection works in Ruby and JRuby?

Concept

Garbage collection reclaims memory for objects no longer reachable. MRI uses a generational, mark-and-sweep collector; JRuby relies on the JVM's GC implementations (G1, Shenandoah, ZGC) depending on JVM and configuration.

Optimal answer (concise)

MRI GC: generational + incremental improvements, tuned with RUBY_GC_* variables. JRuby: uses JVM GC — benefit from mature collectors and tuning options of the JVM.

Subquestions & answers

  • How to profile? — MRI: objspace, GC.stat, memory_profiler. JRuby: Java profilers (jmap, jvisualvm, async-profiler).
  • Tuning? — MRI: environment variables and GC.stat; JRuby: heap sizes and JVM GC flags.

Best practices / Pitfalls

  • Reduce short-lived allocations for lower GC pressure.
  • In JRuby, tune JVM GC parameters for throughput or low latency as needed.
