Question 30: Do you understand how Ruby creates threads internally? Are they fully concurrent?

Concept

Internally, MRI threads map to native OS threads, but MRI enforces a Global VM Lock (GVL/GIL) which ensures only one thread runs Ruby bytecode at a time. Thus they're not fully concurrent for CPU-bound Ruby code. JRuby maps to JVM threads without a GVL.

Optimal answer (concise)

MRI threads are backed by OS threads but constrained by GVL for Ruby execution. IO-bound actions or native extensions that release the GVL can run in parallel. For real parallelism, use JRuby or processes.

Subquestions & answers

  • When do threads run in parallel? — When the VM releases the GVL (blocking IO, C extensions), or when using JRuby.
  • How to get full CPU usage? — Use multiple processes, JRuby, or spawn workers across cores.

Best practices / Pitfalls

  • Don't assume threads speed up CPU-bound tasks on MRI; benchmark and choose processes if needed.
