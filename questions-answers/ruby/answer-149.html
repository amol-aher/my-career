Question 149: What are the pitfalls of using global mutable state in a concurrent Ruby app, and how to mitigate them?

Concept

Global mutable state (class vars, globals, singletons) causes contention, race conditions, and hard-to-debug bugs when accessed across threads.

Optimal answer (concise)

Pitfalls: race conditions, inconsistent data, test pollution. Mitigate by avoiding globals, using dependency injection, immutability, or protecting access with Mutex/actors.

Subquestions & answers

  • Mitigations: freeze constants, use thread-local state, prefer DI patterns.
  • Alternatives: actor model, explicit message passing.

Best practices

  • Limit globals to truly constant, frozen data. Avoid global mutable caches in threaded servers.
