Question 3: What gems are you using for authentication and authorization?

Concept

Authentication verifies identity (who you are); authorization decides what an authenticated user can do. In Rails, common patterns involve an authentication library plus a separate authorization policy layer.

Optimal answer (concise)

Use Devise (authentication) and Pundit (authorization) as a solid combo. For APIs, use JWT or Doorkeeper (OAuth2). For simple apps, lightweight approaches (has_secure_password + custom policies) may suffice.

Subquestions & answers

  • Devise modules: confirmable, recoverable, trackable, omniauthable — enable as needed.
  • Pundit vs CanCanCan: Pundit favors plain policy objects (explicit), CanCanCan offers DSL (concise rules).
  • API auth: Use JWT for stateless APIs, or Doorkeeper for OAuth2 flows.
  • Session security tips: use secure cookies, SameSite, HTTPS, and rotate session keys on critical actions.

Example (Pundit policy)

class PostPolicy
  attr_reader :user, :post
  def initialize(user, post) @user, @post = user, post end
  def update?; user && (user.admin? || post.user_id == user.id) end
  def destroy?; user&.admin? end
end

Best practices / Pitfalls

  • Least-privilege: default to deny and explicitly allow actions.
  • Keep auth checks in controllers/policies, not spread across views/models.
  • Audit authentication flows and session lifetimes for security compliance.
