Question 8: What’s the difference between Proc and Lambda?

Concept

Both Proc and lambda create callable objects in Ruby, but they differ in argument handling (arity) and return semantics — lambdas behave more like methods, Procs behave more like closures with different return behavior.

Optimal answer (concise)

Lambda enforces arity and returns control to the caller when return is used; Proc is lenient on arity and return inside a Proc attempts to return from the surrounding method.

Subquestions & answers

  • How to create each? — Lambda: ->(x){...} or lambda { |x| ... }. Proc: Proc.new { |x| ... } or proc { |x| ... }.
  • Arity example? — Lambda will raise on wrong args; Proc will fill with nils or ignore extras.
  • Return behavior? — Returning inside a Proc can cause method return; be cautious.

Example

l = ->(x){ return x * 2 }
def foo; l.call(3); 'after' end
puts foo # => "after"

p = proc { return 'from proc' }
def bar; p.call; 'after' end
puts bar # => "from proc"

Best practices / Pitfalls

  • Use lambda when you want method-like behavior and strict arity.
  • Use Proc when you want looser argument handling or closure semantics (but beware of returns).
