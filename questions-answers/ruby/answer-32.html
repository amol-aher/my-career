Question 32: So there is no way for Ruby threads to exploit all the cores?

Concept

Ruby threads' ability to use multiple CPU cores depends on the interpreter. MRI's GVL prevents simultaneous execution of Ruby bytecode on multiple cores, but JRuby and TruffleRuby can run threads in parallel across cores.

Optimal answer (concise)

On MRI, threads typically can't exploit all cores for CPU-bound code due to the GVL. Use processes or a GVL-free runtime (JRuby/TruffleRuby) to achieve full core utilization.

Subquestions & answers

  • Can extensions help? — Yes; native C extensions can release the GVL during heavy computation.
  • When are threads parallel? — When IO or C code releases the GVL, or when using a non-GVL Ruby runtime.

Best practices / Pitfalls

  • Don't assume threads improve CPU-bound performance under MRI; measure and choose processes or alternate runtimes when needed.
