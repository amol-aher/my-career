Question 62: Explain blocks, procs, and lambdas. How do they differ?

Concept

Blocks are anonymous chunks of code passed to methods. Procs and lambdas wrap blocks into objects. Differences involve arity and return behavior.

Optimal answer (concise)

Blocks: syntactic, not objects unless converted (to_proc). Proc: an object, lenient with arity, return affects enclosing method. Lambda: Proc-like object, strict arity, return returns from lambda only.

Subquestions & answers

  • Converting block to proc: use &block parameter or &:symbol shorthand.
  • When to use: use lambdas for callbacks needing strict arity; procs/blocks for simple closures.

Example

def call_block(&b)
  b.call(1)
end

call_block { |x| puts x }

lam = ->(x){ puts x }
pr = proc { |x| puts x }

lam.call(1) # ok
# lam.call() # would raise arity error
pr.call()   # ok (nil parameter)

Best practices / Pitfalls

  • Document expected callables; prefer lambdas for public APIs to avoid surprising arity/return behavior.
