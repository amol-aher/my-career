Question 35: Have you implemented observability in your applications (custom metrics, memory usage, performance bottlenecks)?

Concept

Observability encompasses metrics, logs, and traces. Instrumenting applications helps detect performance issues, memory leaks, and business metrics.

Optimal answer (concise)

Yes — implemented custom metrics (Prometheus), tracing (OpenTelemetry), logs (structured JSON), and memory/GC metrics to monitor performance and identify bottlenecks.

Subquestions & answers

  • Metrics: expose counters/gauges/histograms (request latency, GC pauses, DB time).
  • Tracing: instrument spans for critical flows to understand latency across services.
  • Logs: structured logs with request IDs for correlation.

Example

# prometheus client example (ruby)
require 'prometheus/client'
prom = Prometheus::Client.registry
http_requests = Prometheus::Client::Counter.new(:http_requests_total, docstring: '...')
prom.register(http_requests)
http_requests.increment(labels: {route: '/users'})

Best practices / Pitfalls

  • Capture cardinality carefully in labels to avoid high-memory usage.
  • Correlate logs and traces via a request ID.
