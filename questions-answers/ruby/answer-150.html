Question 150: How do you benchmark and profile concurrency and parallelism issues in Ruby (CPU, lock contention, GC pauses)? Tools and approaches.

Concept

Benchmarking concurrency requires measuring throughput, latency, and contention under realistic loads. Tools include Benchmark.ips, stackprof, perf, flamegraphs, and GC metrics.

Optimal answer (concise)

Use microbenchmarks for code hotspots, but simulate realistic loads with tools (wrk, ab, JMeter). Profile Ruby with stackprof/ruby-prof, GC::Profiler for GC pauses, and system tools (perf, dtrace). On JRuby use async-profiler.

Subquestions & answers

  • Lock contention: measure with logging, queue stats, or Mutex profiling patches.
  • GC impact: measure GC time/alloc stats via GC::Profiler or runtime metrics.

Best practices

  • Benchmark in staging-like environments. Collect both throughput and latency distributions (p95/p99).
