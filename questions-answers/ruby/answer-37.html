Question 37: Logs tell you the flow, but do you also capture metrics like memory/time at each stage?

Concept

Logs provide events; metrics provide quantifiable signals. Capturing memory and timing metrics at key stages complements logs and helps spot regressions.

Optimal answer (concise)

Yes — capture timing metrics (histograms) for request phases and memory metrics (GC stats, RSS) at intervals and on key events to correlate with logs and traces.

Subquestions & answers

  • Memory metrics: collect GC.stat, ObjectSpace statistics, and process RSS.
  • Timing: instrument entry/exit times for DB, view rendering, external calls.
  • Correlation: include request IDs to link logs, traces, and metrics.

Example

start = Process.clock_gettime(Process::CLOCK_MONOTONIC)
# do work
duration = Process.clock_gettime(Process::CLOCK_MONOTONIC) - start
histogram.observe(duration, labels: {route: '/users'})

# memory
mem_kb = `ps -o rss= -p #{Process.pid}`.to_i
gcs = GC.stat
gauge.set(mem_kb)

Best practices / Pitfalls

  • Be cautious of high-resolution metrics that can increase storage/cost; aggregate appropriately.
  • Use low-overhead sampling for expensive stats.
