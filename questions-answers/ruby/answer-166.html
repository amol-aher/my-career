Question 166: When would you prefer actor-model libraries (e.g., concurrent-ruby Actors) over shared-memory threads?

Concept

Actor-model enforces message-passing and encapsulates state, avoiding many shared-memory concurrency pitfalls.

Optimal answer (concise)

Use actors when you need strong encapsulation, easier reasoning about state, fault isolation, or when modeling entities as independent actors (e.g., game servers, IoT devices). Shared-memory is fine for simple cases where locks are well-understood.

Subquestions & answers

  • Pros: safer concurrency model, easier to reason about, good for distributed systems.
  • Cons: messaging overhead, complexity for transactions across actors.

Example

require 'concurrent-ruby'
actor = Concurrent::Actor.spawn(:counter) do
  state = 0
  loop do
    react do |msg|
      case msg
      when :inc
        state += 1
      when :get
        sender << state
      end
    end
  end
end

Best practices

  • Design actor interfaces carefully; use supervision and monitoring for production systems.
