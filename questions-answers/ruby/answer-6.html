Question 6: What’s the difference between includes, preload, and eager_load in Rails?

Concept

These ActiveRecord methods control how associations are loaded to avoid N+1 queries. They differ in how ActiveRecord fetches associated records: separate queries vs joins.

Optimal answer (concise)

preload always issues separate queries for associations. eager_load forces a LEFT OUTER JOIN (single query). includes is smart: it chooses between separate queries (preload) or JOIN (eager_load) depending on how you use the result (e.g., filters/ordering on associated columns).

Subquestions & answers

  • When to prefer preload? — when join would cause large row duplication or complex SQL.
  • When to use eager_load? — when you must filter/order by associated table columns in SQL.
  • How includes decides? — AR inspects query usage; presence of conditions/order that reference the association leads to join behavior.

Examples

# separate queries
posts = Post.preload(:comments).limit(20)

# force join + load
posts = Post.eager_load(:comments).where('comments.visible = ?', true)

# default: intelligent includes
posts = Post.includes(:comments).where(published: true)

Best practices / Pitfalls

  • Check generated SQL to avoid accidental heavy joins.
  • Use .distinct when joins duplicate parent rows.
  • Benchmark queries—join can be faster sometimes but may increase data transfer.
