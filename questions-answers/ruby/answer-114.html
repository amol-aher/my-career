Question 114: Explain how Ruby MRI’s Global VM Lock (GVL): history, purpose, implications, and current behavior.

Concept

The GVL (also called GIL) is a global lock in MRI to simplify internal C API and extension safety by ensuring only one thread executes Ruby VM bytecode at a time.

Optimal answer (concise)

GVL was introduced to protect VM internals and simplify extension development. It limits concurrency for Ruby-level code but MRI still allows parallelism for IO and when C extensions release the GVL. Ongoing efforts reduce contention for better concurrency (e.g., more granular locking).

Subquestions & answers

  • Why keep GVL? — compatibility and C-extension ecosystem. Removing it requires reengineering many assumptions.
  • Current behavior: VM allows native threads but serializes Ruby bytecode execution; IO and GVL-releasing extensions run concurrently.

Best practices

  • For CPU-bound tasks on MRI, use processes or alternative runtimes; leverage C-extensions or native libraries that release the GVL if needed.
