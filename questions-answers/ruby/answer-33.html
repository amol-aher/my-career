Question 33: Have you come across a use case where you had to override that limitation and extract all the CPU power?

Concept

To extract full CPU power on MRI, you generally use multiple processes (fork) or run compute-heavy parts in native extensions that release the GVL. Alternatively, use JRuby/TruffleRuby which allow true parallel threads.

Optimal answer (concise)

Yes — for CPU-bound workloads, I used process pools (forked workers) and native extensions (C) that release the GVL, and in some cases moved services to JRuby for parallel execution.

Subquestions & answers

  • Native C extensions: Implement heavy algorithms in C and release the GVL during computation.
  • Process pools: Use Process.fork, worker supervisors, or job systems (Sidekiq with multiple processes) to parallelize across cores.
  • Offload: Consider moving heavy tasks to a service written in a language with native parallelism (Go, Java).

Example

# using Process.fork to parallelize CPU work
jobs = (1..8).to_a
workers = 4.times.map do
  fork do
    jobs.each_slice(2) do |slice|
      slice.each { |j| heavy_compute(j) }
    end
    exit 0
  end
end
Process.waitall

Best practices / Pitfalls

  • Forking has overhead — balance number of processes vs available memory.
  • Beware shared resources (DB connections) which may need reconnection after fork.
