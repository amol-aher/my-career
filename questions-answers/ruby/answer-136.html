Question 136: How do you detect and debug a race condition or data race in a Ruby program? Tools and strategies.

Concept

Detecting race conditions involves reproducing the concurrency scenario, adding logging, using thread sanitizers (where available), and stress testing under high concurrency.

Optimal answer (concise)

Use stress tests, race detectors (limited in Ruby), thread-safe logging, and deterministic concurrency testing techniques. Add assertions, increase concurrency, and use tools like ThreadSanitizer for native parts or heavy logging plus heap snapshots.

Subquestions & answers

  • Reproducibility: race conditions may be timing-dependent — increase load, add sleeps, and use fuzzing to reproduce.
  • Tools: limited native Ruby race detectors; use sanitizer tools for C extensions, heavy instrumentation, and unit tests that control scheduling.

Example approach

# add per-operation logging and thread ids
mutex = Mutex.new
shared = 0
100.times.map do
  Thread.new do
    100.times do
      old = shared
      new = old + 1
      puts "\#{Thread.current.object_id} reads \#{old} -> writes \#{new}"
      shared = new
    end
  end
end.each(&:join)

Best practices / Pitfalls

  • Design for determinism in tests; consider using tools that allow controlling thread scheduling in tests (e.g., custom schedulers).
