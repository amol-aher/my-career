Question 112: What are common pitfalls when sharing mutable objects between threads?

Concept

Sharing mutable objects across threads can lead to race conditions, inconsistent state, and hard-to-reproduce bugs if accesses are not synchronized.

Optimal answer (concise)

Avoid unsynchronized mutations of shared objects. Use Mutex, Monitor, atomic primitives, or immutable data structures to prevent races.

Subquestions & answers

  • Visibility: ensure writes are visible to other threads; use synchronization to establish happens-before relationships.
  • Copy-on-write: sometimes copy data or use immutable snapshots to avoid locks.

Example

# unsafe
shared = []
threads = 5.times.map { Thread.new { 100.times { shared << 1 } } }
threads.each(&:join) # may corrupt array or lose entries

# safe
mutex = Mutex.new
threads = 5.times.map { Thread.new { 100.times { mutex.synchronize { shared << 1 } } } }
threads.each(&:join)

Best practices

  • Prefer thread-local or immutable data when possible; minimize locked regions and prefer well-tested concurrency primitives.
