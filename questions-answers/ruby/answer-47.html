Question 47: What’s the difference between ==, eql?, and equal?

Concept

Ruby offers multiple equality operators serving different semantics: == for value equality (overridable), eql? for hash key equality (strict), and equal? for object identity (same object).

Optimal answer (concise)

== checks value equality (often overridden), eql? is used by Hash for key comparison (strict, e.g., 1.eql?(1.0) is false), and equal? checks object identity (same object id).

Subquestions & answers

  • Examples: a == b compares values; a.eql?(b) is stricter; a.equal?(b) checks object_id equality.
  • Hash keys: Hash uses eql? and hash for key comparison.

Example

a = "hi"
b = "hi"
a == b        # => true (value)
a.equal?(b)   # => false (different objects)
1 == 1.0      # => true
1.eql?(1.0)   # => false

Best practices / Pitfalls

  • Implement eql? and hash together when defining custom hash-keyable objects.
