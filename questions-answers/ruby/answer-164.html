Question 164: Tell me about a concurrency bug you found in the wild. How did you find and fix it?

Concept

Real-world concurrency bugs often arise from shared mutable caches, thread-local leakage, or improper synchronization. Finding them involves reproducing under load and inspecting traces/heap.

Optimal answer (concise)

Example: a web app using thread pool stored user-specific context in Thread.current without clearing it. Under high load, worker reuse leaked context between requests. Found via memory/behavioral traces and failing tests. Fix: clear thread-local context in an ensure block or use request-scoped objects passed explicitly.

Steps taken

  1. Reproduced bug with stress tests mimicking production load.
  2. Instrumented threads to log Thread.current contents and request IDs.
  3. Identified leakage due to missing cleanup in failure paths.
  4. Applied fix: ensure cleanup in ensure block, and added tests and monitoring to prevent regressions.

Best practices

  • Prefer explicit context passing over implicit thread-locals for clarity. Add instrumentation and tests for concurrency-sensitive areas.
