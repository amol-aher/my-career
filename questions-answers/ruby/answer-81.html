Question 81: What is const_missing and when might you use it?

Concept

const_missing is a hook invoked by Ruby when an uninitialized constant is referenced. It allows lazily autoloading constants, implementing custom resolution, or providing helpful errors.

Optimal answer (concise)

Override const_missing in a module/class to implement lazy loading (e.g., autoload paths) or to dynamically define constants when first referenced. Use carefully to avoid surprising behavior.

Subquestions & answers

  • Autoload vs const_missing? — autoload registers a file to load on first reference; const_missing gives full programmatic control.
  • Risks? — can mask typos, complicate constant lookup, and affect performance if abused.

Example

module ServiceLoader
  def const_missing(name)
    require "./services/\#{name.to_s.downcase}"
    const_get(name)
  rescue LoadError
    super
  end
end

Object.extend(ServiceLoader)
# referencing MyService will trigger require "./services/myservice.rb"

Best practices / Pitfalls

  • Avoid silent failures: re-raise or call super when unable to resolve.
  • Prefer explicit requires or autoload for clarity when possible.
