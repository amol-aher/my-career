Question 65: How does Ruby handle method lookup (method resolution order)?

Concept

Ruby looks up methods starting from the object's singleton class, then the class, then included modules (in reverse include order), then superclasses and their included modules, up the chain to BasicObject.

Optimal answer (concise)

Lookup order: singleton class → class → included modules (last included searched first) → superclass → ... → BasicObject. Prepend changes this by inserting modules earlier.

Subquestions & answers

  • Method_missing: called when lookup fails; can be used to implement dynamic behavior.
  • ancestors: use Class.ancestors to inspect lookup chain.

Example

module A; end
class C; include A; end
C.ancestors # => [C, A, Object, Kernel, BasicObject]

Best practices / Pitfalls

  • Inspect ancestors when debugging method resolution. Avoid complex include/prepend patterns that complicate reasoning.
