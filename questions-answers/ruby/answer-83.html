Question 83: How does Ruby handle scoping (lexical scope, closures, binding)?

Concept

Ruby uses lexical scope for local variables and closures: blocks, procs, and lambdas capture the surrounding local variable bindings. binding captures the execution context which can be eval'd later.

Optimal answer (concise)

Blocks/procs/lambdas close over local variables lexically. Use binding to capture the execution context, and eval with a binding to execute code in that scope.

Subquestions & answers

  • Closures: captured variables remain accessible even after outer method returns if referenced by the closure.
  • Binding use: rarely used in production but useful for REPLs, templates, or DSLs.

Example

def counter
  n = 0
  -> { n += 1 }
end
c = counter
c.call # => 1
c.call # => 2

b = binding
eval('x = 10', b) # defines x in current binding

Best practices / Pitfalls

  • Avoid heavy use of eval for maintainability and security; prefer explicit APIs.
