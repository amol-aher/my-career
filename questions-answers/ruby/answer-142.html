Question 142: How does Ruby’s garbage collector interact with threads and the GVL? Impacts on latency and throughput?

Concept

In MRI, GC runs with the GVL held, meaning Ruby threads are paused during GC. This introduces stop-the-world pauses that impact latency. Throughput is reduced if GC runs frequently.

Optimal answer (concise)

GC stops all Ruby threads during marking/sweeping (stop-the-world). Incremental and compaction strategies reduce pause times. Throughput suffers with high allocation rates; latency-sensitive apps must tune GC or use alternative runtimes.

Subquestions & answers

  • JRuby: GC runs concurrently (JVM GCs like G1, ZGC), reducing pause times.
  • Tuning: use GC tuning parameters (RUBY_GC_HEAP_GROWTH_FACTOR, RUBY_GC_MALLOC_LIMIT, etc.).

Best practices

  • Monitor GC stats with GC::Profiler or New Relic.
  • Optimize object allocation and use frozen strings to reduce GC load.
