Question 123: How do fibers and Fiber.schedule (or Fiber + async libraries) enable async IO patterns?

Concept

Ruby 3 introduced a fiber scheduler API allowing IO libraries to integrate with fiber-based concurrency. Fiber.schedule and async libraries let you write synchronous-looking code that yields on IO, enabling efficient async IO.

Optimal answer (concise)

Async libraries hook into the fiber scheduler so blocking IO calls yield the current fiber and allow others to run. Use Fiber.schedule/Async frameworks to write sequential-style code with non-blocking IO.

Example

# conceptual; libraries provide real hooks
require 'async'
Async do
  task = Async do
    HTTP.get('https://example.com') # non-blocking within Async
  end
  task.wait
end

Best practices

  • Use libraries that support the fiber scheduler; avoid blocking calls that don't yield.
