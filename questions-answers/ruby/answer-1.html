Question 1: What’s the use of ensure in exception handling? When does it execute?

Concept

ensure is part of Ruby's exception handling construct (begin/rescue/ensure). Conceptually, it is a finally-block: code placed inside ensure is guaranteed to run after the begin body and any rescue handlers, regardless of whether an exception occurred or not.

Optimal answer (concise)

ensure is used for cleanup that must always run (closing files, releasing locks). It executes after begin and rescue blocks complete — even if the method returns or an exception is re-raised — but it won't run if the process is killed by the OS (SIGKILL).

Subquestions & answers

  • Does ensure run on return? — Yes. If you return inside begin or rescue, ensure runs before the method actually returns.
  • Can ensure suppress the original exception? — Not by itself. But if ensure raises a new exception, it will replace the original one.
  • When won't ensure run? — When the process is abruptly terminated (SIGKILL), or the machine crashes; normal exit will still run ensure.

Example

def with_file(path)
  f = File.open(path, "r")
  begin
    yield f
  rescue => e
    warn "error: \#{e.class}: \#{e.message}"
    raise
  ensure
    f.close if f && !f.closed?
  end
end

Best practices / Pitfalls

  • Keep ensure short and avoid raising exceptions inside it.
  • Don't rely on ensure for critical external side-effects that must survive process kills — use transactional/atomic persistence where required.
