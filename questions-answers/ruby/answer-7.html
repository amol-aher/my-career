Question 7: Have you generally used includes, preload, joins?

Concept

These tools are the basic instruments for controlling association loading strategies in ActiveRecord. Using them well prevents performance issues and N+1 queries.

Optimal answer (concise)

Yes — use includes as the default for avoiding N+1; switch to preload to force separate queries, and use joins/ eager_load when you need to filter or order by joined tables.

Subquestions & answers

  • joins vs includes: joins does an INNER JOIN and doesn't load associated records unless you select them; use when filtering.
  • left_joins: safe for optional associations (LEFT OUTER JOIN).
  • When to avoid includes: when you only need to filter, not fetch associated objects.

Example patterns

# filter users with published posts (don't need posts objects)
User.joins(:posts).where(posts: {published: true}).distinct

# need loaded posts to display
users = User.includes(:posts).where(active: true)

Best practices / Pitfalls

  • Always inspect SQL for unexpected joins.
  • Use indexes on foreign keys to make preloaded queries efficient.
